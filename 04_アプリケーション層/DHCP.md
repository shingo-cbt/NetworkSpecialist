# DHCP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. DHCPの基本（○）

- **DHCP（Dynamic Host Configuration Protocol）**：端末に**IP（Internet Protocol）アドレスなどのネットワーク設定を自動で配る**プロトコル
- ポート：**サーバはUDP（User Datagram Protocol） 67、クライアントはUDP 68**
- 配る主な情報（オプション）
  - IPアドレス、サブネットマスク
  - **デフォルトゲートウェイ**
  - **DNS（Domain Name System）サーバのアドレス**、ドメイン名
  - リース期間、NTP（Network Time Protocol）サーバ、プロキシ自動設定（WPAD（Web Proxy Auto-Discovery））など
- **リース**：アドレスは期限付きで貸し出す。期限が来る前に延長する

## 2. アドレスを受け取る流れ（◎）

| 順番 | メッセージ | 向き | 宛先 |
|---|---|---|---|
| 1 | **DHCPDISCOVER** | 端末 → | **ブロードキャスト**（まだアドレスもサーバも知らない） |
| 2 | **DHCPOFFER** | → 端末 | 「このアドレスはどうか」 |
| 3 | **DHCPREQUEST** | 端末 → | **ブロードキャスト**（複数のサーバにOfferをもらった場合、どれを選んだか全員に知らせる） |
| 4 | **DHCPACK** | → 端末 | 「確定」 |

- 頭文字で **DORA**（Discover、Offer、Request、Ack）
- **リースの延長**：期間の**50**%で、借りたサーバに**ユニキャスト**でREQUEST → 応答がなければ**87.5**%でブロードキャストして他のサーバにも頼む（△）
- 端末は受け取ったアドレスが使われていないか、ARP（Address Resolution Protocol）で確認する → [[Gratuitous ARP]]
- 午前の定番：「DHCPDISCOVERの宛先」→ ブロードキャスト

## 3. DHCPリレー（◎）

- DISCOVERは**ブロードキャスト** → **ルータを越えられない** → DHCPサーバが別のネットワークにあると届かない
- **DHCPリレーエージェント**：ルータ（L3スイッチ）が端末のブロードキャストを受け、**DHCPサーバへユニキャストで転送**する
  - 転送するときに、**受け取ったインタフェースのIPアドレス**（giaddr）を入れる → DHCPサーバは**どのネットワーク（VLAN（Virtual LAN））の端末か**を判断し、そのネットワーク用のアドレスの範囲（スコープ）から配る
- ◎の定番：**VLANを追加したのに、そのVLANの端末がアドレスを取れない** → **L3スイッチのそのVLANインタフェースにDHCPリレーを設定し忘れた**、またはDHCPサーバに**スコープを追加し忘れた**
- 記述の型：「DHCPDISCOVERはブロードキャストのためルータを越えられないので、L3スイッチでDHCPリレーを設定し、DHCPサーバに転送させる」
- 端末にアドレスが付かないと **169.254.x.x** が付く → [[IPアドレスとサブネット]]

## 4. 冗長化（○）

| 方式 | 内容 |
|---|---|
| **スコープの分割** | 同じネットワーク用のアドレスを2台のサーバで分け合う（例：8割と2割）。重ならないので矛盾しない |
| **フェイルオーバ機能** | 2台がリースの情報を同期し、片方が止まってももう片方が同じ範囲を配る |

- DHCPリレーには**2台のDHCPサーバの両方を転送先として**設定する
- 記述の型：「2台のDHCPサーバで配布するアドレスの範囲が重ならないようにスコープを分割し、一方が停止しても他方から割り当てられるようにするため」

## 5. 午後で問われるテーマと記述の型

### ◎ 固定のアドレスが必要な機器

- サーバ、プリンタ、ネットワーク機器は、アドレスが変わると困る → **手動で固定**するか、**DHCPでMAC（Media Access Control）アドレスに対して決まったアドレスを予約**する
- 手動で固定する範囲と、DHCPで配る範囲を**重ねない**（重なると重複が起きる）

### ◎ 不正なDHCPサーバとDHCPスヌーピング

- **攻撃者の観点・事故**
  - 攻撃者や、利用者が持ち込んだ家庭用ルータが**DHCPサーバとして応答**する → 端末に**偽のデフォルトゲートウェイ・DNSサーバ**が配られ、通信を盗聴・誘導される、または通信できなくなる
  - 大量のDISCOVERでアドレスを**使い果たさせる**（DHCPスタベーション）
- **防御側の対策：DHCPスヌーピング**
  - L2スイッチで、DHCPサーバ（またはルータ）につながるポートを **信頼するポート（trusted）** に設定し、**それ以外のポートから来たOFFER・ACK（Acknowledgement）を破棄**する
  - DISCOVERの量をポートごとに制限する
  - スヌーピングで作った**バインディング情報**（IPアドレス・MACアドレス・ポートの対応）は、**DAI**（Dynamic ARP Inspection）やIPソースガードにも使う → [[Gratuitous ARP]]
- 記述の型：「L2スイッチのDHCPスヌーピングで、信頼するポート以外から受信したDHCPOFFERを破棄し、不正なDHCPサーバからの割当てを防ぐ」

### ○ リース期間の設計

- 短すぎる：更新の通信が増え、DHCPサーバが止まるとすぐに影響が出る
- 長すぎる：使われなくなったアドレスが戻らず、**アドレスが不足**する（来訪者の多い無線LAN（Local Area Network）など）
- 問われ方：「ゲスト用無線LANのリース期間を短くする理由」

### ○ IPv6との違い

- IPv6ではSLAAC（Stateless Address Autoconfiguration）でアドレスを作り、DHCPv6は**DNSサーバの情報だけ**配る方式もある
- → [[IPv6アドレス・NDP]]、[[IPv6移行技術]]

## 6. 覚え方

- **流れは「DORA（ドーラ）」**：Discover → Offer → Request → Ack。DiscoverとRequestはブロードキャスト
- **ポートは「サーバ67、クライアント68」**
- **ブロードキャストは「ルータの壁を越えない」→ リレーで手渡し**。リレーは「どの窓口（giaddr）から来たか」を書き添える
- **DHCPスヌーピングは「正規の窓口（trusted）以外の返事は捨てる」**
- **169.254が付いたら「DHCPが来ていない」**
- **延長は「半分で本人に、87.5%で誰にでも」**

## 7. 勉強の優先順位

1. DHCPリレーが必要な理由と、設定し忘れたときの症状を30〜40字で書けるようにする
2. DORAの流れと、ブロードキャストになるメッセージ
3. DHCPスヌーピングの仕組み（信頼するポート、バインディング情報）
4. 冗長化（スコープの分割、フェイルオーバ）
5. 固定アドレスの機器（予約）、リース期間の設計
6. リース延長のタイミング（50%、87.5%）は午前で確認する程度でよい

> [!tip] 得点につながる覚え方
> DHCPは**VLANの追加・ネットワークの更改の問題で**「設定漏れ」として出やすい。構成図でDHCPサーバと端末が別のネットワークにあれば、**間のL3スイッチにDHCPリレーがあるか**、**DHCPサーバにそのネットワークのスコープがあるか**を確認する。
