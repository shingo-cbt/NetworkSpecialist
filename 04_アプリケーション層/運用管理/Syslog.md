# Syslog まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. Syslogの基本（○）

- **Syslog**：ネットワーク機器やサーバの**ログ（イベントの記録）を、ログサーバに送って集める**仕組み
- ポート：**UDP（User Datagram Protocol） 514**（TCP（Transmission Control Protocol）や、TLS（Transport Layer Security）で暗号化するTCP 6514もある）
- 機器 → ログサーバの**一方向**に送る（ログサーバは応答しない）
- 各メッセージには**ファシリティ**（どの機能のログか）と**重要度**（シビリティ）が付く

### 重要度（○）

| 値 | 名前 | 意味 |
|---|---|---|
| 0 | Emergency | システムが使えない |
| 1 | Alert | すぐに対応が必要 |
| 2 | Critical | 致命的 |
| 3 | Error | エラー |
| 4 | Warning | 警告 |
| 5 | Notice | 通常だが重要 |
| 6 | Informational | 情報 |
| 7 | Debug | デバッグ |

- **値が小さいほど重要**。「重要度4以上（0〜4）を送る」のように**しきい値を決めて送る**
- 午前の定番：「最も重要度が高いのは」→ Emergency（0）

## 2. 午後で問われるテーマと記述の型

### ◎ ログを集める理由

- 機器ごとに見に行かなくても、**1か所でまとめて調べられる**
- 機器の中のログは**容量が小さく古いものから消える**、機器が故障・再起動すると消えることがある
- 攻撃者が機器に侵入して**ログを消しても、ログサーバに残る**
- 記述の型：「機器の再起動や攻撃者による削除でログが失われても、ログサーバに保存されたログで調査できるようにするため」

### ◎ 時刻の同期が必要

- 複数の機器のログを**時系列で突き合わせる**には、全機器の**時刻が揃っている**必要がある → **NTP**（Network Time Protocol）で同期する
- 記述の型：「各機器の時刻がずれていると、複数機器のログを時系列で照合できず、障害や不正アクセスの調査ができないから」
- → [[NTP]]

### ○ UDPであることの問題

- UDPなので**ログが失われても分からない**（ネットワークが混雑したとき、ログサーバが止まっているとき）
- **改ざん・盗聴**される可能性がある
- 対策：**TCPやTLSで送る**、**ログサーバを冗長化**する（2台に送る）
- 記述の型：「UDPで送信するため、ネットワークの輻輳時などにログが欠落しても検知できないから」

### ○ FWのルールとログの活用

- 機器 → ログサーバ：UDP 514を許可する → [[FW]]
- 集めたログを**SIEM**（Security Information and Event Management）で分析し、複数の機器のログを関連付けて攻撃を検知する（△〜○）

## 3. 覚え方

- **Syslogは「機器の日記をまとめて本部に送る」**：UDP 514、送りっぱなし
- **重要度は「0が一番やばい、7はデバッグ」**
- **ログを集めるなら時計を合わせる（NTP）**
- **UDPなので「なくなっても気づかない」** → TCP・TLS、ログサーバの冗長化

## 4. 勉強の優先順位

1. ログサーバに集める理由を30〜40字で書けるようにする
2. NTPで時刻を同期する必要性
3. UDPであることの問題と対策
4. 重要度の順番（午前）、ポート番号

> [!tip] 得点につながる覚え方
> Syslogは「**集める理由」と「時刻同期（NTP）**」のセットで問われる。障害・セキュリティ事故の調査の設問では、「ログが残っているか」「時刻が揃っているか」の2点を確認する。
