# SNMP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

監視の設計（何をどう監視するか）は [[ネットワーク監視]] を参照。令和3年春 午後Ⅱでも、SNMPと監視がテーマになっている。

## 1. SNMPの基本（◎）

- **SNMP（Simple Network Management Protocol）**：ネットワーク機器やサーバの**状態を収集・監視・設定**するプロトコル
- 登場人物
  - **SNMPマネージャ**：監視サーバ。情報を集める
  - **SNMPエージェント**：監視される機器（ルータ、スイッチ、サーバ）の中で動くソフト
- **MIB（Management Information Base）**：エージェントが持つ管理情報の集まり（インタフェースの送受信量、CPU（Central Processing Unit）使用率、状態など）
  - 各項目は **OID（Object Identifier）**（1.3.6.1.2.1… のような番号）で識別する

## 2. 2つの通信方法（◎）

| 方式 | 向き | ポート | 内容 |
|---|---|---|---|
| **ポーリング**（GetRequest など） | **マネージャ → エージェント** | エージェントの **UDP（User Datagram Protocol） 161** | マネージャが**定期的に問い合わせて**値を取る |
| **トラップ** | **エージェント → マネージャ** | マネージャの **UDP 162** | 機器が**異常を自分から通知**する（リンクダウン、再起動など） |

| | ポーリング | トラップ |
|---|---|---|
| 検知の速さ | ポーリングの**間隔の分だけ遅れる** | **すぐに通知**される |
| 確実さ | 応答がなければ異常と分かる（機器の停止も検知できる） | **UDPで確認応答がない** → 失われても分からない。機器が完全に止まるとトラップも送れない |
| 負荷 | 監視対象・項目が多いと、マネージャと回線の負荷が増える | 普段は通信しない |

- **インフォーム**（SNMPv2c以降）：トラップに**確認応答を付けた**もの。届かなければ再送する（○）
- **SetRequest**：マネージャからエージェントの設定を変更する（△）
- 両方を組み合わせるのが普通：**トラップで即時に知り、ポーリングで定期的に確かめる**
- 記述の型（ポーリングも必要な理由）：「トラップはUDPで送られ到達が保証されず、機器が停止した場合はトラップ自体が送信されないため」

## 3. バージョンとセキュリティ（◎）

| バージョン | 認証 | 暗号化 |
|---|---|---|
| SNMPv1／**v2c** | **コミュニティ名**（パスワードのような文字列）。**平文**で流れる | なし |
| **SNMPv3** | **ユーザごとの認証**（ハッシュで改ざん・なりすましを検知） | **あり** |

- コミュニティ名は読み取り用（read-only）と書き込み用（read-write）を分けられる。**初期値（public など）のまま**だと誰でも情報を取れる
- 対策：**SNMPv3を使う**、エージェントで**問い合わせを受け付けるマネージャのアドレスを限定**する、書き込みを許可しない
- 記述の型：「SNMPv2cではコミュニティ名が平文で送信されるため、盗聴されると機器の情報を取得されるおそれがあるから」

## 4. 午後で問われるテーマと記述の型

### ◎ トラフィック量の計算

- インタフェースの**受信・送信オクテット数のカウンタ（ifInOctets／ifOutOctets）**を一定間隔で取り、**差分 ÷ 間隔**で通信量（bps）を求める
  - 例：5分（300秒）で 3,750,000,000 オクテット増えた → 3,750,000,000 × 8 ÷ 300 ＝ **100Mbps**
- **32ビットのカウンタは約43億で一周する** → 高速な回線では、ポーリングの間隔の間に**一周して値が戻り**、正しく計算できない
  - 対策：**64ビットのカウンタ（ifHCInOctets など）**を使う、間隔を短くする
- 記述の型：「32ビットのカウンタがポーリング間隔内に一周してしまい、差分から正しい通信量を算出できないから」

### ◎ FWのルール

- マネージャ → エージェント：UDP 161
- エージェント → マネージャ：UDP 162（トラップ）
- 監視サーバがDMZ（DeMilitarized Zone）や別拠点の機器を監視するときに、この2つを許可する
- → [[FW]]

### ○ 冗長構成での監視

- VRRP（Virtual Router Redundancy Protocol）の**仮想IP（Internet Protocol）アドレスだけ**を監視すると、どちらの機器が止まったか分からない → **実機のアドレス**も監視する
- バックアップ機は普段通信しないので、**故障に気づきにくい** → 定期的にポーリングする

### ○ 監視サーバ自体

- 監視サーバが止まると監視できない → 冗長化する、監視サーバを別の仕組みで監視する
- 監視の通信を業務の通信と分ける（管理用VLAN（Virtual LAN）、アウトオブバンド管理）→ [[ネットワーク監視]]

## 5. 覚え方

- **SNMPは「マネージャ（監視サーバ）がエージェント（機器）に聞く・機器が知らせる」**
- **ポーリングは「161番に聞きに行く」、トラップは「162番に知らせが来る」**（161＋1）
- **ポーリングは「遅いが確実」、トラップは「速いが届かないこともある」**
- **v2cは「合言葉（コミュニティ名）が丸見え」、v3は「本人確認と暗号化」**
- **通信量は「カウンタの差 × 8 ÷ 秒」**、32ビットは高速回線で一周する

## 6. 勉強の優先順位

1. ポーリングとトラップの違い、ポート番号、両方を組み合わせる理由を30〜40字で書けるようにする
2. カウンタからの通信量の計算と、32ビットのカウンタの一周
3. SNMPv2cとv3の違い、コミュニティ名の問題
4. FW（Firewall）で許可する通信
5. インフォーム、SetRequest、OIDは名前を知っている程度でよい

> [!tip] 得点につながる覚え方
> SNMPは**監視サーバと機器の間の矢印の向き**で整理する。マネージャ→エージェントが161（ポーリング）、エージェント→マネージャが162（トラップ）。午後では、この向きでFWのルールを書かせる問題と、通信量の計算が定番。
