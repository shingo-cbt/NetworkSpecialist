# VRRP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. VRRPの基本（◎）

- **VRRP（Virtual Router Redundancy Protocol）**：**デフォルトゲートウェイ（ルータ、L3スイッチ）を冗長化する**プロトコル
- 端末に設定できるデフォルトゲートウェイは通常1つ → そのルータが止まると、端末は外に出られない
- 複数のルータで1台の**仮想ルータ**を作り、端末には**仮想ルータのIP（Internet Protocol）アドレス**をデフォルトゲートウェイとして設定する

| 用語 | 内容 |
|---|---|
| **仮想ルータ** | 複数の実ルータをまとめた論理的なルータ。**VRID**（Virtual Router Identifier：1〜255）で識別 |
| **仮想IPアドレス** | 端末がデフォルトゲートウェイとして使うアドレス |
| **仮想MAC（Media Access Control）アドレス** | **00-00-5E-00-01-{VRID}**（IPv6は 00-00-5E-00-02-{VRID}） |
| **マスタ** | 仮想ルータとして実際にパケットを転送する1台 |
| **バックアップ** | 待機する残りのルータ |

- **仮想MACアドレスはマスタが替わっても同じ** → 端末のARP（Address Resolution Protocol）テーブルを更新する必要がない
- VRRPv3はIPv4とIPv6の両方に対応する

## 2. マスタの決め方と切替（◎）

- **優先度（プライオリティ：1〜254）が最も大きい**ルータがマスタになる
  - 同じなら、**IPアドレスが大きい**ルータ
  - 仮想IPアドレスを自分の実アドレスとして持つルータ（アドレスの所有者）は優先度**255**で、必ずマスタになる（△）
- マスタは **VRRPアドバタイズメント**を定期的に送る
  - 送信先：マルチキャスト **224.0.0.18**、**IPのプロトコル番号112**
  - 間隔：初期値 **1秒**
- バックアップは、アドバタイズメントが**一定時間（約3秒：間隔の3倍＋α）届かない**とマスタが故障したと判断し、自分がマスタになる
- 新しいマスタは、仮想MACアドレスを送信元にした **Gratuitous ARP（GARP）** を送る → **L2スイッチのMACアドレステーブルを更新**させ、仮想MACアドレス宛てのフレームを新しいマスタのポートに流す → [[Gratuitous ARP]]

### プリエンプト（○）

- 優先度の高いルータが**復旧したときに、マスタを取り戻す**機能（VRRPでは初期値で有効のことが多い）
- 問題：障害時と復旧時の**2回、切替**（通信の瞬断）が起きる。復旧直後はルーティングが整っておらず、通信できないこともある
- 対策：プリエンプトを無効にする、または取り戻すまでの**待ち時間**（遅延）を設定する
- 記述の型：「復旧したルータがマスタに戻る際にも切替が発生し、通信が瞬断するから」

## 3. トラッキング（◎）

- VRRPは、**ルータ自身や、端末側のインタフェースが止まった**ことしか検知できない
  - マスタの**上流（WAN（Wide Area Network）回線、インターネット側）だけが切れた**場合、マスタはアドバタイズメントを送り続ける → 切替が起きず、端末の通信は途絶える
- **トラッキング**：上流のインタフェースや経路を監視し、障害時に**自分の優先度を下げる** → バックアップの優先度が上回り、マスタが交代する
- 計算問題：「優先度をいくつ下げれば切り替わるか」→ 下げた後の値がバックアップの優先度を**下回る**ようにする（プリエンプトが有効であることも条件）
- 記述の型：「上流回線の障害を検知した場合に優先度を下げ、バックアップ側のルータにマスタを切り替えるため」

## 4. 午後で問われるテーマと記述の型

### ◎ VLANごとにマスタを分けた負荷分散

- 1つの仮想ルータだけだと、平常時はバックアップのルータ（L3スイッチ）が遊んでいる
- **VLAN（Virtual LAN）ごとに仮想ルータを作り、VLANごとにマスタを入れ替える**
  - VLAN10はL3SW（Layer 3 Switch）1がマスタ、VLAN20はL3SW2がマスタ → 平常時に両方を使う
- STP（Spanning Tree Protocol）のルートブリッジも**VRRPのマスタと同じ機器**に揃えると、L2の経路とL3の出口が一致して無駄な迂回がなくなる
- → [[VLAN]]、[[STP]]

### ◎ OSPF・FWとの組合せ（行きと帰りの経路を揃える）

- 端末から外への通信はVRRPのマスタを通る。外から戻る通信は**OSPF（Open Shortest Path First）のコスト**で決まる
- 行きと帰りで別のL3スイッチ・別のFW（Firewall）を通ると、**ステートフルインスペクションのFWで戻りのパケットが破棄**される（セッション情報がないため）
- 対策：VRRPのマスタ側を通るように**OSPFのコストを調整**する、トラッキングでVRRPとOSPFの切替を連動させる
- 令和7年春 午後Ⅰ 問1「企業ネットワークのルータ更改」でも、OSPFとVRRPの理解が問われている
- → [[OSPF]]

### ◎ 切替の仕組みとGARP

- 「新しいマスタがGARPを送る目的」→ **L2スイッチのMACアドレステーブルの更新**（端末のARPテーブルではない。仮想MACは変わらないため）
- 記述の型：「L2SW（Layer 2 Switch）のMACアドレステーブルを更新し、仮想MACアドレス宛てのフレームを新しいマスタに転送させるため」

### ○ 両方がマスタになる（スプリットブレイン）

- 2台の間のL2の経路が切れて**アドバタイズメントが届かない**と、両方が自分をマスタだと判断する
- 同じ仮想IP・仮想MACを2台が使い、通信が不安定になる
- 対策：2台の間の経路を冗長化する（リンクアグリゲーションなど）、アドバタイズメントが通るVLANを両方の間で確実につなぐ

### ○ 機器の更改・メンテナンス

- マスタを止める前に、**優先度を下げて先にバックアップへ切り替えて**から作業する → 計画的に切り替えられる
- 更改後の機器は優先度・VRID・仮想IPアドレス・アドバタイズメントの間隔を**既存の機器と揃える**

### △ 類似のプロトコル

- **HSRP（Hot Standby Router Protocol）**：Cisco社独自の同様のプロトコル。考え方は同じ

## 5. 覚え方

- **VRRPは「代表電話番号」**：端末は代表番号（仮想IP）にかけるだけ。誰が出るか（マスタ）は裏で決まる
- **仮想MACは「00-00-5E-00-01-VRID」**、マスタが替わっても同じ → 端末のARPはそのまま、**更新するのはスイッチのMAC表（GARPで）**
- **優先度は「大きい方が勝つ」、255はアドレスの持ち主**
- **アドバタイズは「1秒ごと、3秒途絶えたら交代」**、宛先224.0.0.18、プロトコル番号112
- **トラッキングは「上流が切れたら自分から降りる」**
- **プリエンプトは「元の主が帰ってきたら席を返す」** → 2回目の瞬断に注意
- **負荷分散は「VLANごとに主役を入れ替える」**

### プライオリティの向き：STP・VRRP・OSPFの比較

- **VRRPの優先度は「点数（やる気）」**：マスタをどれだけやりたいかの点数なので、大きい方が勝つ
  - **0の意味**で確認できる：優先度0は「マスタをやめる」という通知。「0＝やる気なし」が成り立つのは、大きいほど強いから
  - **トラッキング**も「点数を下げて負ける」と考えると自然
  - 同点なら、IPアドレスが大きい方。これも同じ向き
- [[OSPF]]のDR（Designated Router）プライオリティも同じ向き（0はDRにならない）。逆に、[[STP]]のプライオリティはブリッジID（番号）の一部なので、小さいほど強い

| 種類 | 例 | 向き | 同点のとき |
|---|---|---|---|
| **番号・距離** | STPのブリッジID、STP・OSPFのコスト | **小さいほど優先** | MACアドレスが小さい方（STP） |
| **点数（やる気）** | VRRPの優先度、OSPFのDRプライオリティ | **大きいほど優先**（0は不参加） | IPアドレスが大きい方（VRRP）、ルータIDが大きい方（OSPF） |

- 覚え方：**「STPは背番号、VRRPとOSPFのDRは点数、コストは距離」**
- 設計者がこの向きを選んだ経緯の記録はない。上は仕組みから説明できる理由で、覚えるための整理

## 6. 勉強の優先順位

1. マスタの決まり方と、切替の流れ（アドバタイズメント → 交代 → GARP）を説明できるようにする
2. トラッキングの目的と、優先度の計算
3. VLANごとのマスタの分散、STPのルートブリッジとの一致
4. OSPF・FWとの組合せで行きと帰りの経路を揃える理由を30〜40字で書けるようにする
5. プリエンプトによる2回の切替、メンテナンス時の手順
6. スプリットブレイン、HSRPは概要を知っている程度でよい

> [!tip] 得点につながる覚え方
> VRRPは**冗長化の問題でほぼ必ず出る**。構成図を見たら、VLANごとに**どちらがマスタか**を書き込み、端末からの行きの経路（VRRP）と戻りの経路（OSPF）が同じ機器を通るかを確認する。障害の設問では「どの障害なら切り替わり、どの障害ならトラッキングが必要か」を区別する。
