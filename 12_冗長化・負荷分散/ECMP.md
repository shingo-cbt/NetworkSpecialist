# ECMP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. ECMPの基本（○）

- **ECMP（Equal Cost Multi-Path：等コストマルチパス）**：同じ宛先に対して**メトリック（コスト）が等しい経路が複数ある**とき、それらを**同時に使って通信を分散**する仕組み
- ルーティングテーブルに、同じ宛先・複数のネクストホップが登録される
- 対応する主な方法
  - **OSPF（Open Shortest Path First）**：コストが同じ経路を自動でECMPにする
  - **BGP（Border Gateway Protocol）**：マルチパスの設定で複数の経路を使う
  - スタティック経路：同じ宛先に複数のネクストホップを設定する
- 利点
  - **複数の回線の帯域をまとめて使える**（アクティブ／アクティブ）
  - 1本が切れても、残りの経路で通信を続けられる（経路が消えるだけなので**切替が速い**）
- 何本まで使うかは機器の設定で決める（△）

## 2. 分散のしかた（◎）

| 方式 | 内容 | 欠点 |
|---|---|---|
| **パケット単位** | パケットごとに経路を順番に替える | 同じ通信のパケットが別の経路を通り、**到着順が入れ替わる** → TCP（Transmission Control Protocol）の再送や性能低下 |
| **フロー単位**（主流） | 送信元・宛先のIP（Internet Protocol）アドレス、ポート番号などから**ハッシュ値**を計算し、**同じ通信（フロー）は同じ経路**に流す | **偏り**が出ることがある（大きな通信が1つの経路に集中する、通信の種類が少ない） |

- フロー単位では、**1つの通信が使える帯域は1本の経路の分まで**（2本束ねても1つのファイル転送は速くならない）
- 記述の型（フロー単位にする理由）：「同じ通信のパケットが異なる経路を通ると到着順序が入れ替わり、TCPの再送が発生するため」
- 記述の型（偏る理由）：「ハッシュ値で経路を決めるため、通信量の大きいフローが同じ経路に割り当てられると負荷が偏るから」

## 3. リンクアグリゲーションとの違い（○）

| | ECMP | リンクアグリゲーション（LAG：Link Aggregation Group） |
|---|---|---|
| 層 | **L3**（ルーティング） | **L2**（複数の物理リンクを1本の論理リンクに束ねる） |
| 束ねる相手 | 別々のネクストホップ（**別のルータ・別の経路**でもよい） | **同じ2台の機器の間**の複数リンク（スタック機器なら2台にまたがれる） |
| 分散のしかた | フロー単位（ハッシュ） | フロー単位（ハッシュ） |

- どちらも「フロー単位で偏ることがある」「1つの通信は1本分まで」は同じ
- → [[リンクアグリゲーション]]

## 4. 午後で問われるテーマと記述の型

### ◎ FWを挟んだ非対称経路

- ECMPの経路上に**別々のFW**（Firewall）がある（FWが2台ある）と、**行きと帰りで別のFWを通る**ことがある
- ステートフルインスペクションのFWは、行きのセッション情報を持たない側で**戻りのパケットを破棄**する
- 対策
  - FWを冗長構成にして**セッション情報を同期**する
  - 行きと帰りで**同じ経路になるようにする**（ECMPにしない、コストを調整してアクティブ／スタンバイにする、対称になるハッシュ）
  - FWをECMPの区間の外に置く
- 記述の型：「行きと帰りの通信が異なるFWを経由し、戻りの通信のセッション情報がないFWで破棄されるから」
- → [[VRRP]]、[[OSPF]]

### ◎ OSPFのコストとECMP

- コストが同じになるように設計すれば、2本の回線を両方使える（アクティブ／アクティブ）
- 片方を待機にしたいなら、**わざとコストを変える**（アクティブ／スタンバイ）
- 問われ方：「この宛先への通信がECMPになるのはどのルータか」「ECMPにするにはコストをいくつにするか」
- 1Gbpsと10Gbpsが初期設定だと同じコスト1になり、**意図せずECMPになる**（遅い回線にも半分流れる）→ 基準帯域を見直す

### ○ クラウド・拠点間の回線の二重化

- クラウドとの接続で**VPN（Virtual Private Network）トンネルを2本**張り、BGPで両方の経路を受けて**ECMP**で使う
- 2つの回線の速度が違うと、遅い回線が詰まる → 帯域が同じ回線同士で組む、またはアクティブ／スタンバイにする
- → [[BGP]]

### ○ データセンターのネットワーク

- **リーフ・スパイン構成**：各リーフスイッチがすべてのスパインスイッチにつながり、**ECMPで全経路を使う** → STP（Spanning Tree Protocol）で経路を止めずに帯域を使い切れる（△〜○）

### ○ 障害の切り分けが難しい

- どの通信がどの経路を通ったか分かりにくい → 一部の通信だけ失敗する、という症状になる
- 経路ごとに**MTU（Maximum Transmission Unit）や遅延が違う**と、特定のフローだけ遅い・通らない問題が起きる

## 5. 覚え方

- **ECMPは「同じ距離の道が2本あれば、両方使う」**
- **フロー単位は「同じ車列（通信）は同じ道を走らせる」**：追い越し（順序の入れ替わり）を防ぐ。その代わり、大型車の列が1本に集まると渋滞する
- **「束ねても、1つの通信は1本分」**
- **ECMP＋FW2台＝非対称経路の危険**：行きと帰りで別の関所を通ると、帰りは通してもらえない
- **ECMPはL3で別の道、LAGはL2で同じ相手との線を束ねる**

## 6. 勉強の優先順位

1. FWを挟んだECMPで非対称経路になり通信できない理由と対策を30〜40字で書けるようにする
2. フロー単位で分散する理由（順序の入れ替わり）と、偏りが出る理由
3. OSPFのコストでECMPにする・しないの設計
4. リンクアグリゲーションとの違い
5. クラウドVPNの二重化、リーフ・スパインは概要を押さえればよい

> [!tip] 得点につながる覚え方
> ECMPは「帯域を両方使える」便利さより、**「行きと帰りが揃わない」「1つの通信は速くならない」という副作用**が午後で問われやすい。構成図でコストが同じ経路を見つけたら、その途中にFWやNAPT（Network Address Port Translation）装置など**状態を持つ機器**がないかを確認する。
