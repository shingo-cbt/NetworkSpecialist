## 3. 設問ごとの解説

### 設問1(1)　a：バックボーン
- エリアID 0.0.0.0（エリア0）は**バックボーンエリア**。OSPFのすべてのエリアは、エリア0につながる
- スタブエリアは「AS（Autonomous System）外部の経路（タイプ5のLSA（Link State Advertisement））を受け取らないエリア」で、エリアIDとは関係ない

### 設問1(2)　不正なOSPFルータと隣接関係になり経路交換してしまう問題
- 根拠：「OSPFの経路交換をするインタフェースでは，①OSPFのネイバー認証を行うことで，安全に経路交換をするようにしている」
- OSPFは、Helloで相手を自動で見つけて隣接関係を結ぶ。勝手につないだルータとも隣接関係ができ、偽の経路を流し込まれる
- 自分の答えは「偽の経路情報を受け取る」で中身は合っている。**問題の出発点（不正なルータと隣接関係になる）まで書く**と、採点者に意図が伝わる

### 設問1(3)　長くする
- AS_PATHは短い方が優先される。R31が広告する経路のAS_PATHを長くすると、C社SaaSからの通信はR30を選ぶ
- 経路の広告と、通信の向きは逆（広告した経路を見て、相手からの通信の入口が決まる）

### 設問1(4)　OSPFの経路情報が収束した状態
- 根拠：「③プリエンプトディレイを設定し，プライオリティの値が高いルータの電源をオンにした際や再起動した際などは，一定時間が経過した後にマスターに状態遷移する」と、設問の「OSPFを利用していることに着目して」
- プリエンプトだけだと、再起動したR20はすぐにマスタに戻る。PCの通信を受け取っても、まだ経路がそろっていないので転送できない
- 待つ必要があるのは、**経路がそろって転送できる状態**（収束）。ネイバーの確立は、その途中の段階にすぎない（隣接関係ができても、LSA（Link State Advertisement）の交換とSPF（Shortest Path First）の計算が終わるまでは経路がない）
- 記述は「**その状態で何ができるようになるか**」から逆算する：マスタになるのに必要なのは「受け取った通信を転送できること」→ 経路が収束していること

### 設問2(1)　大阪本社：(ウ)　東京支社：(ア)，(イ)
- R10は広域イーサ網側のルータ。通常の通信は広域イーサ網（コスト100）を通る
- 拠点ごとに「R10を通る通信」をたどる

| 送信元 | 宛先 | 経路 | R10を通るか |
|---|---|---|---|
| 大阪 | (ア) インターネット | L3SW10 → FW10 | 通らない |
| 大阪 | (イ) サーバセグメント | L3SW10の中 | 通らない |
| 大阪 | (ウ) C社SaaS | L3SW10 → **R10** → 広域イーサ網 → R30 | 通る |
| 東京 | (ア) インターネット | R20 → 広域イーサ網 → **R10** → L3SW10 → FW10 | 通る |
| 東京 | (イ) サーバセグメント | R20 → 広域イーサ網 → **R10** → L3SW10 | 通る |
| 東京 | (ウ) C社SaaS | R20 → 広域イーサ網 → **R30**（大阪を通らない） | **通らない** |

- 間違えたのは東京の(ウ)。広域イーサ網にはR10・R20・R30がつながっていて、東京から直接C社に届く。「WAN（Wide Area Network）は大阪を中心にしている」と思い込まず、図の線をそのままたどる

### 設問2(2)　65535といった十分大きな値に変更する。
- 迂回させるには、R10を通る経路を、迂回先（IPsec VPN、コスト1000）を通る経路より悪くする
- 2000でも、この構成なら迂回できる。ただ、採点者は「なぜ2000なのか」を答えから読み取れない。**根拠を書かない数値より、「十分大きな値（最大値の65535）」の方が確実**
- 全インタフェースに設定するのは、行きと帰りの両方の向きでR10を避けさせるため（経路のコストは、通るルータの「出ていくインタフェース」のコストの合計）

### 設問2(3)　物理インタフェース閉塞の方が素早く切り戻せるから
- 問われているのは「電源を切る**前に**、インタフェースを閉塞する理由」
- 閉塞した状態で問題が起きても、閉塞を解除すればすぐに元に戻せる。電源を切ってから問題が見つかると、電源を入れて起動を待つ必要がある
- 「〜の前に〜する理由」は、移行・切替の問題では**切り戻し**の観点で考える

### 設問2(4)　イーサネットケーブルにラベルを付与する。
- 自分の答え（接続ポート番号のタグ）で正解。抜く前に、どのポートに挿さっていたかを分かるようにする

### 設問2(5)　L3SW10、R11、R20、R30
- 手順3-2の時点では、インタフェースは開いたが、コストはまだ大きいまま → 業務の通信はまだ新R10を通らない
- ここで確かめるのは、**新R10の各インタフェースが、隣の機器とつながっているか**
- 図1で、R10から線が出ている先を全部拾う：LAN（Local Area Network）側（vlan20）のL3SW10とR11、広域イーサ網側のR20とR30
- FW10とL2SW10・L2SW11は、L3SW10の先にあり、R10の隣ではない。**「隣」は、R10から直接つながる機器だけ**

## 5. 確認するべき観点・知識

- **図から経路や隣接をたどる設問は、メモ用紙に表を作って機械的に確かめる**（送信元／宛先／経路／通るか）。思い込みで「大阪経由」とせず、図の線をそのまま追う
- **「〜に着目して」は答えの方向の指示**（設1(4)：OSPF → 経路の収束）
- **状態を答える設問は、「その状態で何ができるようになるか」から逆算する**
- **数値を答える設問は、根拠になる比較相手を確かめる**（迂回先のコスト）。根拠を書けないなら「十分大きな値」
- **「〜の前に〜する理由」は切り戻しの観点**（素早く元に戻せる）
- 関連するノート：[[OSPF]]（エリア0、コストの計算）、[[VRRP]]（プリエンプトとその遅延）、[[BGP]]（AS_PATHプリペンド、経路と通信の向き）、[[移行・切替手順]]（迂回させてから止める、切り戻し、確認の観点）

## 6. ノートに追記した内容

- [[OSPF]]：迂回させるコストの決め方（迂回先と比べる。根拠が書けなければ最大値の65535）
- [[VRRP]]：プリエンプトの遅延で待つのは「経路が収束して転送できる状態」であること、記述の型
