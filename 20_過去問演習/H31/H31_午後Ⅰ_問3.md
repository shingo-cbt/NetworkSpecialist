## 3. 設問ごとの解説

### 設問1　DHCPリレーエージェント／L3SW1、L3SW2
- PCのセグメント（フロア1・2の4つ）と、DHCPサーバのセグメント（サーバ室）が別 → PCのDHCPDISCOVER（ブロードキャスト）はL3SWを越えられない → **PCのセグメントの出口のL3SW**（L3SW1、L3SW2）でリレーして、DHCPサーバへユニキャストで転送する
- L3SW0は、リレーされたユニキャストのパケットを普通にルーティングするだけ。リレーの設定は要らない

### 設問2(1)　IPアドレスを固定設定すれば、正常PC以外でも通信できる。
- 案1は、DHCPサーバが**正常PCにだけ**アドレスを配る
- ところが、排除対象PCでも、IPアドレスを**手で固定設定**すれば、DHCPを使わずに通信できてしまう
- DHCPスヌーピング（＋IPソースガード）を有効にすると、L2SWは「**DHCPで払い出された組合せ（IP・MAC・ポート）以外の通信**」を通さない → 固定設定のPCは通信できない

### 設問2(2)　DHCPスヌーピングの制限を受けない設定
- L3SWと接続するポートは、DHCPサーバ（リレー）からの応答が来るポート。L3SW自身やサーバ室の機器からの通信も、このポートから入ってくる
- このポートを**信頼するポート**（trusted）にして、スヌーピングの制限（DHCPの応答の破棄、バインディングにない通信の破棄）を受けないようにする

### 設問2(3)　a：エ　b：ア　c：エ　d：オ
- ARPスプーフィングで、通信制限装置が**排除対象PCと相手の間に割り込む**

| | 通信制限装置が送るARP応答（排除対象PCへ） | 通信制限装置が送るARP要求（他の機器へ） |
|---|---|---|
| 送信元ハードウェアアドレス | a：**通信制限装置のMAC** | c：**通信制限装置のMAC** |
| 送信元プロトコルアドレス | b：**アドレス解決対象のIP** | d：**排除対象PCのIP** |
| 意味 | 「あなたが聞いたIP（相手）のMACは、このMACです」→ 排除対象PCの送信先が装置になる | 「排除対象PC（このIP）のMACは、このMACです」→ 相手から排除対象PCへの送信先が装置になる |

- **ARPの送信元の欄は、「このIPアドレスはこのMACアドレス」という名乗り**。うその名乗りをするので、IPは「なりすます相手」、MACは「装置自身」
- 採点講評：「ARPの詳細な仕様を覚えていなくても、IPアドレスからMACアドレスを得るプロトコルであることを理解していれば、正答を導き出せる」

### 設問3(1)　2台
- 条件：装置の各LANポートは異なるセグメント（4ポート）、タグVLANは使わない、フロア間の配線は追加しない
- PCのセグメントは、フロア1に2つ、フロア2に2つ。タグVLANを使わないので、1ポートで1セグメント
- フロア間を配線できないので、フロア1の装置とフロア2の装置を分ける → **各フロアに1台、計2台**（サーバ室の対策は考慮しない）

### 設問3(2)　L3SW1、L3SW1、空き、空き（フロア2の装置ならL3SW2、L3SW2、空き、空き）
- 下線④：接続するスイッチは既設の**L3SW**
- フロア1の2つのセグメントは、L3SW1の**ポートVLAN**（本文「L3SW1、L3SW2で設定されているVLANは、全てポートVLAN」）→ L3SW1のそれぞれのVLANのポートに、装置のポート1・2をつなぐ。ポート3・4は空き

### 設問4(1)　PC管理サーバ、メンテナンスサーバ
- 不正PCを正常PCに戻すには、メンテナンスサーバでアップデートし、Sエージェントが検査結果をPC管理サーバに登録する必要がある

### 設問4(2)　L3SW0／対処用セグメントへのルーティング情報を追加する。DHCPサーバ／対処用セグメントのアドレスプールを追加する。
- **L3SW0**：ルーティングは全部スタティック → サーバ室から対処用セグメントへ**戻る**経路を追加する（サーバ宛ての経路は前からある）
- **DHCPサーバ**：PCのアドレスはDHCPで配る → 新しいセグメントのアドレスプールを追加する
- 新しいセグメントを作ったら、「**経路（行きと帰り）**」と「**アドレスを配る仕組み（DHCPのプール、リレー）**」の両方を確かめる

## 4. 間違えた理由

| 設問 | 分類 | 中身 |
|---|---|---|
| 設1 スイッチ | 知識不足（リレーの置き場所） | リレーはPCのセグメントの出口だけ。リレー後はユニキャストなので、途中のL3SWは関係ない |
| 設2(1) | 当てはめ漏れ（下線の目的） | スヌーピングの一般的な効果（不正なDHCPサーバ）を書き、下線②の目的（取得したPCだけ通信可能）に合わせていない |
| 設2(3) b | 知識不足（ARPの名乗り） | ARPの送信元の欄は「このIPはこのMAC」の名乗り。偽装ではIPに「なりすます相手」を入れる |
| 設3(1)(2) | 読み落とし（本文の制約） | 下線③（タグVLANなし、フロア間配線なし）と下線④（既設のL3SWに接続）、「ポートVLAN」を使わなかった |
| 設4(2) 機器② | 当てはめ漏れ | 下線①（PCのアドレスはDHCPで配る）を、新しいセグメントの追加に結びつけていない |

## 5. 確認するべき観点・知識

- **DHCPリレーは、DHCPクライアントのセグメントの出口のルータ（L3SW）だけに設定する**
- **DHCPスヌーピングの2つの効果**：①不正なDHCPサーバの応答を捨てる、②DHCPで払い出されていない（固定設定の）端末の通信を通さない。設問の下線の目的に合う方を答える
- **ARPスプーフィングの欄**：送信元のIP ＝ なりすます相手、送信元のMAC ＝ 自分
- **本文の制約（タグVLANなし、配線追加なし、接続先はL3SW）から台数・接続先を決める**
- **セグメントを追加したら、戻りの経路とDHCPのアドレスプール**
- 関連するノート：[[DHCP]]、[[Gratuitous ARP]]、[[スタティックルーティング]]、[[VLAN]]

### 読み方の型

1. **下線の「〜となるように」が、その対策の目的**。「しない場合の問題」はその目的の裏返し
2. **台数・接続先の設問は、本文の制約を全部書き出してから数える**
3. **新しく作ったものには、それを使えるようにするための設定（経路、アドレスの配布）が必ず要る**
