## 3. 設問ごとの解説

### 設問1(1)　a：BGP　b：バックボーン　c：GARP
- a：ISPとの冗長経路接続のための、パスベクトル型のルーティングプロトコル → BGP
- b：OSPFのエリアが1つだけなら、それは**バックボーン**エリア（エリア0）
- c：新しいマスタが、L2SWのMACアドレステーブルを更新するためにブロードキャストする → GARP

### 設問1(2)　キ、ク、ケ
- VRRPのアドバタイズメントは、**同じセグメント（顧客VLAN）の中**に送るマルチキャスト（224.0.0.18）。ルータを越えて転送されない
- 顧客VLANは、L3SWのL2SW側のポート（タグVLAN）からL2SWへ延びている → L3SW1 →**キ**→ L2SW1 →**ケ**→ L2SW2 →**ク**→ L3SW2
- カ（L3SW1〜L3SW2）は「独立したIPセグメント」なので顧客VLANは流れない。ウ・エ・オはコアルータを通るL3の経路
- 採点講評：「VRRPを構成する2台がどの回線を経由して、互いの正常性を確認し合うかは重要な点」

### 設問1(3)　キ、ク、ケ
- 顧客ごとに1つのVLANを割り当て、L3SWのL2SW向けポートにタグVLANを設定 → 複数の顧客VLANが通る回線にはタグが必要
- L3SW〜L2SW（キ、ク）と、L2SW1〜L2SW2（ケ）。カは独立したIPセグメントなので顧客VLANは通らない

### 設問1(4)　リンクダウンを伴わない故障発生時に、LAGのメンバから故障回線を自動で除外できる。
- ビル3階と4階の間は、スイッチ ─ M/C ─ 光ファイバ ─ M/C ─ スイッチ
- 光ファイバが切れても、M/Cはスイッチ側（1000BASE-T）をリンクダウンさせない → スイッチから見るとリンクは**正常（リンクアップ）のまま**
- **静的LAG**：リンクの状態だけで判断するので、切れた回線にもパケットを振り分け続ける（その分が失われる）
- **LACP**：両端がLACPのメッセージを定期的に交換している → 相手から届かなくなったら、その回線を**LAGから外す**
- 採点講評：「なぜLACPを利用するのか、把握しておいてほしい」

### 設問1(5)　1Gビット／秒を超えたパケットが廃棄される。
- 下線②の対策をしないと：LAGの2本のうち1本が切れると、残り1本（1Gビット／秒）に全部が寄る
- 設計方針「ビル4階の顧客の合計は最大**2G**ビット／秒」「回線が1か所切れても**輻輳させない**」→ 1Gビット／秒を超えた分は**廃棄**される
- だから、1本切れたら同じLAGを構成するIFを全部閉塞し、もう一方の経路（L3SW4側）に切り替える

### 設問1(6)　送信元と宛先MACアドレスの組合せが少なく、ハッシュ値が分散しないから
- コアルータとL3SWの間は、ルータどうし → フレームの送信元・宛先MACは、いつもその2台のもの
- MACアドレスの組でハッシュすると、値が変わらず1本に偏る。IPアドレスとポート番号の組なら、通信ごとに分散する

### 設問2(1)　d：ICMP　e：SNMPトラップ　f：MIB
- ping ＝ ICMP、状態変更の通知 ＝ トラップ、管理情報ベース ＝ MIB

### 設問2(2)　(iii)
- 各回線のトラフィック量 ＝ インタフェースの**送受信バイト数のカウンタ**（MIB）を、5分ごとに取得し、差分 × 8 ÷ 秒数で求める → [[SNMP]]

### 設問2(3)　コアルータからL3SWまでの区間
- 追加した監視：監視装置 → L2SWz2 → **コアルータ** → 顧客のデータが流れるネットワーク → **L3SWのVRRPの仮想IPアドレス**
- 仮想IPアドレスにpingが通れば、コアルータからL3SW（マスタ）までが正常に通信できていると分かる
- CRは顧客が設置・管理するので、Z社の監視の対象ではない

## 4. 間違えた理由

| 設問 | 分類 | 中身 |
|---|---|---|
| 設1(2)、設1(3) | 当てはめ漏れ（本文の条件） | 「L3SW同士を接続している回線は独立したIPセグメント」を使わず、カを入れた。VRRPのアドバタイズメントがL2のセグメントの中だけを流れることを、構成図に当てはめていない |
| 設1(4) | 読み落とし・知識不足 | 本文の「M/Cには自動でリンクダウンさせる機能はない」と、LACPの目的（リンクダウンしない故障の検知）を結びつけられなかった |
| 設1(5) | 着地点のずれ | 「輻輳」で止まり、設計方針の数値（2G、1本1G）に当てはめた「廃棄」まで書いていない |
| 設2(2) | 知識の取り違え | トラフィック量（定期取得のMIB）と、異常の通知（トラップ）を混同した |
| 設2(3) | 当てはめ漏れ（宛先） | pingの宛先（L3SWの仮想IPアドレス）から区間の終点を決めていない |

## 5. 確認するべき観点・知識

- **VRRPのアドバタイズメントは、L2のセグメントの中だけ**（マルチキャスト224.0.0.18、ルータを越えない）
- **LACPを使う理由**：リンクダウンを伴わない故障（M/Cを挟む回線、片方向の故障）を、LACPの交換が止まることで検知し、LAGから外す
- **LAGの1本が切れたときの影響は、設計の数値で書く**（合計2G、1本1G → 超えた分は廃棄）
- **監視方法の使い分け**：死活 ＝ ping、異常の通知 ＝ トラップ、量の把握 ＝ MIBの定期取得
- **監視の区間は、pingの送信元と宛先で決まる**
- 関連するノート：[[リンクアグリゲーション]]、[[VRRP]]、[[VLAN]]、[[SNMP]]、[[ネットワーク監視]]
