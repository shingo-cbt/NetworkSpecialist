## 3. 設問ごとの解説

### 設問1　ア：ICMP　イ：IPアドレス　ウ：UDP　エ：コミュニティ
- ア：ping ＝ ICMP（RFC 792）のecho request／reply
- イ：pingの宛先にするため、監視対象の機器にIPアドレスを割り当てる
- ウ：SYSLOGは**UDP**（RFC 768）で送る → 届かなくても送信側は分からない
- エ：SNMPv2cで、同じグループであることを示すのは**コミュニティ**名（パスワードのような文字列）

### 設問2(1)　デフォルトゲートウェイ
- VRRPで冗長化するのは、PCやサーバに設定する**デフォルトゲートウェイ**（仮想IPアドレス）

### 設問2(2)　VRRPアドバタイズメント
- マスタが定期的に送る。届かなくなるとバックアップがマスタになる

### 設問2(3)　VLAN100、VLAN200、VLAN300
- コアSW1・コアSW2のp1〜p3は、どちらもVLAN100・200・300のアクセスポート
- 各VLANでVRRPのアドバタイズメントをやり取りし、STPのループ構成を作るには、2台の間のp4に**すべてのVLAN**を通す必要がある

### 設問3(1)　p2
- ケーブル1（フロアSW1 p1 〜 コアSW1 p2）が切れる → それまでブロックしていた**フロアSW2のp1**がフォワーディングへ。BPDUを受けなくなったのは、フロアSW2でコアSW1側からのBPDUが来ていたポートではなく、フロアSW1とつながる**p2**（フロアSW1経由でコアSW1のBPDUが届いていた）

### 設問3(2)　スパニングツリーが再構築中だったから
- ケーブル2の断線と同時にケーブル1も切れていた → フロアSW1から監視サーバへの経路は、フロアSW2経由に切り替わる途中
- STPの再構築（ブロッキング → リスニング → ラーニング → フォワーディング、合わせて数十秒）の間は、フレームを転送できない
- SYSLOGはUDPで1回送るだけ → その間に送ったメッセージは失われる

### 設問4(1)　（エージェント）フロアSW1など／（マネージャ）監視サーバ
- 監視対象の機器（コアSW、サーバSW、フロアSW）がエージェント、監視サーバがマネージャ

### 設問4(2)　ポーリング：5分ごとに状態を取得するので多くの場合異常検知が遅れる。トラップ：到達確認がないのでメッセージが失われる可能性がある。
- 下線⑦は「**今回発生した**ネットワークの異常においては、それぞれ問題がある」
- ポーリング：次の問合せまで最大5分待つ → **検知が遅れる**
- トラップ：UDPで送りっぱなし → STPの再構築中に送ると、**確認がないので失われても分からない**（SYSLOGと同じ問題）
- 採点講評：「ポーリングとトラップの特徴を踏まえた解答を期待した」→ 事象の説明ではなく、方式の特徴（遅れる／確認がない）で書く

### 設問4(3)　スパニングツリーが再構築するまでインフォームの再送信を繰り返す。
- インフォームは、トラップに**確認応答と再送**を付けたもの
- 下線⑧「**今回と同様な**ネットワークの異常に備えて、マネージャがインフォームの受信を行えるよう」→ STPの再構築（数十秒）が終わるまで、再送が続くように、再送の回数・間隔を設定する
- 採点講評：「問題文をよく読み、設問で何が問われているかを正しく理解し、注意深く解答してほしい」

## 5. 確認するべき観点・知識

- **SYSLOGもSNMPのトラップもUDPで送りっぱなし** → 経路が切り替わる途中（STPの再構築中）に送ると失われる
- **ポーリング ＝ 検知が遅れる、トラップ ＝ 到達確認がない、インフォーム ＝ 確認応答と再送がある**
- **STPの再構築中は転送できない**（ブロッキング → リスニング → ラーニング → フォワーディング）
- **コアSW間のトランクには、両方にアクセスポートがある全部のVLANを通す**
