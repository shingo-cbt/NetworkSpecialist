## 3. 設問ごとの解説

### 設問1　ア：NAPT　イ：事前共有鍵　ウ：AS　エ：TCP　オ：ICMP　カ：echo reply
- ア：IPアドレスとポート番号を変換する ＝ NAPT
- イ：IKEのフェーズ1で、両方の機器に同じ鍵をあらかじめ設定する ＝ 事前共有鍵
- ウ・エ：BGPはAS（自律システム）の間で経路を交換する。TCPの179番
- オ・カ：pingはICMPのecho requestを送り、echo replyが返ってくるかで確かめる

### 設問2(1)　暗号化対象の通信がグローバルIPアドレス間の通信だから
```
元のパケット：         [IP：社内のプライベート][データ]
IP in IPで包む：       [IP：VPNa1 → VPNa2（グローバル）][IP：社内][データ]
IPsec（トランスポート）：[IP：VPNa1 → VPNa2][ESP][IP：社内][データ][ESPトレーラ]
                                                └──── 暗号化 ────┘
```
- IP in IPで包んだ時点で、外側のヘッダは**VPNルータどうしのグローバルIPアドレス**になっている → インターネットをそのまま運べる
- トンネルモードは「新しいIPヘッダを付けて包む」ためのもの。もう包んであるので要らない（付けるとヘッダが重複して、パケットが大きくなるだけ）
- 社内のプライベートアドレスのパケットは、外側のヘッダの内側にあるので、トランスポートモードでも暗号化される

### 設問2(2)　フラグメントとリアセンブルの処理が発生する。
- IP in IPのヘッダ（20バイト）とESP（Encapsulating Security Payload）のヘッダ・トレーラが増える → トンネルインタフェースのMTUを1,500のままにすると、物理インタフェース（1,500）を超える
- 送る側のVPNルータで**分割（フラグメント）**、受ける側で**組み立て**（リアセンブル）が発生し、負荷が上がる → だからMTUとTCP MSSを小さく書き換える

### 設問3(1)　BGPによって回線断や機器障害を検知し、トラフィックをう回できる。
- 静的経路は、回線や機器が止まっても経路が残る → スタンバイ側に切り替わらない
- BGPなら、ピアが切れると経路が消える → アクティブのトンネルが止まれば、スタンバイの経路が使われる（自動で迂回）

### 設問3(2)　Helloパケットを出さない。
- トンネルインタフェースのOSPFは、経路情報の交換が要らない（下線④）→ **パッシブインタフェース**にする
- OSPFのパッシブインタフェースは**Helloを送らない** → ネイバーができないので、LSA（Link State Advertisement）のやり取りもしない。そのインタフェースのネットワークは、OSPFの経路として広告される

### 設問3(3)　A：大きく
- 社内からクラウド方向：L3SWが、VPNa1とVPNb1のどちらへ送るかを、OSPFのコストで決める → スタンバイのVPNb1が再配布するときのコストを**大きく**する

### 設問3(4)　eBGPからOSPFへ再配布された経路を再びeBGPへ再配布しない。
- VPNa1とVPNb1の両方で、OSPF ⇔ BGPを相互に再配布している（境界が2か所、双方向）
- VPNa1がBGPで受けたクラウドの経路をOSPFに再配布 → VPNb1がOSPFで受けて、それをBGPに再配布してクラウドへ広告 → 経路が一周する
- 対策：**BGPから来た経路は、BGPに戻さない**（ルートフィルタ、ルートタグ）
- AS_PATHのループ防止は、BGPの中だけで効く仕組み。OSPFを経由すると、AS_PATHの情報が消えるので働かない

### 設問4　ネットワーク接続の冗長構成が失われたことを検出するため
- 通常はアクティブ側だけが通信している。スタンバイ側のトンネルが切れても、通信は止まらないので気づけない
- その状態でアクティブ側も止まると、全部止まる → スタンバイ側も監視して、**冗長構成が失われた**ことを早く知り、直しておく

## 5. 確認するべき観点・知識

- **IP in IP ＋ IPsecならトランスポートモード**：外側のヘッダが、もうVPNルータどうしのグローバルアドレスだから
- **トンネルのMTUを下げないと、フラグメントとリアセンブルが発生する**
- **動的経路制御の利点 ＝ 障害を検知して、自動で迂回できる**
- **OSPFのパッシブインタフェース ＝ Helloを出さない**（ネイバーを作らない。ネットワーク自体は広告される）
- **2か所で双方向に再配布するとループする → 受けた経路を、元のプロトコルに戻さない**
- **アクティブ・スタンバイは、スタンバイ側も監視する**（冗長構成が失われたことに気づくため）
