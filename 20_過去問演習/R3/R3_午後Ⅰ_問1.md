## 3. 設問ごとの解説

### 設問1(1)　DHCPサーバ
- 在庫管理端末はDHCPクライアント → DNSサーバのアドレスはDHCPサーバが配る

### 設問1(2)　82
- 192.168.1.0/24 → 使えるアドレスは254個
- 本社：DHCPサーバ、DNSサーバ、在庫管理サーバ、在庫管理端末2台、L2SW ＝ **6個**
- 店舗1つ：L2SW、在庫管理端末2台 ＝ **3個**（「各機器にはIPアドレスが一つ」なので、L2SWにもある）
- (254 − 6) ÷ 3 ＝ 82.66… → **82店舗**

### 設問1(3)　L2SWの入力ポート以外の全てのポートに転送される。
- 在庫管理サーバはARPテーブルで宛先MACを知っているので、ARPはせずに**ユニキャスト**のフレームを送る
- L2SWの**MACアドレステーブルは空** → 出すポートが分からない → 受信ポート以外の全ポートに出す（**フラッディング**）
- 「ARPで調べてから」はPC（サーバ）側の話で、設問の前提（ARPテーブルにある）と合わない

### 設問2(1)　RT管理コントローラのIPアドレスが変更された場合でもRTの設定変更が不要である。
- RTはC社から出荷される時点で設定済み。FQDNで書いておけば、コントローラのアドレスが変わってもDNSを直すだけ

### 設問2(2)　HTTP又はHTTPS
- 下線①「**REST API**を利用して」→ REST APIはHTTP（HTTPS）の上で動く

### 設問2(3)　運用管理サーバ
- 在庫管理端末011は店舗のL2SW01 → RT01の**BP**につながる。運用管理サーバも本社のL2SW00 → RT00の**BP**側
- 本文「店舗のRTのBPは、トンネルで接続された本社のRTのBPと**同一ブロードキャストドメイン**となる」→ 端末と運用管理サーバは、L2で直接つながった同じセグメント
- ルータ（L3）を経由しないので、TTLは減らない → tracerouteに出るのは**宛先の運用管理サーバだけ**
- RTは、BPではL2のブリッジとして動いている。L2の機器はtracerouteに表示されない

### 設問2(4)　店舗から本社にはBP経由でしかアクセスができないから
- Wi-Fi APはRT01の**RP**につながる（図3）
- 本文：「RPに接続した機器とBPに接続した機器との間の通信はできない」「インターネットからRPに接続した機器へのアクセスはできない」→ RP側は、NATでインターネットに出ることしかできない
- 本社につながる道はBPのトンネルだけ。そこにWi-Fi APを置くと、フリーWi-Fiから在庫管理システムに入れてしまう（要件違反）→ 本社にはログサーバを置けない（クラウドなど、インターネット上に置く）

### 設問3(1)　a：2
- LLDPは**データリンク層**（第2層）のプロトコル

### 設問3(2)　b：SNMP　c：RT管理コントローラ
- b：「SNMPによる監視…は運用管理サーバに担わせる」→ MIBの取得はSNMP
- c：RTは「RT管理コントローラから行う。他の機器からは行うことができない」→ RTのLLDP-MIBは、RT管理コントローラが集めて、運用管理サーバがREST APIで受け取る

### 設問3(3)　各機器の接続構成が構成図どおりであること
- 店員が構成図を見て配線する → LLDPで、構成図どおりにつながっているかを確かめる。採点講評：「LLDPを用いた確認であることを読み落とした解答が散見された」

### 設問3(4)　イ、エ、カ
- L2SW-XをL2SW01のIF2と端末011の間に入れる → L2SW01のIF2の隣は**L2SW-X**（イ）、端末011のIF1の隣も**L2SW-X**（エ）
- L2SW-XはLLDPを送るので、隣の機器には見える → 「**隣接機器名**L2SW-X」の行ができる（カ）
- L2SW-Xの管理用IPアドレスは分からない → 運用管理サーバはL2SW-X自身のMIBを取れない → 「自機器名L2SW-X」の行はできない（オは誤り）

## 4. 間違えた理由

| 設問 | 分類 | 中身 |
|---|---|---|
| 設1(3) | 当てはめ漏れ（再発・3回目） | フラッディングを、一問一答では答えられたのに、問題の場面（MACアドレステーブルが空）に当てはめられなかった。設問の前提（ARPテーブルにはある）を読み落とした |
| 設1(2) | 数え漏れ | 本社の機器の数（L2SWを含めて6個） |
| 設2(3) | 知識不足（L2トンネル） | L2 over IPトンネルで同じブロードキャストドメインになる → ルータを経由しない、をtracerouteに結びつけられなかった（講評でも正答率が低い） |
| 設2(4)、設3(2) c | 読み落とし（本文の制約） | 「RPとBPの間は通信できない」「他の機器からは行うことができない」の制約を使っていない |
| 設3(4) | 知識不足（LLDPとMIBの取得） | LLDPを送る機器は隣から見えるが、管理用IPが分からなければ自身のMIBは取れない |

## 5. 確認するべき観点・知識

- **L2SWがフラッディングする条件**：宛先MACを学習していない（テーブルが空）、ブロードキャスト、スヌーピングのないマルチキャスト
- **L2トンネル（L2 over IP、EtherIP、L2TPv3）**：両端が同じブロードキャストドメイン → tracerouteでは、途中のルータが出ない
- **本文の「できない」「〜だけ」は、そのまま答えの根拠になる**
- **LLDP**：隣接機器に自分の情報を送るL2のプロトコル。受け取った側はLLDP-MIBに保持し、SNMPで取得できる
- 関連するノート：[[VLAN]]（MACアドレスの学習とフラッディング）、[[ICMP]]（traceroute）、[[SD-WAN]]（L2を延ばす技術）、[[SNMP]]、[[ネットワーク監視]]（LLDP）、[[IPアドレスとサブネット]]

1. **設問文の前提（「〜は保持されている」「何も学習されていない」）を、答えの条件として線を引く**
2. **「できない」「他の機器からは」は、機器の役割を限定する根拠**
3. **計算では、図の機器をすべて書き出して数える**
