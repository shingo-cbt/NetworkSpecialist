# SDN まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. SDNの基本（○）

- **SDN（Software-Defined Networking）**：ネットワーク機器の**制御**（どう転送するかを決める）と**転送**（実際にパケットを送る）を分け、**制御をコントローラに集中**させて、ソフトウェアでネットワーク全体を設定する考え方

| 機能 | 従来の機器 | SDN |
|---|---|---|
| **コントロールプレーン**（経路の計算、転送ルールの決定） | **各機器が自分で**持つ | **コントローラにまとめる** |
| **データプレーン**（パケットの転送） | 各機器 | 各機器（スイッチ） |

- 利点
  - **ネットワーク全体を1か所で設定・変更**できる（機器ごとの設定が不要）
  - プログラムで自動化できる、通信の経路を柔軟に制御できる
- 欠点：**コントローラが止まると制御できない**（単一障害点）→ コントローラを冗長化する
- API（Application Programming Interface）の向き
  - **サウスバウンドAPI**：コントローラ ⇔ スイッチ（OpenFlowなど）
  - **ノースバウンドAPI**：アプリケーション ⇔ コントローラ

## 2. OpenFlow（○）

- **OpenFlow**：コントローラがスイッチに転送ルールを指示するプロトコル
- スイッチは**フローテーブル**を持つ
  - **マッチ条件**：受信ポート、MAC（Media Access Control）アドレス、IP（Internet Protocol）アドレス、ポート番号など
  - **アクション**：転送、破棄、書き換え（VLAN（Virtual LAN）タグの付与など）
- **フローテーブルに一致しないパケット**は、スイッチが**コントローラに問い合わせる（Packet-In）** → コントローラが判断してルールを登録する（Flow-Mod）
- 従来の「宛先MACアドレス・宛先IPアドレスだけで転送」と違い、**送信元やポート番号など、いろいろな条件で経路を決められる**

## 3. 午後で問われるテーマ

### ○ SDNを導入する利点

- 多数の機器の設定変更を、コントローラから一括で行える（作業の手間とミスの削減）
- 利用者・アプリケーションごとに通信の経路を変える（特定の通信だけ別の経路に流す）
- 記述の型：「コントローラから全スイッチの転送ルールを一元的に設定できるため、機器ごとに設定する必要がないから」

### ○ コントローラの障害

- コントローラが止まると、**新しい通信のルールを登録できない**（すでに登録されたルールでは転送を続けられることが多い）
- コントローラとスイッチの間の通信（管理ネットワーク）も冗長化する

### ○ NFVとの違い

- **SDN：制御の集中（どう転送するかをソフトウェアで決める）**
- **NFV（Network Functions Virtualization）：機能のソフトウェア化（FW（Firewall）・ルータなどを汎用サーバで動かす）**
- → [[仮想化]]

### ○ SD-WANとの関係

- **SD-WAN**（Software-Defined WAN）は、SDNの考え方を**WAN**（Wide Area Network、拠点間の回線）に応用したもの → [[SD-WAN]]

## 4. 覚え方

- **SDNは「信号機の制御を管制センター（コントローラ）にまとめる」**：各交差点（スイッチ）は指示どおりに車を流すだけ
- **コントロールプレーンは「頭脳」、データプレーンは「手足」**
- **OpenFlowは「マッチ条件とアクションの表」**、分からないパケットはコントローラに聞く（Packet-In）
- **サウスは「下（スイッチ）へ」、ノースは「上（アプリ）へ」**
- **管制センターが止まると困る → 冗長化**

## 5. 勉強の優先順位

1. コントロールプレーンとデータプレーンの分離、SDNの利点と欠点
2. OpenFlowのフローテーブル（マッチ条件とアクション）とPacket-In
3. SDNとNFVの違い
4. サウスバウンド・ノースバウンドAPIは午前で確認する程度でよい

> [!tip] 得点につながる覚え方
> SDNは午前では用語、午後では「**なぜ導入するか（一元管理・柔軟な経路制御）」「コントローラが止まったらどうなるか**」の形で問われる。
