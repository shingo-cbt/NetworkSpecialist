# IoT まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

令和7年春 午後Ⅱ 問2は、LPガスの遠隔検針を題材に、**LPWA（Low Power Wide Area）回線の選択、CoAP（Constrained Application Protocol）の利用、IoTシステムのセキュリティ対策**を問う問題だった（IPA（情報処理推進機構）の出題趣旨より）。

## 1. IoTの特徴（○）

- **IoT（Internet of Things）**：センサ、メータ、機械などの「モノ」がネットワークにつながり、データを送る
- IoT機器の制約
  - **電池で長期間（数年）動かしたい** → 消費電力を小さく
  - **処理能力・メモリが小さい** → 軽いプロトコルが必要
  - 送るデータは**少量**（数十〜数百バイトを1日数回など）
  - **台数が多い**、設置場所が遠い・広い（山間部、地下）

## 2. LPWA（◎）

- **LPWA**：**低消費電力で、遠くまで（数km〜十数km）届く**が、**通信速度は遅い**無線通信の総称

| 種類 | 周波数 | 特徴 |
|---|---|---|
| **LoRaWAN**（Long Range WAN） | **免許不要**の帯域 | 自前で基地局（ゲートウェイ）を置ける |
| Sigfox | 免許不要の帯域 | 事業者のサービス。非常に低速・少量 |
| **NB-IoT（Narrow Band IoT）** | **携帯電話の帯域（免許が必要）** | 通信事業者の基地局を使う。品質が安定 |
| **LTE-M（LTE for Machines）** | 携帯電話の帯域 | NB-IoTより高速、移動しながらも使える |

- 比較の観点：**免許の要否（自前で基地局を建てるか、事業者の網を使うか）**、通信距離、速度、消費電力、移動への対応、費用
- 携帯電話の帯域を使う方式では、**SIM**（Subscriber Identity Module）で機器を識別・認証し、**閉域網**に直接つなぐこともできる（インターネットを通らない）
- 記述の型：「通信事業者のセルラー網を利用するため、基地局を自前で設置する必要がなく、通信品質も安定しているから」
- 近距離の無線：ZigBee、BLE（Bluetooth Low Energy）（△）

## 3. IoT向けのプロトコル（◎）

| | **MQTT（Message Queuing Telemetry Transport）** | **CoAP** |
|---|---|---|
| 下位 | **TCP（Transmission Control Protocol）**（1883、TLS（Transport Layer Security）は8883） | **UDP（User Datagram Protocol）**（5683、DTLS（Datagram TLS）は5684） |
| 通信モデル | **パブリッシュ／サブスクライブ**：送信者（パブリッシャ）が**ブローカ**に送り、そのトピックを購読する受信者（サブスクライバ）に届く | **クライアント／サーバ**（HTTP（Hypertext Transfer Protocol）に似たGET・PUTなど） |
| 特徴 | ヘッダが小さい。**QoS**（Quality of Service、0：最大1回、1：最低1回、2：ちょうど1回）で届け方を選べる | とても軽い。確認応答が必要なメッセージ（Confirmable）を選べる |
| 向く場面 | 多数の機器からのデータ収集、通知 | 処理能力がとても小さい機器、UDPで済ませたい場合 |

- HTTPより軽い（ヘッダが小さく、接続の手順が少ない）→ 通信量・消費電力を減らせる
- **CoAPとリフレクション攻撃**：UDPなので送信元を詐称できる → 小さな要求に大きな応答を返すと**踏み台**にされる。令和7年春 午後Ⅱ 問2では、**ハンドシェイクで送信元IP（Internet Protocol）アドレスが詐称されていないことを確かめ、詐称ならハンドシェイクを終了する**対策が問われた → [[DNSリフレクタ攻撃]]

## 4. 午後で問われるテーマ

### ◎ 回線・プロトコルの選択

- 設置場所（山間部、地下）、台数、データ量、電池の寿命、費用から、LPWAの種類やプロトコルを選ばせる
- 記述の型（MQTTを使う理由）：「ブローカを介したパブリッシュ／サブスクライブ型で、ヘッダが小さく、多数の機器からのデータを少ない通信量で収集できるため」

### ◎ IoTのセキュリティ

| 攻撃者の観点 | 防御側の対策 |
|---|---|
| **初期パスワードのまま**の機器に侵入し、ボットにする（DDoS（Distributed Denial of Service）攻撃の踏み台） | 初期パスワードを変更する、機器ごとに異なるパスワード・**証明書**で認証する |
| **ファームウェアの脆弱性**を突く | ファームウェアを**遠隔で更新**できる仕組み（署名で正当性を確認）を用意する |
| 通信を盗聴・改ざんする | **TLS／DTLS**で暗号化する（処理能力に応じて） |
| 偽の機器がデータを送る、偽のサーバに誘導する | 機器とサーバの**相互認証**（証明書、SIM） |
| インターネットから機器に直接アクセスする | **閉域網**（SIMを使った閉域接続）に置き、インターネットから見えないようにする |
| UDPのプロトコルを**リフレクション攻撃の踏み台**にする | 送信元の確認（ハンドシェイク）、応答を小さくする、外部からの要求に応答しない |

## 5. 覚え方

- **LPWAは「遠くまで、電池長持ち、でも遅い」**：免許不要のLoRaWAN・Sigfox、携帯網のNB-IoT・LTE-M
- **MQTTは「掲示板（ブローカ）に貼ると、購読者に届く」**：TCP 1883、QoS 0／1／2
- **CoAPは「UDPで動く小さなHTTP」**：5683、詐称に注意（踏み台）
- **IoTのセキュリティは「初期パスワード・更新・暗号化・認証・閉域」**

## 6. 勉強の優先順位

1. LPWAの種類と選び方（免許の要否、距離、速度）
2. MQTTとCoAPの違い（TCP／UDP、パブリッシュ／サブスクライブ、ブローカ）
3. IoTのセキュリティ対策（攻撃者の観点と対策）を30〜40字で書けるようにする
4. CoAPのリフレクション攻撃への対策
5. ZigBee、BLEは名前を知っている程度でよい
