# SD-WAN まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. SD-WANの基本（○）

- **SD-WAN（Software-Defined WAN）**：拠点間・拠点とクラウドの間の**WAN（Wide Area Network）を、ソフトウェアで一元的に制御**する仕組み（SDN（Software-Defined Networking）の考え方をWANに応用したもの）
- 主な機能

| 機能 | 内容 |
|---|---|
| **複数の回線をまとめて使う** | 閉域網、インターネット回線、LTE（Long Term Evolution）／5G回線などを組み合わせ、その上に**IPsec（Security Architecture for Internet Protocol）などのトンネル（オーバーレイ）**を張る |
| **アプリケーションごとの経路選択** | 通信の種類（Web会議、業務システム、SaaS（Software as a Service））を識別し、**回線の品質（遅延・損失）に応じて最適な回線**に流す |
| **ローカルブレイクアウト** | **SaaSへの通信を、本社を経由せず拠点から直接インターネットへ**出す |
| **一元管理・ゼロタッチプロビジョニング** | コントローラから全拠点の設定を配る。拠点の機器は**つなぐだけで設定が自動で入る** |

## 2. ローカルブレイクアウト（◎）

- 従来：全拠点のインターネット通信を**本社（データセンター）に集め**、本社のプロキシ・FW（Firewall）を経由して出す
  - **SaaS（Web会議、クラウドのメール・ストレージ）の利用が増える**と、本社の回線・プロキシが混雑し、遅くなる
- **ローカルブレイクアウト**：**特定のSaaSへの通信だけ**を、拠点のインターネット回線から**直接**出す
  - 本社の回線・プロキシの負荷が減る、SaaSへの遅延が小さくなる
  - SD-WANの機器が**アプリケーション（宛先のドメイン・IPアドレス）を識別**して振り分ける
- 注意：本社のプロキシ・FWを通らなくなる → **拠点でのセキュリティ（SWG（Secure Web Gateway）などクラウドのセキュリティサービス）**が必要 → [[ゼロトラスト・SASE]]
- 記述の型：「SaaS宛ての通信を拠点から直接インターネットへ送出することで、本社の回線とプロキシの負荷を軽減できるため」
- → [[プロキシ]]

## 3. WANサービスの比較（◎）

SD-WANを導入する前の「今のWAN」として、問題文によく出てくる。**網を誰が用意するか**と**L2かL3か**で区別する。

| 種類 | 網 | 運ぶもの | 拠点間のルーティング | 暗号化 | 費用・品質 |
|---|---|---|---|---|---|
| **専用線** | 事業者（2点間を占有） | 何でも | 自社で決める | 不要 | 最も高い・帯域を独占 |
| **広域イーサネット** | **事業者の閉域網** | **L2**（Ethernetフレーム） | **利用者が自由に選べる**（OSPF（Open Shortest Path First）などを拠点のルータ同士で動かせる。IP以外も通せる） | 不要 | 高い・安定 |
| **IP-VPN** | **事業者の閉域網**（MPLS（Multi-Protocol Label Switching）） | **L3**（IPパケット） | **事業者のルータ**と経路を交換する（BGP（Border Gateway Protocol）、スタティック） | 不要 | 高い・安定 |
| **インターネットVPN**（Virtual Private Network） | インターネット | L3 | 自社で決める | **IPsecで暗号化** | 安い・品質の保証なし |

### 広域イーサネットの2つの使い方

- **① 拠点ごとにルータを置き、別のサブネットにする（一般的）**
  - 広域イーサネットは「拠点のルータ同士をつなぐ大きなL2スイッチ」の役割。拠点間はルータでルーティングする
  - WAN側は多数のルータがつながる1つのセグメントになるので、OSPFを動かすと**DR（Designated Router）／BDR（Backup DR）の選出**が起きる
  - ブロードキャストを拠点の中に閉じ込め、障害の範囲を拠点ごとに分けられる
- **② 同じVLAN（Virtual LAN）を拠点間で延ばす**
  - 事業者が利用者のVLANタグの外側に事業者用のタグを重ねて運ぶ（**Q-in-Q**）ので、利用者は自分のVLAN番号のまま拠点間をつなげる
  - 拠点間で同じサブネットを使いたい場合（IPアドレスを変えずにサーバを移したい）に使う
  - その代わり、**ブロードキャストやループの影響が全拠点に及ぶ** → 必要な所だけにする

### よく出る比較・変更の論点

- **広域イーサネットとIP-VPNの違いは「L2かL3か」**：広域イーサネットはルーティングプロトコルを自由に選べる、IP-VPNは事業者のルータと経路を交換する
- **閉域網からインターネットVPNに変える**と：暗号化（IPsec）が必要になる、品質が保証されなくなる、NAT-T（NAT Traversal）やMTU（Maximum Transmission Unit）の考慮が要る → [[IPsec]]、[[MTUとフラグメント]]
- **L2を自社で延ばす技術**：EtherIP over IPsec、L2TPv3（Layer 2 Tunneling Protocol version 3）、データセンターならVXLAN（Virtual eXtensible LAN）→ [[仮想化]]
- 記述の型：「広域イーサネットはL2で拠点間を接続するため、利用者が任意のルーティングプロトコルを使用できるから」
- 記述の型：「拠点間を同一のL2で接続すると、ブロードキャストやループの影響が全拠点に及ぶから」

## 4. 午後で問われるテーマ

### ◎ 拠点ネットワークの更改

- 高価な閉域網だけの構成から、**閉域網＋安いインターネット回線**（または**インターネット回線2本**）の構成へ
  - 重要な業務の通信は閉域網、それ以外はインターネット回線、のように**アプリケーションで振り分け**る
  - 片方の回線が切れたら、もう片方に自動で切り替える
- 回線の品質を常に測り、品質が落ちた回線を避ける

### ○ 一元管理の利点

- 多数の拠点の設定・変更を、コントローラから一括で行える
- **ゼロタッチプロビジョニング**：拠点に機器を送り、現地の担当者はケーブルをつなぐだけ → 技術者の派遣が不要
- 記述の型：「拠点の機器を接続するだけでコントローラから設定が配信されるため、拠点に技術者を派遣する必要がないから」

### ○ 監視

- 回線ごと・トンネルごとの品質（遅延、損失、帯域）を監視する → [[ネットワーク監視]]

## 5. 覚え方

- **SD-WANは「拠点の回線をまとめて賢く使い分ける管制塔」**
- **ローカルブレイクアウトは「SaaSへは本社を経由せず近道」**：その代わり、拠点の出口のセキュリティ（SWG）を忘れない
- **ゼロタッチは「つなぐだけで設定が届く」**
- **SD-WAN＋クラウドのセキュリティ＝SASE**（Secure Access Service Edge）

## 6. 勉強の優先順位

1. ローカルブレイクアウトの目的と注意点を30〜40字で書けるようにする
2. アプリケーションごとの経路選択、複数の回線の組み合わせ
3. ゼロタッチプロビジョニング、一元管理の利点
4. SASEとの関係

> [!tip] 得点につながる覚え方
> SD-WANが出たら、**どの通信が本社経由で、どの通信が拠点から直接出るか**を構成図で色分けし、直接出る通信のセキュリティ（SWG）とプロキシの例外設定（PAC（Proxy Auto-Config））を確認する。
