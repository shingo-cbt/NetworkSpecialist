# 仮想化 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

令和4年春 午後Ⅱ 問2「仮想化技術の導入」で大問として出ている。

## 1. サーバの仮想化（○）

- **ハイパーバイザ**：1台の物理サーバの上で、**複数の仮想マシン**（VM（Virtual Machine））を動かすソフトウェア
- 利点：物理サーバの台数を減らす、VMを素早く作る・移す、障害時に別の物理サーバで動かし直す
- **仮想スイッチ**：物理サーバの中にあるソフトウェアのスイッチ。VM同士、VMと外部をつなぐ
  - VMごとにVLAN（Virtual LAN）を分ける → **物理サーバと物理スイッチの間はトランク**にする
  - 物理NIC（Network Interface Card）を複数束ねて冗長化する（チーミング）
- **コンテナ**：OS（Operating System）を共有して、アプリケーションごとに分けて動かす軽い仮想化（△）

## 2. ライブマイグレーション（◎）

- **動いているVMを止めずに、別の物理サーバへ移す**機能（保守、負荷の平準化）
- 条件：移動先でも**同じIP（Internet Protocol）アドレスのまま**使う → 移動先も**同じL2のネットワーク**（同じVLAN・同じサブネット）である必要がある
- 移動後、VMのMAC（Media Access Control）アドレスが**接続されている物理ポートが変わる** → 移動先から**GARP（Gratuitous ARP）やRARP**（Reverse ARP）を送り、**物理スイッチのMACアドレステーブルを更新**させる
- 記述の型：「VMが移動したことを物理スイッチに伝え、MACアドレステーブルを更新して、VM宛てのフレームを移動先のポートに転送させるため」
- → [[Gratuitous ARP]]

## 3. ネットワークの仮想化：VXLAN（◎）

- 拠点（データセンター）をまたいでライブマイグレーションしたい → **L2のネットワークを、L3（IP）ネットワークを越えて延ばす**必要がある
- **VXLAN（Virtual eXtensible LAN）**：**L2のフレーム（Ethernetフレーム）をUDP（User Datagram Protocol）に入れて**、IPネットワークの上で運ぶ
  - **VTEP（VXLAN Tunnel End Point）**：フレームを包む・取り出す装置（スイッチ、ハイパーバイザ）
  - **VNI（VXLAN Network Identifier）**：**24ビット**で約1,600万個 → VLAN（12ビット、約4,000個）の数の制限を超えられる
  - UDPのポート番号：**4789**
- **オーバーレイ**（VXLANで作る論理的なネットワーク）と**アンダーレイ**（それを運ぶ物理的なIPネットワーク）を分けて考える
- **MTU（Maximum Transmission Unit）が増える**：VXLANのヘッダで**約50バイト**大きくなる → アンダーレイのMTUを大きくしないと、1500バイトのフレームを運べない
- 記述の型（MTU）：「VXLANのカプセル化でヘッダが付加されるため、アンダーレイのMTUを拡張しないと最大長のフレームを転送できないから」
- 記述の型（VXLANを使う理由）：「L3ネットワークを越えて同一のL2セグメントを延伸でき、VMを同じIPアドレスのまま移動できるため」
- → [[VLAN]]

## 4. NFV（○）

- **NFV（Network Functions Virtualization）**：ルータ、FW（Firewall）、負荷分散装置などを、**専用機器ではなく汎用サーバの上のソフトウェア**（仮想アプライアンス）として動かす
- 利点：必要なときにすぐ増やせる、機器の調達が不要
- SDN（Software-Defined Networking）とは別の考え方（SDNは**制御の集中**、NFVは**機能のソフトウェア化**）だが、組み合わせて使われる → [[SDN]]

## 5. 午後で問われるテーマ

### ◎ 仮想化基盤のネットワーク設計

- 物理サーバと物理スイッチの間のトランク、VLANの割当て、NICの冗長化
- **管理用・ライブマイグレーション用・ストレージ用・VMの業務用**の通信を、VLANや物理NICで分ける（ライブマイグレーションの大量の通信が業務を圧迫しないように）

### ◎ データセンター間のライブマイグレーション

- VXLANでL2を延ばす、MTUを拡張する、移動後にスイッチのMAC表を更新する
- 移動先のデータセンターでも、**同じデフォルトゲートウェイのアドレス**で外に出られるようにする（両方のデータセンターに同じゲートウェイを置く）

### ○ リーフ・スパイン構成

- データセンターで、各リーフスイッチ（サーバをつなぐ）が**すべてのスパインスイッチ**につながる構成
- アンダーレイはL3で**ECMP**（Equal Cost Multi-Path）を使い、全経路を使う。その上にVXLANでL2を作る
- → [[ECMP]]

## 6. 覚え方

- **ハイパーバイザは「1台のビルを仕切って、多数のテナント（VM）を入れる」**
- **ライブマイグレーションは「住所（IPアドレス）を変えずに引っ越し」** → 同じL2が必要、引っ越し後にGARPで「ここに来た」と知らせる
- **VXLANは「L2の荷物をUDP（4789）の箱に入れて、L3の道路で運ぶ」**、VNIは24ビット（約1,600万）
- **VXLANは「箱の分（約50バイト）重い」→ MTUを広げる**
- **NFVは「専用機器をソフトにする」、SDNは「制御を1か所に集める」**

## 7. 勉強の優先順位

1. ライブマイグレーションの条件（同じL2）と、移動後にGARPを送る理由
2. VXLANの仕組み（UDPでカプセル化、VNI、VTEP）と、VXLANを使う理由を30〜40字で書けるようにする
3. VXLANでMTUを拡張する必要性
4. 仮想化基盤の通信の分離、トランク
5. NFVとSDNの違い、リーフ・スパイン
6. コンテナは名前を知っている程度でよい

> [!tip] 得点につながる覚え方
> 仮想化の問題では、**VMを動かすと「どのスイッチのMAC表」「どのMTU」「どのデフォルトゲートウェイ」が影響を受けるか**を追いかける。VXLANが出たら、MTUとVNIの数（VLANとの比較）は必ず確認する。
