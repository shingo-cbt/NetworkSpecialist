# クラウド接続 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

令和5年春 午後Ⅱ 問1「マルチクラウド利用による可用性の向上」のように、クラウドを使った構成の可用性・接続方法が出題される。

## 1. クラウドの基本（○）

| 種類 | 利用者が使うもの | 利用者が管理する範囲 |
|---|---|---|
| **IaaS（Infrastructure as a Service）** | 仮想サーバ、ネットワーク | OS（Operating System）から上 |
| **PaaS（Platform as a Service）** | アプリケーションの実行環境、データベース | アプリケーション |
| **SaaS（Software as a Service）** | 完成したアプリケーション（メール、Web会議など） | 設定・データ |

- **責任共有モデル**：どこまでをクラウド事業者、どこからを利用者が守るかが種類ごとに決まっている（△）

### IaaSのネットワーク（○）

- **VPC（Virtual Private Cloud）**（クラウドによって呼び名が違う）：クラウドの中に作る**自社専用の仮想ネットワーク**
  - 中を**サブネット**に分け、**ルートテーブル**で経路を決める
  - **セキュリティグループ**など：仮想サーバごとのFW（Firewall）
  - インターネットへの出口（インターネットゲートウェイ）、プライベートなサーバのための**NAT（Network Address Translation）ゲートウェイ**
- 社内とアドレスが**重ならない**ように設計する（重なると、接続したときにルーティングできない）

## 2. 社内とクラウドの接続方法（◎）

| 方法 | 内容 | 品質・安全性 | 費用・準備 |
|---|---|---|---|
| **インターネット経由**（TLS（Transport Layer Security）） | そのままインターネットで使う | 品質は保証されない | 安い・すぐ使える |
| **インターネットVPN（Virtual Private Network）**（IPsec（Security Architecture for Internet Protocol）） | クラウドのVPNゲートウェイとIPsecで接続 | 暗号化されるが、帯域・遅延は保証されない | 比較的安い・早い |
| **専用線接続**（閉域接続） | 通信事業者の閉域網・専用線で、クラウドの接続点とつなぐ | **帯域が安定、インターネットを通らない** | 高い・開通に時間がかかる |

- 経路の交換は**BGP**（Border Gateway Protocol）で行うのが一般的 → [[BGP]]

### 冗長化（◎）

- **専用線を2本**（**別の接続拠点・別の事業者**にすると、1か所の障害で両方が止まらない）
- **専用線をメイン、インターネットVPNをバックアップ**：BGPの属性（AS_PATHプリペンド、LOCAL_PREF）で専用線を優先させる
- **VPNは2本のトンネル**で張る（クラウド側も2つのエンドポイントを持つ）
- 障害を早く検知するため**BFD**（Bidirectional Forwarding Detection）を使う
- 記述の型：「専用線で受信した経路のLOCAL_PREFを大きくし、平常時は専用線を、専用線の障害時はインターネットVPNを使うため」
- → [[IPsec]]、[[ECMP]]

## 3. 午後で問われるテーマと記述の型

### ◎ マルチクラウド・可用性の向上

- 1つのクラウドの**リージョン（地域）全体の障害**に備え、別のリージョン・**別のクラウド**にもシステムを置く
- 利用者の振り分け：**DNS（Domain Name System）**（GSLB（Global Server Load Balancing））で、稼働しているクラウドのアドレスを返す → [[DNS]]、[[負荷分散装置]]
- データの同期、切替の手順、DNSのTTL（Time To Live）による切替時間が論点になる

### ◎ 名前解決（ハイブリッド環境）

- クラウドの中のサーバ名を社内から引く、社内のサーバ名をクラウドから引く → **条件付きフォワーディング**（特定のドメインの問い合わせだけを相手のDNSサーバに転送する）
- 記述の型：「社内のドメインの名前解決だけを社内のDNSサーバに転送するよう、条件付きフォワーディングを設定する」

### ○ SaaSへの通信の経路

- 全拠点の通信を本社経由でインターネットに出すと、本社の回線・プロキシが混雑する → **ローカルブレイクアウト**（SaaSへの通信だけ各拠点から直接出す）→ [[SD-WAN]]
- SaaS側で**送信元IPアドレスを制限**（社内やSWG（Secure Web Gateway）の出口からだけ許可）→ [[ゼロトラスト・SASE]]

### ○ クラウドの中のアクセス制御

- セキュリティグループで、Webサーバには443だけ、データベースにはWebサーバからだけ、のように絞る
- 管理用の接続（SSH（Secure Shell）、リモートデスクトップ）を、インターネットから直接受けない

## 4. 覚え方

- **IaaSは「土地と建物を借りる」、PaaSは「家具付き」、SaaSは「ホテル」**
- **VPCは「クラウドの中の自社専用の部屋」**：社内とアドレスを重ねない
- **接続は「インターネット → VPN → 専用線」の順に高品質・高価**
- **専用線がメイン、VPNは控え（BGPで優先度をつける）**
- **ハイブリッドの名前解決は「条件付きフォワーディング」**

## 5. 勉強の優先順位

1. 接続方法（インターネット、VPN、専用線）の違いと、冗長化の設計（BGPでの優先付け）
2. アドレスを重ねない理由、VPCの構成要素
3. マルチクラウド・リージョン障害への備え（GSLB、DNSのTTL）
4. 条件付きフォワーディング
5. ローカルブレイクアウト、SaaSの送信元IPアドレス制限
6. IaaS・PaaS・SaaS、責任共有モデルは午前で確認する程度でよい

> [!tip] 得点につながる覚え方
> クラウドの問題は、**社内とクラウドの間の「回線」「経路（BGP）」**「名前解決（DNS）」の3つで整理する。冗長化の設問では、**何が同時に止まり得るか**（同じ接続拠点、同じリージョン）を考える。
