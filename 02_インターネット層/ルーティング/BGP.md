# BGP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. BGPの基本（◎）

- **BGP（Border Gateway Protocol）**：**AS（Autonomous System：自律システム）間**の経路を交換する、**パスベクタ型**のEGP（Exterior Gateway Protocol）。インターネットを支えるプロトコル
- **TCP（Transmission Control Protocol）の179番**でピア（BGPの通信相手）とセッションを張る
  - TCPなので、相手は**手動で1つずつ設定**する（OSPF（Open Shortest Path First）のように自動では見つけない）
  - 信頼性はTCPに任せるので、最初に全経路を送った後は**変化分だけ**送る
  - キープアライブ60秒、ホールドタイム180秒（初期値。△）
  - **IPsec（Security Architecture for Internet Protocol）とのつながり**：BGPは**ユニキャスト**（TCP）で動くので、OSPFのように「IPsecはマルチキャストを運べない」問題が起きない。クラウドとのIPsec VPNで、OSPFではなくBGPを使うのが一般的なのはこのため → [[IPsec]]
- 経路と一緒に**パス属性**を送り、属性と**組織の方針**（ポリシー）で経路を選ぶ
  - 「速い経路」より「**契約・コスト・方針に沿った経路**」を選べるのがBGPの特徴
- **AS_PATH属性**：経由したAS番号の並び。**自分のAS番号が含まれる経路は受け取らない** → ASレベルのループを防ぐ
- AS番号：グローバルAS番号（インターネットで一意）と、**プライベートAS番号（64512〜65534）**
- 企業がBGPを使う場面：**複数のISP（Internet Service Provider）への接続（マルチホーム）**、**クラウドとの専用線・VPN（Virtual Private Network）接続**、広域網（閉域網）サービスとの接続

### 補足：ASとIGP・EGPの関係

- **AS**：1つの組織が、1つの方針で管理しているネットワークのまとまり（ISP、大企業、クラウド事業者など）

```
     AS 64500（A社）        AS 2500（ISP-X）         AS 16509（クラウド）
   ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
   │ 中はOSPF     │─BGP─│ 中はOSPFなど  │─BGP─│ 中は独自      │
   └─────────────┘      └─────────────┘      └─────────────┘
```

| | 使うプロトコル | 目的 |
|---|---|---|
| **ASの中** | **IGP**（OSPF、RIP（Routing Information Protocol）） | 社内で、一番速い（コストの小さい）経路を選ぶ |
| **ASとASの間** | **EGP**（＝**BGP**） | 組織どうしで、**方針（契約）に沿った**経路を選ぶ |

- たとえ：ASは「国」、IGPは「国内の道路網」、BGPは「国と国の間の外交ルート」。国境を越えるときは、どの国を通るかを条約や費用（契約）で決める

### 補足：ルーティングプロトコルの3つの型

| 型 | 経路と一緒に送るもの | 代表 |
|---|---|---|
| ディスタンスベクタ型 | **距離**（ホップ数） | RIP |
| リンクステート型 | **全体の地図**（つながり方とコスト） | OSPF |
| **パスベクタ型** | **通ってきたASの一覧**（AS_PATH）＋**属性** | **BGP** |

### 補足：OSPFとBGPの違い

| | OSPF | BGP |
|---|---|---|
| 相手の見つけ方 | Helloを**マルチキャスト**（224.0.0.5）で送り、**自動で**見つける | 相手のIPアドレスとAS番号を、**手で1つずつ設定**する |
| 信頼性 | OSPF自身で確認応答・再送 | **TCPに任せる** |
| 経路の送り方 | 変化があると、地図の差分を広める | 最初に**全経路**、あとは**変化分だけ** |
| 生存確認 | Hello（10秒） | **キープアライブ**（60秒）。**ホールドタイム**（180秒）の間何も届かなければ、相手が落ちたと判断 |

- 相手を手で設定する理由：BGPは**組織と組織の間**の取り決めで、誰と経路を交換するかは契約で決まっている。知らない相手と勝手に経路を交換するのは危険
- キープアライブは、令和3年 午後Ⅱの採点講評で「BGPに関する基本的な用語として知っておいてほしい」と書かれた

### 補足：方針で選ぶ例、AS_PATHのループ防止

- 例：A社が、ISP-X（高いが速い回線）とISP-Y（安い回線）の両方と契約している
  - OSPFなら、コストの小さい経路を自動で選ぶだけ
  - BGPなら、「**ふだんはISP-Xを使い、ISP-Xが落ちたらISP-Yを使う**」のように会社の方針どおりに選ばせられる → ポリシーベースのルーティング

```
AS 100 → AS 200 → AS 300 → （AS 100 に戻ってきた）
                            AS_PATH：300 200 100
                                          ↑ 自分の番号がある → 捨てる
```

- **プライベートAS番号**（64512〜65534）は、**クラウドや閉域網とのBGP**など、インターネットに広告しない場面で使う（例：社内側を65001、クラウド側は事業者が指定）。午後の構成図に「AS 65001」などがあれば、プライベートAS番号

### 補足：企業がBGPを使う場面と過去の出題

| 場面 | 何をするか | 過去の出題 |
|---|---|---|
| **マルチホーム** | 2つのISP（2回線）とつなぎ、**行き・帰りの経路を制御**し、片方が落ちたら切り替える | 令和3年 午後Ⅱ 問2 |
| **クラウドとの接続** | 専用線やIPsec VPNを**2本**張り、BGPで経路を交換して冗長化する | 令和5年 午後Ⅱ 問1 |
| 閉域網（IP-VPN）との接続 | 通信事業者の網と、拠点の経路を交換する | − |
| CDN（Content Delivery Network）・データセンタ | 複数の拠点から、同じアドレスを広告する | 令和6年 午後Ⅰ 問1 |

- 令和6年 午後Ⅰ 問1の採点講評：「BGPの基本を正しく理解していないと思われる解答が多かった」「BGPで受け取った経路がどのトラフィックに影響するか正しく理解してほしい」（**通信の向きを逆に答えた誤答が多かった**）→ 3章の「影響する方向」が重要
- 覚え方：**「ASは国、BGPは外交。速さより条約（方針）で道を選ぶ」「BGPはTCP 179で、相手は手で決める。ユニキャストなのでIPsecに乗る」「AS_PATHに自分がいたら捨てる」**

## 2. eBGPとiBGP（○）

| | eBGP（External BGP） | iBGP（Internal BGP） |
|---|---|---|
| ピアの相手 | **別のAS**のルータ | **同じAS**のルータ |
| 主な用途 | ISP、クラウド、他社との経路交換 | AS内の複数の境界ルータで、外部から受けた経路を共有 |

- iBGPで受けた経路は、別のiBGPピアに**転送しない**（ループ防止）→ AS内のiBGPルータは**フルメッシュ**でピアを張る必要がある
  - 台数が多いと大変 → **ルートリフレクタ**が経路を中継する（△）
- eBGPで受けた経路の**ネクストホップ**は、iBGPで渡しても**変わらない**（相手ASのルータのまま）→ AS内でそのアドレスに届く経路が必要（△）

```
            A社（AS 65001）                     ISP-X（AS 2500）
   ┌──────────────────────────────┐
   │  ルータR1 ═══ iBGP ═══ ルータR2 │──── eBGP ──── ISP-Xのルータ
   │     │                          │
   │     └──────── eBGP ────────────│──── ISP-Yのルータ（AS 2600）
   └──────────────────────────────┘
```

- **なぜiBGPが必要か**：R1とR2がそれぞれ別のISPから経路を受け取る。お互いの経路を知らないと「どちらの出口が良いか」を比べられないので、iBGPで共有する。3章のLOCAL_PREFも、このiBGPで共有される
- **iBGPの経路を別のiBGPピアに渡さない理由**：AS_PATHはASを出るときに番号が追加されるので、**AS内では番号が増えず、AS_PATHによるループ防止が効かない**。そのため「iBGPで受けた経路はiBGPに流さない」決まりでループを防ぐ
  - その結果、AS内のBGPルータは全員と直接ピアを張る（フルメッシュ）。n台なら **n(n−1)/2本**のピアが必要

```
R1 ── R2      全員と直接つながっていないと、
 │  ╲ │       R1の経路が、R2経由でR3に届かない
R3 ── R4
```

- **ネクストホップの例**

```
ISP-Xのルータ（198.51.100.1）── eBGP ── R1 ── iBGP ── R2
  R1が受けた経路：ネクストホップ 198.51.100.1
  R2に渡した経路：ネクストホップ 198.51.100.1（R1のアドレスにはならない）
  → R2が 198.51.100.1 への行き方を知らないと、この経路を使えない
```

  - 対策①：**next-hop-self**：R1がiBGPで渡すとき、ネクストホップを**自分のアドレスに書き換える**（令和5年 午後Ⅱ 問1で出題）
  - 対策②：AS内のIGP（OSPFなど）で、198.51.100.1 への経路も広告する
- 覚え方：**「eBGPは外交、iBGPは社内の情報共有」「iBGPの経路は又貸ししない → 全員と直接（フルメッシュ）」「ネクストホップは相手のまま。困るならnext-hop-self（自分に書き換え）」**

## 3. 主なパス属性と経路選択（◎）

| 属性 | 意味 | 優先 | 影響する方向 | 出題度 |
|---|---|---|---|---|
| **LOCAL_PREF**（ローカルプリファレンス） | **自AS内**で、どの出口を使うか | **大きい方** | **自ASから出ていく通信（アウトバウンド）** | ◎ |
| **AS_PATH** | 経由するASの並び | **短い方** | 相手が自ASを選ぶか（**入ってくる通信（インバウンド）**） | ◎ |
| **MED**（Multi-Exit Discriminator） | 隣のASに「こちらの入口を使って」と伝える | **小さい方** | **入ってくる通信** | ○ |
| ORIGIN | 経路の出どころ（IGP（Interior Gateway Protocol）、EGP、不明） | IGP ＞ EGP ＞ 不明 | − | △ |
| NEXT_HOP | 次の転送先 | − | − | △ |

- **経路選択の主な順番**（ネスペで押さえる範囲）
  1. （Cisco社の機器ではWeightが最初。△）
  2. **LOCAL_PREFが大きい**
  3. **AS_PATHが短い**
  4. ORIGINが優先度の高いもの
  5. **MEDが小さい**
  6. iBGPよりeBGPで受けた経路
  7. IGPでネクストホップまでのコストが小さい ……
- **LOCAL_PREFはAS内（iBGP）だけで共有**され、隣のASには伝わらない
- **MEDは隣のASにだけ伝わり**、その先のASには伝わらない

### 補足：大原則「経路の流れと、通信の流れは逆」（◎）

```
         経路の広告（「203.0.113.0/24はこっちだよ」）
   A社  ──────────────────────────→  ISP
   A社  ←──────────────────────────  ISP
         通信（203.0.113.0/24 宛てのパケット）
```

| 自分がすること | 影響する通信 |
|---|---|
| **受け取った経路**に、優先度を付ける | **自分から出ていく通信**（アウトバウンド） |
| **広告する経路**に、細工をする | **相手から入ってくる通信**（インバウンド） |

- たとえ：道案内の看板。自分が**看板を見て**道を選ぶ → 自分が出かけるときの道が決まる。自分が**看板を出す** → 相手が自分のところに来るときの道に影響する
- 令和6年 午後Ⅰ 問1の採点講評で「向きを逆に答えた誤答が多かった」と指摘された点

### 補足：例「A社が2つのISPとつながっている」

```
                    ┌── R1 ── ISP-X（AS 2500）──┐
A社（AS 65001）─────┤                           ├── インターネット
                    └── R2 ── ISP-Y（AS 2600）──┘
方針：ふだんは、行きも帰りもISP-Xを使いたい。ISP-Yは予備
```

- **行き（A社 → インターネット）：LOCAL_PREF**
  - A社のルータが、**ISPから受け取った経路**に点数を付ける（ISP-Xから受けた経路：200、ISP-Yから受けた経路：100）→ **大きい方が優先**なので、出ていく通信はISP-X（R1）を通る
  - LOCAL_PREFは**iBGPでA社の中だけで共有**される（R1とR2で同じ判断をするため）。自社の方針なので、ほかのASには伝わらない
- **帰り（インターネット → A社）：AS_PATH**
  - 帰りの通信の道を選ぶのは**相手側**。A社は直接は決められないので、**広告する経路**に細工して仕向ける
  - ISP-Y側へ広告する経路のAS_PATHに、**自分のAS番号を何回も足す**（**AS_PATHプリペンド**）→ 相手は短い方を選ぶので、ISP-X経由で入ってくる

```
ISP-X経由で届く経路：AS_PATH  2500 65001                ← 短い
ISP-Y経由で届く経路：AS_PATH  2600 65001 65001 65001    ← わざと長くした
```

- **帰りの補足：MED**
  - **同じ隣のAS**と**2か所以上でつながっている**とき、「こちらの入口を使って」と伝える値（例：ISP-Xと東京・大阪の2か所でつながっている → 東京側のMEDを小さくして広告する）
  - **小さい方が優先**。**隣のASにだけ**伝わる。違うISPの間で比べるときは、ふつうAS_PATHを使う

| 属性 | 誰が決める・どこで使う | 優先 | 影響する通信 | 伝わる範囲 |
|---|---|---|---|---|
| **LOCAL_PREF** | 自分が、**受け取った経路**に付ける | **大きい方** | **出ていく通信**（行き） | **自分のASの中だけ** |
| **AS_PATH**（プリペンド） | 自分が、**広告する経路**に細工する | **短い方** | **入ってくる通信**（帰り） | インターネット全体 |
| **MED** | 自分が、**広告する経路**に付ける | **小さい方** | **入ってくる通信**（帰り） | **隣のASだけ** |

- 優先の向き（[[STP]]・[[VRRP]]・[[OSPF]]のプライオリティの向きと同じ考え方）：LOCAL_PREFは「好み（点数）」→ 大きいほど優先。AS_PATHは「距離（経由するASの数）」→ 短いほど優先。MEDは「メトリック（距離）」→ 小さいほど優先
- 経路選択の順番で**LOCAL_PREFがAS_PATHより先**：「自分の会社の方針」が「相手がどれだけ近いか」より優先される → 速さより方針のプロトコル

### 補足：午後の典型的な問われ方

| 問われ方 | 答え |
|---|---|
| 「社内からインターネットへの通信を、ISP-X経由にしたい」 | ISP-Xから受け取る経路の**LOCAL_PREFを大きく**する |
| 「インターネットから社内への通信を、ISP-X経由にしたい」 | ISP-Yへ広告する経路の**AS_PATHを長く**する（プリペンド） |
| 「LOCAL_PREFを変えても、入ってくる通信が変わらないのはなぜか」 | LOCAL_PREFは**自ASの中だけ**の値で、相手には伝わらず、**出ていく通信**にしか影響しないから |

- 記述の型：「LOCAL_PREFは自AS内でだけ使われ、自ASから出ていく通信の経路選択にしか影響しないから」
- 覚え方：**「経路と通信は逆向き。受け取る経路で行きを、広告する経路で帰りを決める」「行きはLOCAL_PREF（大きい方）、帰りはAS_PATH（短い方）とMED（小さい方）」「LOCAL_PREFは社内の方針なので、外には漏れない」**

## 4. 午後で問われるテーマと記述の型

### ◎ 2つのISP（または2回線）への接続：通信の向きごとの制御

- **出ていく通信（自社 → インターネット）**：自社の境界ルータで、メインのISPから受けた経路の**LOCAL_PREFを大きく**する
  - 記述の型：「ISP-Aから受信した経路のLOCAL_PREFをISP-Bより大きく設定し、送信をISP-A経由にする」
- **入ってくる通信（インターネット → 自社）**：相手（他AS）の経路選択は直接変えられないので、**広告する経路の属性で誘導**する
  - バックアップ側のISPへ広告する経路の**AS_PATHに自AS番号を繰り返し追加する（AS_PATHプリペンド）** → 長く見えるので選ばれにくい
  - 同じISPに2回線で接続しているなら**MED**で入口を指定できる
  - **より詳しい経路**（長いプレフィックス）をメイン側にだけ広告する → ロンゲストマッチでメインが選ばれる
  - 記述の型：「ISP-Bに広告する経路のAS_PATHに自AS番号を追加して長くし、受信をISP-A経由にする」
- 「LOCAL_PREFは出ていく方向、AS_PATH・MEDは入ってくる方向」の区別が最頻出

### ◎ クラウドとの接続（専用線・VPN）

- クラウドの専用線接続やVPN接続では、**BGPで経路を交換する**のが一般的
  - 社内の経路をクラウド側へ広告し、クラウドのネットワーク（VPC（Virtual Private Cloud）など）の経路を受け取る
- **専用線をメイン、インターネットVPNをバックアップ**にする：専用線側の経路を優先させる（LOCAL_PREF、AS_PATHプリペンド）
- **BFD**（Bidirectional Forwarding Detection）で障害を素早く検知して切り替える
- クラウドを使った可用性の設計（専用線とVPNの二重化、複数クラウドの利用）の問題で出やすい

### ○ 受け取る経路の量

- **フルルート**（インターネットの全経路、約100万経路）：最適な出口を選べるが、ルータに大きなメモリが必要
- **デフォルトルートだけ**：ルータの負荷は小さいが、出口の細かい選択はできない
- 問われ方：「ISPからデフォルトルートだけを受け取る理由」

### ○ 社内（IGP）との連携

- BGPで受けた経路を社内のOSPFに**再配布**する、または境界ルータからOSPFで**デフォルトルートだけ**を配る
- 全経路をOSPFに入れると、社内のルータに負荷がかかる
- → [[再配布]]、[[OSPF]]

### △ セキュリティ：経路ハイジャック

- **攻撃者の観点**：他人のアドレスを自分のASから広告する（より詳しいプレフィックスにするとロンゲストマッチで勝つ）→ 通信を横取り・盗聴・破棄できる
- **防御側の対策**：ISPが顧客から受ける経路を**フィルタ**する、**RPKI**（Resource Public Key Infrastructure）で「このアドレスを広告してよいAS」を検証する、ピアとの間に**TCP MD5（Message Digest 5）認証**などを設定する

## 5. 覚え方

- **BGPは「国（AS）同士の外交」**：速さより方針。相手は手動で決める（TCP 179で電話をかける）
- **AS_PATHは「通ってきた国のスタンプ」**：自分の国のスタンプがあればループなので捨てる
- **LOCAL_PREFは「社内向けの指示：どの出口から出るか」（大きいほど優先）**
- **AS_PATHプリペンドは「わざと遠回りに見せる」**：自分のAS番号を水増しして、入ってくる通信を避けさせる
- **MEDは「お隣さんへのお願い：この玄関から来て」（小さいほど優先）**
- **出るはLOCAL_PREF、入るはAS_PATH・MED**
- **iBGPはフルメッシュ**：社内の経路は又聞きさせない

## 6. 勉強の優先順位

1. 2つのISP・回線への接続で、出ていく通信（LOCAL_PREF）と入ってくる通信（AS_PATHプリペンド、MED）の制御を30〜40字で書けるようにする
2. BGPの基本（TCP 179、AS、パスベクタ、AS_PATHによるループ防止）
3. 経路選択の順番（LOCAL_PREF → AS_PATH → ORIGIN → MED）
4. クラウド接続での利用、BFDによる切替
5. eBGPとiBGP、フルメッシュ
6. フルルートとデフォルトルート、再配布
7. ルートリフレクタ、経路ハイジャック、RPKIは名前と目的を知っている程度でよい

> [!tip] 得点につながる覚え方
> BGPは「**どちらの向きの通信を、どちらの回線に寄せたいか**」で使う属性が決まる。午後で設問を読んだら、まず**出ていく通信か、入ってくる通信か**に印を付け、出るならLOCAL_PREF、入るならAS_PATHプリペンド（またはMED、詳しい経路の広告）と対応させる。
