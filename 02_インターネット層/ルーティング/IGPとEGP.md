# IGPとEGP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

ルーティングの共通知識（経路の選び方）もこのファイルにまとめる。各プロトコルの詳細は [[RIP]]、[[OSPF]]、[[BGP]]、[[スタティックルーティング]]、[[再配布]] を参照。

## 1. ASとIGP／EGP（○）

- **AS（Autonomous System：自律システム）**：1つの組織（ISP（Internet Service Provider）、大企業など）が**同じ方針で管理するネットワークのまとまり**。AS番号で識別する
- **IGP（Interior Gateway Protocol）**：**AS内**で使うルーティングプロトコル
- **EGP（Exterior Gateway Protocol）**：**AS間**で使うルーティングプロトコル。現在は実質 **BGP（Border Gateway Protocol）** だけ

| 分類 | 方式 | 代表 | 経路の選び方 |
|---|---|---|---|
| IGP | **ディスタンスベクタ型** | **RIP（Routing Information Protocol）** | **ホップ数**（経由するルータの数）が少ない経路 |
| IGP | **リンクステート型** | **OSPF（Open Shortest Path First）**、IS-IS | **コスト**（帯域から計算）の合計が小さい経路 |
| EGP | **パスベクタ型** | **BGP** | **パス属性**（経由するASの並び、優先度など）と**運用方針（ポリシー）** |

- **ディスタンスベクタ型**：隣のルータから「宛先までの距離と方向」を教えてもらう。ネットワーク全体の形は知らない（うわさで道を知る）
- **リンクステート型**：全ルータが**リンクの状態を交換してネットワーク全体の地図**を作り、各自で最短経路を計算する
- **パスベクタ型**：宛先までに**経由するASの一覧**を交換する。ループの検出と、方針に基づく経路選択ができる
- IGPは「**速く・最適に**」、EGPは「**組織の方針どおりに・大規模に**」が目的
- 午前の定番：「リンクステート型のプロトコルはどれか」→ OSPF。「AS間で使うプロトコル」→ BGP

## 2. ルーティングテーブルと経路選択の共通ルール（◎）

### ① ロンゲストマッチ（最長一致）

- 宛先IP（Internet Protocol）アドレスに一致する経路が複数あるとき、**プレフィックス長が最も長い（最も詳しい）経路**を使う
- 例：宛先 10.1.1.5 に対して `10.0.0.0/8`、`10.1.0.0/16`、`10.1.1.0/24` があれば **/24** を使う
- **デフォルトルート**（0.0.0.0/0）は最も短いので、ほかに一致する経路がないときだけ使われる
- この性質を使い、**詳しい経路を一時的に広告して通信を引き寄せる**、**詳しい経路が消えたら集約経路で迂回する**といった設計ができる

### ② アドミニストレーティブディスタンス（経路の信頼度）

- **同じ宛先・同じプレフィックス長**の経路を、**異なるプロトコル**から受け取ったときの優先順位。**小さい方が優先**
- 代表値（Cisco社の機器の例。値はメーカーにより異なる）

| 経路の種類 | 値 |
|---|---|
| 直接接続 | 0 |
| スタティック | 1 |
| eBGP（External BGP） | 20 |
| OSPF | 110 |
| RIP | 120 |
| iBGP（Internal BGP） | 200 |

- **フローティングスタティック**：スタティック経路の値を、動的な経路より**大きく**設定してバックアップにする → [[スタティックルーティング]]

### ③ メトリック（同じプロトコル内での比較）

- 同じプロトコルの中では、**メトリック（RIPはホップ数、OSPFはコスト）が小さい経路**を選ぶ
- メトリックが同じ経路が複数あれば、**ECMP**（Equal Cost Multi-Path：等コストマルチパス）で負荷分散できる

### 判定の順番（◎）

1. **プレフィックス長**が最も長い経路
2. 同じ長さなら、**アドミニストレーティブディスタンス**が小さいプロトコルの経路
3. 同じプロトコルなら、**メトリック**が小さい経路
4. メトリックも同じなら、ECMPで分散（または1つを選ぶ）

- 問われ方：「ルータXがこの宛先へのパケットを転送する次ホップ」「障害後に選ばれる経路」

## 3. 経路集約（○）

- 複数の経路を1つにまとめて広告する（例：`192.168.0.0/24`〜`192.168.3.0/24` → `192.168.0.0/22`）
- 利点：**ルーティングテーブルが小さくなる**、**一部の経路が変化しても集約先の外に影響しない**（不安定さを閉じ込める）
- 注意：集約経路に含まれるが実際には存在しないアドレス宛てのパケットも引き寄せてしまう → 集約したルータで**Null0（破棄）への経路**を持たせてループを防ぐ（△）
- 計算問題：複数のネットワークを集約したときのプレフィックス長を求める

## 4. 収束（○）

- **収束**：障害などでネットワークが変化した後、全ルータの経路が一致して安定するまでの状態・時間
- 収束するまでの間は、パケットが失われる、ループする
- 速さ：**OSPF（変化をすぐに知らせる）＞ RIP（定期的な更新を待つ）**
- 高速化：**BFD**（Bidirectional Forwarding Detection）で障害を数百ms以内に検知し、ルーティングプロトコルに知らせる（○）

## 5. 午後で問われるテーマと記述の型

### ◎ 経路の判定

- 構成図とルーティングテーブルから、**どの経路が使われるか**を2章の順番で判定する
- 障害時に「次に選ばれる経路」も同じ手順
- 記述の型：「宛先に対してプレフィックス長がより長い経路が優先されるから」

### ◎ IGPとEGPの使い分け

- 社内：OSPF（またはスタティック）
- ISPやクラウドとの接続：**BGP**（複数のISP、クラウドの専用線接続）
- 社内とBGPの境界では、経路を**再配布**するか、デフォルトルートで済ませる → [[再配布]]

### ○ スタティックか動的か

- 小規模で経路が変わらない → スタティック（設定が単純、ルータの負荷が小さい）
- 冗長な経路があり、自動で切り替えたい → 動的（OSPF、BGP）
- 記述の型：「障害時に経路を自動で切り替えるため、動的ルーティングを用いる」

## 6. 覚え方

- **IGPは「社内の道案内」、EGPは「国境（AS）をまたぐ道案内」**
- **ディスタンスベクタは「うわさで道を知る」、リンクステートは「全員が同じ地図を持つ」、パスベクタは「通る国の一覧を持つ」**
- **経路の選び方は「長さ → 信頼度 → 距離」**：プレフィックス長 → アドミニストレーティブディスタンス → メトリック
- **信頼度は「直接0、スタティック1、eBGP20、OSPF110、RIP120」**

## 7. 勉強の優先順位

1. 経路の判定の順番（ロンゲストマッチ → アドミニストレーティブディスタンス → メトリック）を使いこなせるようにする
2. ディスタンスベクタ／リンクステート／パスベクタの違い
3. 経路集約の計算
4. IGPとEGPの使い分け
5. 収束とBFDは概要を押さえればよい

> [!tip] 得点につながる覚え方
> 午後のルーティング問題は、プロトコルの細部より「**このパケットはどこを通るか」「障害時にどう切り替わるか」を構成図の上で追えるか**が問われる。まずロンゲストマッチ、次に信頼度、最後にメトリック、の順で機械的に判定する。
