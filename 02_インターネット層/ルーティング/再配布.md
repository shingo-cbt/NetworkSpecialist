# 再配布 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. 再配布の基本（○）

- **再配布（ルート再配送）**：あるルーティングプロトコル（またはスタティック経路、直接接続）で得た経路を、**別のルーティングプロトコルに取り込んで広告する**こと
- 必要になる場面
  - **スタティック経路**（インターネット向けのデフォルトルートなど）を**OSPF**（Open Shortest Path First）で社内に広める
  - **BGP**（Border Gateway Protocol）で受けたクラウド・他拠点の経路を社内のOSPFに入れる（逆に社内の経路をBGPで広告する）
  - **RIP（Routing Information Protocol）からOSPFへの移行中**に両方を共存させる
  - 会社の合併などで、別々のプロトコルを使うネットワークをつなぐ
- 再配布は、両方のプロトコルが動いている**境界のルータ**で設定する（OSPFではこのルータが**ASBR**（AS Boundary Router）になる）

## 2. メトリックの扱い（◎）

- プロトコルごとにメトリックの意味が違う（RIPはホップ数、OSPFはコスト、BGPは属性）→ **そのままでは比較できない**
- 再配布するときに、取り込む側のプロトコルでの**メトリックを設定**する（シードメトリック）
  - 設定しないと、プロトコルによっては無限大（到達不能）扱いになり、経路が広まらない（RIPへの再配布など。△）
- OSPFに再配布した経路は**外部経路**になる
  - **E2（初期値）**：外部で付けたコストだけを使う。OSPF内の距離は足さない
  - **E1**：外部のコストに、OSPF内のコストも足す → 出口が複数あるとき、近い出口を選ばせたいならE1（△）

## 3. 再配布の問題点（◎）

### ルーティングループ・最適でない経路

- **2か所以上の境界ルータで、双方向に再配布**すると起きやすい
  - A→Bに再配布した経路が、別の境界ルータでB→Aに戻される
  - 戻ってきた経路のほうがアドミニストレーティブディスタンス（AD：Administrative Distance）が小さいなどの理由で選ばれ、**遠回りやループ**になる
- **具体的な流れ**（OSPF（本社）とRIP（支社 10.20.0.0/16）を、境界ルータR1・R2の2台で双方向に再配布する例）

```
       OSPFの世界（本社）
     ┌───────────────┐
     │   R1       R2   │    ← R1・R2 で、OSPF ⇔ RIP を双方向に再配布
     └──┼────────┼──┘
     ┌──┼────────┼──┐
     │  RIPの世界（支社） │
     │  10.20.0.0/16   │
     └───────────────┘

① 支社（RIP）の 10.20.0.0/16 を、R1 と R2 が、それぞれRIPで受け取る
② R1 が、10.20.0.0/16 をOSPFに再配布する → 本社のOSPFに広がる
③ R2 は、10.20.0.0/16 を2か所から知ることになる
     ・RIPから（直接、支社から）       AD 120
     ・OSPFから（R1が再配布したもの）  AD 110 ← ADが小さいので、こちらを選ぶ
④ R2 は、支社が目の前にあるのに、10.20.0.0/16 宛ての通信を、OSPFで R1 の方へ送る（遠回り）
⑤ さらに R2 が、OSPFで覚えた 10.20.0.0/16 を、RIPに再配布し直す
   → 支社の中に「R2 の方にも 10.20.0.0/16 がある」という誤った経路が流れ、ループする
```

  - 核心は③：**OSPF（110）の方がRIP（120）よりAD（Active Directory）が小さい**ので、R2は「R1が再配布して戻ってきた経路」を選んでしまう → [[IGPとEGP]]
  - 記述の型（流れを問われたとき）：「R1がOSPFに再配布した支社の経路を、R2がADの小さいOSPFから学習して選び、さらにRIPへ再配布し直すため、経路が一周してループする」
- 対策
  - **ルートフィルタ**：相手側から来た経路は、相手側に戻さない
  - **ルートタグ**：再配布するときに目印（タグ）を付け、そのタグの経路は再配布しない
  - アドミニストレーティブディスタンスを調整する
  - 再配布は**一方向だけ**にする、またはデフォルトルートで済ませる
- 記述の型：「再配布した経路が他方の境界ルータで元のプロトコルに再び再配布され、ルーティングループが発生するから」

### 経路の数・不安定さ

- BGPのフルルートなどをOSPFに全部入れると、社内のルータのメモリ・CPU（Central Processing Unit）に負荷がかかる
- 外部の変化が社内全体に広がる
- 対策：**必要な経路だけに絞る**（フィルタ）、**集約してから再配布**、**デフォルトルートだけ**配る

## 4. 午後で問われるテーマと記述の型

### ◎ インターネット接続のデフォルトルートを社内に配る

- 出口のルータにスタティックのデフォルトルートを設定し、それを**OSPFに再配布**（またはOSPFのデフォルトルート広告機能を使う）
- 出口が2つある場合、**外部経路のコスト**を変えて、メインの出口を優先させる
- 出口の回線が切れたら、その出口からのデフォルトルートの広告をやめる（スタティック経路をトラッキングで無効にする）→ もう一方の出口に切り替わる
- → [[スタティックルーティング]]

### ◎ クラウド・拠点とのBGPと社内OSPFの連携

- クラウド側のネットワークの経路を、境界ルータでBGP → OSPFに再配布する
- 社内の経路は、OSPF → BGPに再配布して（必要な範囲だけ）クラウドへ広告する
- 双方向・複数の境界ルータになるので、**ループ対策**（フィルタ、タグ）とセットで問われる
- → [[BGP]]、[[OSPF]]

### ○ RIPからOSPFへの段階的な移行

- 移行期間中は、境界のルータでRIPとOSPFを相互に再配布する
- 移行が終わったらRIPと再配布の設定を削除する
- → [[RIP]]

## 5. 覚え方

- **再配布は「通訳」**：言葉（プロトコル）が違うネットワークの間で、経路を言い直して伝える
- **メトリックは「通貨の両替」**：ホップ数とコストは直接比べられない。再配布するときに値を決め直す
- **2か所で双方向の再配布は「伝言ゲームが一周して戻ってくる」** → タグとフィルタで、戻ってきた話は無視する
- **OSPFに入れた経路は「外部（E2が初期値）」、入れたルータはASBR**

## 6. 勉強の優先順位

1. 複数の境界ルータで双方向に再配布するとループする理由と、フィルタ・タグによる対策を30〜40字で書けるようにする
2. デフォルトルートをOSPFで社内に配り、障害時に出口を切り替える設計
3. BGPとOSPFの再配布（クラウド接続）
4. メトリックの設定、E1とE2の違い
5. 経路を絞る理由（ルータの負荷、外部の不安定さ）

> [!tip] 得点につながる覚え方
> 再配布は**複数のプロトコルが混在する構成図**で必ず関わる。境界ルータを見つけたら、**どの経路が、どの向きに再配布されるか**を矢印で書き込み、矢印が一周していないか（ループしないか）を確認する。
