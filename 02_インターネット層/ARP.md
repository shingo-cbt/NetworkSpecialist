# ARP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

ARPそのものが大問の中心になることはほとんどない。ただし、**VRRP（Virtual Router Redundancy Protocol）の切替、LB（Load Balancer、負荷分散装置）のDSR（Direct Server Return）、ARPスプーフィング**など、多くの午後問題の「前提の知識」として使う。

## 1. ARPの基本（◎）

- **ARP**（Address Resolution Protocol）：**IP（Internet Protocol）アドレスから、MAC（Media Access Control）アドレスを調べる**プロトコル
- 流れ
  1. **ARP要求**：「このIPアドレスを持っている人は、MACアドレスを教えて」を**ブロードキャスト**（宛先MAC FF-FF-FF-FF-FF-FF）で送る
  2. **ARP応答**：該当する機器だけが、自分のMACアドレスを**ユニキャスト**で返す
  3. 結果を**ARPテーブル**（ARPキャッシュ）に保存する。動的に学習した行には**有効期限**があり、しばらく使わないと消える
- **ARPはルータを超えない**：ルータはブロードキャストを転送しない → ARPが届くのは**同じセグメント（ブロードキャストドメイン）の中だけ**
- IPv6では、ARPの代わりに**NDP**（Neighbor Discovery Protocol）の近隣要請・近隣広告（ICMPv6（Internet Control Message Protocol for IPv6））を使う → [[IPv6アドレス・NDP]]

## 2. 区間ごとの転送：誰が誰をARPするか（◎）

例：PC1 → L2SW（Layer 2 Switch）→ R1（PC1のデフォルトゲートウェイ）→ R2 → PC2（宛先）

```
PC1 ──L2SW── R1 ──────── R2 ──────── PC2
  [区間1]         [区間2]       [区間3]
 PC1がR1をARP   R1がR2をARP   R2がPC2をARP
```

| 区間 | ARPをする機器 | 調べる相手 | 宛先IP | 宛先MAC |
|---|---|---|---|---|
| 1 | PC1 | **R1**（デフォルトゲートウェイ） | PC2 | R1 |
| 2 | R1 | R2（経路表のネクストホップ） | PC2 | R2 |
| 3 | R2 | PC2（直接つながっている） | PC2 | PC2 |

- PC1は、宛先PC2のIPアドレスを**自分のサブネットマスク**と比べ、別のネットワークだと判断する → **デフォルトゲートウェイ（R1）に渡す** → **R1のIPアドレスをARP**する
  - PC1は**PC2やR2をARPしない**（別のネットワークなので、そもそも届かないし、調べる必要もない）
- **IPアドレスは端から端まで変わらない**（NAT（Network Address Translation）しない限り）。**MACアドレスは区間ごとに付け替わる**
- このとき、PC1のARPテーブルには「**R1のIPアドレス → R1のMACアドレス**」の行だけができる。PC2の行はできない
- 記述の型（PCがARPで調べる相手）：「デフォルトゲートウェイのIPアドレスに対応するMACアドレス」

## 3. 3つのテーブルの違い（◎）

| テーブル | 中身 | 持っている機器 | 使い道 |
|---|---|---|---|
| **経路表**（ルーティングテーブル） | 宛先ネットワーク → **ネクストホップのIPアドレス**、出力インタフェース | PC、サーバ、ルータ、L3SW（Layer 3 Switch） | **誰に渡すか**を決める |
| **ARPテーブル** | **IPアドレス → MACアドレス** | PC、サーバ、ルータ、L3SW | ネクストホップのMACアドレスを引く |
| **MACアドレステーブル** | **MACアドレス → ポート** | L2SW、L3SW | フレームを**どのポートから出すか**決める |

- PCが「PC2宛てはR1に渡す」と決めるのは**経路表**（デフォルトルート 0.0.0.0/0 → R1）。ARPテーブルは、そのR1のMACアドレスを引くだけ
- **L2SWは転送にARPテーブルを使わない**。宛先MACアドレスとMACアドレステーブルだけで転送する
  - MACアドレステーブルは、受信したフレームの**送信元MACアドレス**から学習する。宛先が未学習なら**フラッディング**する → [[VLAN]]
  - 例外：管理用のIPアドレスを持つL2SWは、自分の通信（SNMP（Simple Network Management Protocol）、SSH（Secure Shell）、Syslog）のためにARPテーブルを持つ。通過するフレームの転送には使わない
- 似た名前に注意：**DHCP（Dynamic Host Configuration Protocol）スヌーピングのバインディングテーブル**（IP、MAC、ポート、VLAN（Virtual LAN））はL2SWが持つが、ARPテーブルではない → [[DHCP]]

## 4. 午後で問われるテーマと記述の型

### ◎ VRRPの切替とARP

- PCのARPテーブルには「**仮想IPアドレス → 仮想MACアドレス**（00-00-5E-00-01-VRID）」の行ができる
- マスタが切り替わっても仮想MACアドレスは変わらない → **PCのARPテーブルは書き換えなくてよい**
- 新しいマスタが送る**GARP**（Gratuitous ARP）で更新されるのは、**L2SWのMACアドレステーブル**（仮想MACアドレスの出口のポート）→ [[Gratuitous ARP]]、[[VRRP]]
- VRRPが**同じセグメントでしか組めない**のも、ARPとVRRPの広告がセグメントを超えないため

### ◎ LBのDSR方式とARP

- DSRでは、サーバのループバックインタフェースにVIP（Virtual IP、仮想IPアドレス）を付ける → サーバがVIPのARPに応答すると、LBと**アドレスが重複**する（GARPで検知される）
- 記述の型：「VIPアドレスに対するARPリクエストに応答しないように設定する」→ [[負荷分散装置]]

### ○ 機器の交換とARPのキャッシュ

- ルータやサーバを**同じIPアドレスのまま別の機器に交換**すると、MACアドレスが変わる → 周りの機器のARPテーブルに古いMACアドレスが残り、**有効期限が切れるまで通信できない**
- 対策：交換した機器から**GARPを送る**、周りの機器のARPキャッシュを消す

### △ プロキシARP

- ルータが、**別のネットワークにいる相手の代わりに、自分のMACアドレスでARPに応答する**機能
- 使われる場面：PCのサブネットマスクを間違えるなどして、PCが別のネットワークの相手を同じセグメントだと思い込み、直接ARPをしたとき → ルータが代理で応答し、通信できてしまう
- ARPそのものはルータを超えていない（ルータが代わりに答えているだけ）
- 問題点：設定の誤りが表に出ず、原因の切り分けが難しくなる。不要なら無効にする

## 5. 攻撃者の観点：どこを突くか

| 狙う所 | 攻撃のしかた | 成り立つ条件 |
|---|---|---|
| **ARPに認証がない** | **ARPスプーフィング**（ARPポイズニング）：偽のARP応答やGARPで「デフォルトゲートウェイのIPアドレスは自分のMACアドレス」と思い込ませる → 通信を自分経由にして盗聴・改ざん（中間者攻撃） | 攻撃者が**同じセグメント**にいる |
| ARP要求はブロードキャスト | 大量のARPを流して、機器やネットワークに負荷をかける | 同じセグメントにいる |
| L2SWのMACアドレステーブル | 偽の送信元MACアドレスを大量に送ってテーブルをあふれさせる（MACフラッディング）→ フラッディングされたフレームを盗聴する | ポートの台数制限がない |

- ARPの攻撃は**同じセグメントの中**でしか成り立たない（ARPがルータを超えないため）

## 6. 防御側に必要な対策

| 対策 | 内容 | 防げる攻撃 |
|---|---|---|
| **DAI**（Dynamic ARP Inspection） | L2SWが、通過するARPを**DHCPスヌーピングのバインディングテーブル**と照合し、合わないARPを捨てる | ARPスプーフィング |
| **DHCPスヌーピング** | 信頼するポート以外からのDHCP応答を捨て、IPとMACとポートの対応（バインディング）を作る。DAIの前提 | 偽のDHCPサーバ |
| **静的ARP** | 重要な機器（デフォルトゲートウェイ）のARPを固定で登録する | ARPスプーフィング（台数が多いと管理が大変） |
| **ポートセキュリティ** | ポートごとに学習するMACアドレスの数を制限する | MACフラッディング |
| **セグメントの分割**（VLAN） | 攻撃が届く範囲（ブロードキャストドメイン）を小さくする | 被害の範囲を限定 |
| **通信の暗号化（TLS（Transport Layer Security）など）** | 経路を乗っ取られても中身を読ませない | 盗聴（スプーフィング自体は防げない） |

- → [[Gratuitous ARP]]（ARPスプーフィングの詳細）、[[DHCP]]（DHCPスヌーピング）

## 7. 覚え方

- **「ARPは同じ部屋の中でしか大声で呼ばない（ブロードキャスト）。部屋の外の人は、出口係（デフォルトゲートウェイ）に頼む」**
- **「IPは宛名（最後まで同じ）、MACは次の配達員の名前（区間ごとに書き換え）」**
- **「経路表は誰に渡すか、ARPテーブルはその人の顔（MAC）、MACアドレステーブルはその人がいる窓口（ポート）」**
- **「VRRPの切替で書き換わるのは、PCのARPではなくL2SWのMACアドレステーブル」**

## 8. 勉強の優先順位

1. PCがARPで調べるのはデフォルトゲートウェイだけ、IPは不変でMACは区間ごと、を説明できる
2. 経路表・ARPテーブル・MACアドレステーブルの違い（誰が持つか、何に使うか）
3. VRRPの切替とGARP（L2SWのMACアドレステーブルの更新）
4. ARPスプーフィングとDAI・DHCPスヌーピング
5. プロキシARPは一言で説明できればよい
