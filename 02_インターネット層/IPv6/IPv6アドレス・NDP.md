# IPv6アドレス・NDP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

移行技術（デュアルスタック、MAP-E、NAT64など）は [[IPv6移行技術]]、ICMPv6のメッセージ一覧は [[ICMP]] を参照。

## 1. IPv6アドレスの書き方（○：午前の定番）

- **128ビット**。16ビットずつ16進数4桁で、**8つのブロック**をコロンで区切る
  - 例：`2001:0db8:0000:0000:0000:ff00:0042:8329`
- 省略のルール
  1. 各ブロックの**先頭の0は省略**できる：`0db8` → `db8`、`0042` → `42`
  2. **0だけのブロックが連続する部分は「::」にまとめられる**。ただし**1つのアドレスで1回だけ**
  - 上の例 → `2001:db8::ff00:42:8329`
- 午前の定番：「正しい省略表記はどれか」（「::」を2回使っているものは誤り）

## 2. アドレスの種類（◎）

| 種類 | 範囲 | 内容 |
|---|---|---|
| **グローバルユニキャスト** | **2000::/3** | インターネットで一意 |
| **リンクローカル** | **fe80::/10** | 同じリンク内だけ。**全インタフェースに自動で付く**。NDP（Neighbor Discovery Protocol）、ルーティングのネクストホップに使う |
| ユニークローカル（ULA（Unique Local Address）） | fc00::/7（実際は fd00::/8） | 組織内だけで使う |
| **マルチキャスト** | **ff00::/8** | 主なもの：**ff02::1（全ノード）**、**ff02::2（全ルータ）** |
| エニーキャスト | （ユニキャストと同じ形式） | 同じアドレスを持つ複数の機器のうち、最も近い1台に届く |
| ループバック | ::1 | 自分自身 |

- **ブロードキャストはない** → マルチキャストで代用する
- **1つのインタフェースに複数のアドレス**（リンクローカル＋グローバル＋一時アドレスなど）が付くのが普通

**リンクローカルとユニークローカルの違いは「届く範囲」**（付け方の違いではない）

| | **リンクローカル**（fe80::/10） | **ユニークローカル**（fd00::/8） |
|---|---|---|
| 届く範囲 | **同じリンク（セグメント）の中だけ**。ルータを越えない | **組織の中**なら、ルータを越えて届く。インターネットには出ない |
| IPv4でいうと | 近いものはない（169.254.x.x に少し似ている） | **プライベートアドレス**（10.0.0.0/8 など） |
| 付け方 | **全インタフェースに、必ず自動で**付く | 手動、**SLAAC（Stateless Address Autoconfiguration）**（RAでfdのプレフィックスを配る）、DHCPv6 |
| 必須か | **必須**（ないとIPv6が動かない） | 任意（使わない組織も多い） |

```
    セグメントA            ルータ            セグメントB
PC1 fe80::1 ───────── fe80::a | fe80::b ───────── PC2 fe80::2
    fd00:1::10                                    fd00:2::20

PC1 → PC2：リンクローカル（fe80::2）宛ては、ルータを越えられない ✕
PC1 → PC2：ユニークローカル（fd00:2::20）宛ては、ルータを越えて届く ✓
```

- 覚え方：**「リンクローカルは同じ部屋の中だけの内線、ユニークローカルは社内の内線、グローバルは外線」**

### インタフェースIDの作り方（○）

- LAN（Local Area Network）のプレフィックスは **/64** → 下位64ビットが**インタフェースID**
- **EUI-64（64-bit Extended Unique Identifier）**：48ビットのMAC（Media Access Control）アドレスの真ん中に **FFFE** を挟み、先頭から7ビット目（U/Lビット）を反転して作る
  - 例：MAC 00-11-22-33-44-55 → インタフェースID **0211:22ff:fe33:4455**
  - MACアドレスから端末を追跡できてしまう → **一時アドレス**（ランダムなインタフェースID）を使うOS（Operating System）が多い

## 3. IPv6ヘッダの特徴（○）

| 項目                | IPv6               | IPv4との違い                                                                |
| ----------------- | ------------------ | ----------------------------------------------------------------------- |
| ヘッダ長              | **40バイト固定**        | IPv4は可変（20バイト〜）                                                         |
| オプション             | **拡張ヘッダ**として後ろにつなぐ | −                                                                       |
| ヘッダのチェックサム        | **ない**             | ルータの処理が軽い                                                               |
| 途中のルータでの分割        | **しない**（送信元だけが分割）  | → PMTUD（Path MTU Discovery）が必須、最小MTU（Maximum Transmission Unit）は1280バイト |
| TTL（Time To Live） | **ホップリミット**という名前   | 役割は同じ                                                                   |

## 4. NDP（◎）

- **NDP**：ICMPv6を使って、**同じリンク上の機器を見つけたり、アドレスを決めたり**する仕組み。IPv4のARP（Address Resolution Protocol）やICMP（Internet Control Message Protocol）リダイレクト、DHCP（Dynamic Host Configuration Protocol）の一部の役割をまとめて担う

| 機能 | 使うメッセージ | 内容 |
|---|---|---|
| **ルータ探索** | **RS（Router Solicitation）→ RA（Router Advertisement）** | 端末がルータを見つけ、プレフィックスやデフォルトゲートウェイを知る |
| **アドレス自動設定（SLAAC）** | RA | RAのプレフィックス＋インタフェースIDでアドレスを作る |
| **アドレス解決** | **NS（Neighbor Solicitation）→ NA（Neighbor Advertisement）** | 相手のIPv6アドレスからMACアドレスを知る（ARPの代わり） |
| **重複アドレス検出（DAD（Duplicate Address Detection））** | NS | 使う前に、そのアドレスが使われていないか確かめる |
| 近隣到達不能検知（NUD（Neighbor Unreachability Detection）） | NS／NA | 相手にまだ届くか確かめる |
| リダイレクト | Redirect | より良いルータを教える |

- NSは、ブロードキャストではなく**要請ノードマルチキャストアドレス**（ff02::1:ffXX:XXXX、アドレスの下位24ビットを使う）宛てに送る → 関係のない端末を煩わせない
- **RAのフラグ**：Mフラグ（アドレスをDHCPv6でもらう）、Oフラグ（DNS（Domain Name System）サーバなどの情報をDHCPv6でもらう）→ [[IPv6移行技術]]

## 5. 午後で問われるテーマと記述の型

### ◎ 端末がアドレスとデフォルトゲートウェイを得る流れ

1. リンクローカルアドレスを作り、DADで重複を確認する
2. RSを送り、ルータからRAを受け取る（ルータは定期的にもRAを送る）
3. RAのプレフィックスでグローバルアドレスを作る（SLAAC）、DADで確認する
4. **デフォルトゲートウェイは、RAを送ったルータのリンクローカルアドレス**
5. DNSサーバのアドレスは、RA（RDNSS（Recursive DNS Server）オプション）またはDHCPv6で得る
- 記述の型：「端末はルータから受信したRAに含まれるプレフィックスと、自身で生成したインタフェースIDを組み合わせてアドレスを生成する」

### ◎ 不正なRA（なりすましルータ）

- **攻撃者の観点**：偽のRAを送り、自分をデフォルトゲートウェイにさせる → 端末の通信を中継して盗聴・改ざんする（中間者攻撃）。設定ミスのルータ（家庭用ルータの持ち込み）でも同じことが起きる
- **防御側の対策**：**RAガード**（L2スイッチで、ルータがつながるポート以外から来たRAを破棄する）、端末側で不要なIPv6を無効にする
- 記述の型：「L2スイッチのRAガード機能で、ルータを接続していないポートから受信したRAを破棄する」

### ○ ICMPv6をFWで遮断してはいけない理由

- NDP（RS／RA／NS／NA）もPMTUDのPacket Too BigもICMPv6 → 丸ごと遮断すると**通信自体が成り立たない**
- 対策：必要なタイプだけを許可する
- → [[ICMP]]、[[FW]]

### ○ IPv4とIPv6の対応

| IPv4 | IPv6 |
|---|---|
| ARP | NDP（NS／NA） |
| Gratuitous ARP | DAD、非要請NA |
| ブロードキャスト | マルチキャスト |
| DHCP | SLAAC、DHCPv6 |
| プライベートアドレス | ユニークローカルアドレス |
| 169.254.0.0/16 | fe80::/10（ただしIPv6では常に付く） |

## 6. 覚え方

- **省略は「先頭の0は消せる、0の連続は::で1回だけ」**
- **アドレスは「2000::/3外向け、fe80リンク内、fd社内、ff マルチキャスト」**、ブロードキャストはない
  - 16進数で並べると、**数字が大きくなるほど届く範囲が狭くなり、最後（ff）が放送**（外 → 社内 → 部屋 → 放送）。語呂は覚えるためのもので、正式な意味ではない

```
0000 ……………… ::、::1（特殊）           「何もない＝まだアドレスがない（::）、自分＝1番（::1）」
2000〜3fff …… グローバル（外線）          「2（ツー）、3（スリー）で外（ソト）へ」
   ⋮
fd00〜fdff …… ユニークローカル（社内の内線） 「fd ＝ family domain（身内の範囲）」
fe80〜febf …… リンクローカル（部屋の中の内線）「fe80 ＝ Fe（鉄）の柵（80）。柵の中だけ」
ff00〜ffff …… マルチキャスト（館内放送）    「ff ＝ full（みんな）へ」
```

  - マルチキャストのよく出るもの：**ff02::1は全ノード**（「1は全員」）、**ff02::2は全ルータ**（「2はルータ」）。RSは全ルータ（::2）に聞き、RAは全ノード（::1）に知らせる
  - まとめ：**「2で外へ、fdは社内、fe80は部屋の中、ffはみんなへ放送。::1は自分」**
- **EUI-64は「MACの真ん中にFFFE、7ビット目を反転」**
- **NDPは「RS／RAでルータを探し、NS／NAで隣を探す」**（ICMPv6の133〜136）
- **デフォルトゲートウェイは「RAをくれたルータのリンクローカル」**
- **不正なRAは「偽の案内係」→ RAガードで止める**

## 7. 勉強の優先順位

1. 端末がアドレス・デフォルトゲートウェイ・DNSサーバを得る流れを説明できるようにする
2. アドレスの種類（特にリンクローカル、グローバル、マルチキャスト）
3. NDPの機能とメッセージの対応
4. 不正なRAとRAガード、ICMPv6を遮断してはいけない理由を30〜40字で書けるようにする
5. 省略表記のルール（午前）
6. EUI-64、ヘッダの特徴、要請ノードマルチキャストは午前で確認する程度でよい

> [!tip] 得点につながる覚え方
> IPv6は「**IPv4の何に当たるか」で覚える**と整理しやすい。午後では、端末がアドレスを得る流れと、RAを悪用した攻撃・RAガードが定番。
