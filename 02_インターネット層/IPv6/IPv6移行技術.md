# IPv6移行技術 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

令和7年春 午後Ⅱ 問1は、社内ネットワークのIPv6対応を題材に、**IPv6アドレスの割当て、DNS（Domain Name System）の通信の流れ、経路制御の設計**を問う問題だった（IPA（情報処理推進機構）の出題趣旨より）。移行技術の前提として、アドレスの基本も最初にまとめる。

## 1. 前提：IPv6アドレスの基本（○）

| 種類 | 範囲 | 用途 |
|---|---|---|
| **グローバルユニキャスト** | **2000::/3** | インターネットで使う |
| **リンクローカル** | **fe80::/10** | **同じリンク内だけ**。全インタフェースに自動で付く。NDP（Neighbor Discovery Protocol）やルーティングのネクストホップに使う |
| ユニークローカル（ULA（Unique Local Address）） | fc00::/7（実際は fd00::/8） | 組織内だけで使う（IPv4のプライベートアドレスに近い） |
| マルチキャスト | ff00::/8 | ブロードキャストの代わりも担う |

- **LANのプレフィックス長は /64** が基本（上位64ビット：プレフィックス、下位64ビット：インタフェースID）
- 1つのインタフェースに**複数のアドレス**（リンクローカル＋グローバルなど）が付く

### アドレスの割当て方法（◎）

| 方式 | 内容 |
|---|---|
| **SLAAC（Stateless Address Autoconfiguration）** | ルータの**RA**（Router Advertisement）でプレフィックスを受け取り、端末が自分でインタフェースIDを作る |
| **DHCPv6（ステートレス）** | アドレスはSLAACで作り、**DNSサーバのアドレスなどだけ**をDHCPv6でもらう |
| **DHCPv6（ステートフル）** | アドレスもDHCPv6サーバから割り当てる（誰に何を割り当てたか管理できる） |
| **DHCPv6-PD（Prefix Delegation）** | ISP（Internet Service Provider）がルータに**プレフィックスをまとめて委任**し、ルータがLAN（Local Area Network）側に配る |

- RAの**Mフラグ**（アドレスをDHCPv6でもらう）・**Oフラグ**（その他の情報をDHCPv6でもらう）で、端末にどの方式を使うか知らせる（○）
- 問われ方：「端末がDNSサーバのアドレスを知る方法」「アドレスを管理したい場合の方式」

## 2. 移行技術の3つの考え方（◎）

| 考え方 | 内容 | 代表 |
|---|---|---|
| **デュアルスタック** | 1台の機器で**IPv4とIPv6を両方動かす** | 端末、ルータ、サーバの両対応 |
| **トンネリング** | 一方のプロトコルのパケットを、**もう一方のパケットに入れて運ぶ** | IPv6 over IPv4（6to4など）、**IPv4 over IPv6（MAP-E、DS-Lite）** |
| **トランスレーション（変換）** | IPv6とIPv4の**ヘッダを相互に変換**する | **NAT64／DNS64** |

### デュアルスタック（◎）

- 最も一般的な移行方法。IPv4のサービスにはIPv4、IPv6のサービスにはIPv6で通信する
- DNSでAとAAAAの両方が返ると、**多くのOS（Operating System）はIPv6を優先**する
  - IPv6の経路がつながっていないと、IPv6での接続を待ってからIPv4に切り替える → **応答が遅くなる**
  - **Happy Eyeballs**：IPv6とIPv4をほぼ同時に試し、早くつながった方を使う（○）
- 管理の手間：**IPv4とIPv6の両方にFW（Firewall）ルール・経路・監視を設定**する必要がある

### IPv4 over IPv6（◎：日本の家庭・企業のインターネット接続）

- 日本では、フレッツ網の**IPoE**（IP over Ethernet）でIPv6接続し、**IPv4の通信をIPv6の中に入れて運ぶ**方式が普及している
  - PPPoE（Point-to-Point Protocol over Ethernet）の網終端装置の混雑を避けられる → [[PPP]]

| 方式 | NAPT（Network Address Port Translation）する場所 | ポイント |
|---|---|---|
| **MAP-E** | **利用者側のルータ** | 1つのIPv4グローバルアドレスを複数の利用者で共有し、**利用者ごとに使えるポート番号の範囲が決まっている** |
| **DS-Lite** | **ISP側の装置**（AFTR（Address Family Transition Router）） | 利用者側はIPv4パケットをIPv6で包むだけ。ISP側で大規模なNAPT（CGNAT（Carrier-Grade NAT）） |

- **ステートフルとステートレスの違い**（○）：DS-LiteのAFTRは、全利用者分のNAPTを変換テーブルで管理する**ステートフル**な変換 → ISP側に負担が集まる。MAP-Eは、利用者側のルータがNAPTし、ISP側の装置（BR：Border Relay）は規則で変換するだけの**ステートレス**な変換 → ISP側の負担が小さく、冗長化しやすい（→ [[NAT・NAPT]]）
- 共通の問題：IPv4アドレスを共有するので、**外からIPv4で接続を受けられない**（ポートフォワーディングが難しい）、**使えるポート数が限られる**
- 記述の型：「IPv4アドレスを複数の利用者で共有するため、利用できるポート番号が制限され、外部からの接続も受けられないから」
- → [[NAT・NAPT]]

### NAT64／DNS64（○）

- **IPv6だけの端末**から、**IPv4だけのサーバ**に接続する仕組み
  - **DNS64**：IPv4のアドレス（A）しかない名前を問い合わせると、IPv4アドレスを埋め込んだ**IPv6アドレス（AAAA）を合成**して返す（よく使うプレフィックスは 64:ff9b::/96）
  - **NAT64**：そのIPv6アドレス宛てのパケットを、**IPv4に変換**してサーバに送る
  - DNS64と組み合わせるNAT64は、ふつう変換テーブルを持つ**ステートフル**な変換（ステートフルNAT64）
- 問われ方：「IPv6だけのネットワークからIPv4のWebサイトを見る仕組み」

## 3. 午後で問われるテーマと記述の型

### ◎ 社内ネットワークのIPv6対応

- どのセグメントに、どの方式（SLAAC／DHCPv6）でアドレスを割り当てるか
- 端末がDNSサーバを知る方法（RAのRDNSS（Recursive DNS Server）オプション、またはDHCPv6）
- ルーティング：OSPFv3、ネクストホップはリンクローカルアドレス → [[OSPF]]
- FWのルールをIPv6でも設定する。**ICMPv6を丸ごと遮断しない**（NDP、PMTUD（Path MTU Discovery）が動かなくなる）→ [[ICMP]]

### ◎ IPv6で意図しない通信経路ができる

- 多くのOSは**初期設定でIPv6が有効**。IPv4のセキュリティ対策だけを設定していると、**IPv6の通信が監視・制御されずに通る**
- 不正なRAを送るルータ（なりすまし、設定ミス）で、端末が偽のルータを経由する → **RAガード**で防ぐ
- 記述の型：「IPv6が有効な端末はIPv6でも通信するため、IPv4と同等のアクセス制御をIPv6にも設定する必要があるから」

### ○ DNSの通信の流れ

- AとAAAAの両方を問い合わせる、どちらを先に使うか、IPv6がつながらない場合の切替（Happy Eyeballs）
- DNSサーバ自体にIPv6で問い合わせられるか（DNSサーバのIPv6対応）
- → [[DNS]]

### ○ インターネット接続をIPoEに変える

- PPPoEの混雑を避けてIPoE（IPv6）に移行し、IPv4はMAP-E／DS-Liteで運ぶ
- 拠点のサーバを公開している、拠点へのVPN（Virtual Private Network）を受けている場合は、**IPv4アドレスの共有で受けられなくなる** → 固定IPv4アドレスのサービスを使う

## 4. 覚え方

- **移行は「両方話す（デュアルスタック）・包んで運ぶ（トンネル）・通訳する（変換）」**
- **アドレスは「2000::/3が外向け、fe80がリンク内、fdが社内用」、LANは /64**
- **SLAACは「RAでプレフィックスをもらって自分で作る」、DHCPv6-PDは「ISPから区画をまとめて預かる」**
- **MAP-Eは「自宅のルータでNAPT、ポートは割当て制」、DS-Liteは「ISPでまとめてNAPT」**
- **DNS64は「A しかないならAAAAを作って返す」、NAT64は「それを本物のIPv4に通訳」**
- **IPv6は「勝手に有効、勝手に通る」**：FWとRAガードを忘れない

## 5. 勉強の優先順位

1. IPv6アドレスの種類と、割当て方法（SLAAC、DHCPv6、DHCPv6-PD）、RAのM／Oフラグ
2. デュアルスタックの仕組みと、IPv6を優先する動作・Happy Eyeballs
3. MAP-EとDS-Liteの違いと、IPv4アドレス共有による制約を30〜40字で書けるようにする
4. IPv6で意図しない通信経路ができる問題と、FW・RAガードの対策
5. NAT64／DNS64の仕組み
6. 6to4、ISATAPなどの古いトンネル技術は名前を知っている程度でよい

> [!tip] 得点につながる覚え方
> IPv6は直近の午後Ⅱで大問として出ている。「**アドレスをどう配るか」「DNSで何が返り、どちらで通信するか」「IPv4とIPv6の両方を守れているか**」の3つの観点で構成図を読む。
