# NAT・NAPT まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. プライベートアドレス（○）

| 範囲 | 用途 |
|---|---|
| **10.0.0.0/8** | プライベートアドレス |
| **172.16.0.0/12**（172.16〜172.31） | プライベートアドレス |
| **192.168.0.0/16** | プライベートアドレス |
| 100.64.0.0/10 | **シェアードアドレス**（ISP（Internet Service Provider）のCGNATで使う） |

- 組織の中では自由に使えるが、**インターネットにはそのまま出られない** → 境界でグローバルアドレスに変換する
- 午前の定番：「プライベートアドレスはどれか」（172.32.0.1は範囲外、などのひっかけ）

## 2. NATとNAPT（◎）

| | NAT（Network Address Translation） | NAPT（Network Address Port Translation） |
|---|---|---|
| 変換するもの | **IPアドレスだけ** | **IP（Internet Protocol）アドレス＋ポート番号** |
| 対応 | プライベート1つ ↔ グローバル1つ | **多数のプライベート ↔ 1つのグローバル** |
| 区別のしかた | アドレスで区別 | **ポート番号**で各端末の通信を区別 |
| 別名 | − | IPマスカレード |

- **NAPTの動き**
  1. 端末（192.168.1.10:50000）がWebサーバへ送る
  2. ルータが送信元を（203.0.113.1:**60001**）に書き換え、**変換テーブル**に記録する
  3. 戻りのパケット（宛先 203.0.113.1:60001）を、テーブルを見て 192.168.1.10:50000 に戻す
- **静的NAT**：公開サーバ用に、プライベートとグローバルを**常に1対1で対応**させる → 外から接続できる
- **ポートフォワーディング（静的NAPT）**：グローバルアドレスの**特定のポート**宛てを、内部の特定のサーバに転送する
- 変換テーブルには**無通信タイマ**がある → 長時間通信しないと削除され、通信が切れる（WebSocket、IPsec（Security Architecture for Internet Protocol）のNAT-Tのキープアライブが必要な理由）

### NAPTとポートフォワーディングの比較と使い分け（○）

- 向きが逆の仕組み。**NAPTは「中から外へ出す」、ポートフォワーディングは「外から中へ入れる」**

| | NAPT | ポートフォワーディング（静的NAPT） |
|---|---|---|
| 向き | 内 → 外（内側から通信を始める） | 外 → 内（外側から通信を始める） |
| 変換テーブル | 通信が始まるたびに**自動で**作る | **前もって手で**設定する |
| 変換するもの | 送信元（プライベートIP:ポート → グローバルIP:ポート） | 宛先（グローバルIP:ポート → 内部サーバのIP:ポート） |
| 例 | 社員のPCがWebを見る | 外から `グローバルIP:443` に来た通信を、内部のWebサーバへ届ける |

- **NAPTの利点と欠点**
  - 利点：1つのグローバルアドレスを多くの端末で共有できる。内部のアドレスが外から見えない。外から突然来た通信は自然に止まる
  - 欠点：外から始まる通信は届かない。FTP・SIPはALGが必要。ESPはNAT-Tが必要。端末が多いとポート番号が足りなくなる。外からは全員が同じアドレスに見えるので、「誰の通信か」を追うには変換の記録が要る
- **ポートフォワーディングの利点と欠点**
  - 利点：グローバルアドレスが1つでも、内部のサーバを外に公開できる。公開するポートだけを開けられる（1対1の静的NATより開ける範囲が狭い）
  - 欠点：公開したポートは外から誰でも狙える。1つのグローバルアドレスでは、**同じポート番号は1台のサーバにしか割り当てられない**（443番のWebサーバを2台公開できない）。公開したサーバが乗っ取られると内部に入られる → サーバはDMZに置く
- **使い分け**

| やりたいこと | 方法 |
|---|---|
| 社員のPCがインターネットを使う | NAPT |
| グローバルアドレスが1つで、サーバを1〜2台公開する | ポートフォワーディング（サーバはDMZに置く） |
| 同じポート番号のサーバを複数公開する | グローバルアドレスを複数用意して1対1の静的NATにする。または、リバースプロキシ・LB（Load Balancer）で受け、ホスト名（SNI（Server Name Indication）、Hostヘッダ）で振り分ける |
| 公開するサーバが多い・サーバを直接外に見せたくない | リバースプロキシ・LBで受ける |

- 実際のルータ・FWでは両方を同時に使う：社員の通信はNAPTで外へ出し、公開サーバ宛ての通信だけポートフォワーディングで入れる
- 問われ方：「外から内部のサーバにアクセスできない理由」→ 変換テーブルが内から外への通信でしか作られないから。対策はポートフォワーディング（または静的NAT）の設定
- → [[負荷分散装置]]、[[プロキシ]]、[[FW]]

### ステートフルNATとステートレスNAT（○）

- 違いは、**通信ごとの記録（変換テーブル）を持つかどうか**

| | ステートフル | ステートレス |
|---|---|---|
| 変換の決め方 | 通信が始まるたびに対応を決め、変換テーブルに記録する | 決まった規則（計算式）で変換する。テーブルを持たない |
| 例 | NAPT、DS-LiteのAFTR（Address Family Transition Router）、ステートフルNAT64 | 1対1の静的NAT、MAP-EのISP側の装置（BR：Border Relay）、NPTv6（IPv6-to-IPv6 Network Prefix Translation） |
| 外から始まる通信 | 記録がないので届かない | 規則で変換できる（1対1の場合） |
| 装置の負担 | 通信の数だけテーブルが増える。あふれると新しい通信ができない | 通信が増えても負担がほぼ変わらない |
| 冗長化 | テーブルの同期が必要。行きと帰りが別の装置を通ると変換できない | どの装置でも同じ規則で変換できるので、冗長化しやすい |

- 覚え方：**「ステートフルは台帳を付ける、ステートレスは計算式で決める」**。FWのステートフルインスペクションと同じ考え方（記録のない通信は通さない）
- → [[IPv6移行技術]]（DS-LiteとMAP-Eの違い）

## 3. NAPTの性質と問題（◎）

### 外から接続を始められない

- 変換テーブルは**内から外への通信で作られる** → 外から突然来たパケットは、どの端末に送ればよいか分からず捨てる
- 結果として外からの不正なアクセスを防ぐ効果があるが、**外からの接続が必要なサービス**（サーバの公開、アクティブモードのFTP（File Transfer Protocol））は使えない → 静的NAT、ポートフォワーディングで対応

### アドレスをデータの中に書くプロトコル（◎）

- **FTP**（PORTコマンド、227応答）、**SIP（Session Initiation Protocol）**（SDP（Session Description Protocol）の中のRTP（Real-time Transport Protocol）のアドレス・ポート）は、IPアドレスとポート番号を**アプリケーションのデータの中**に書いている
- NAPTはIPヘッダ・TCP（Transmission Control Protocol）／UDP（User Datagram Protocol）ヘッダしか書き換えない → データの中は**プライベートアドレスのまま**相手に届き、通信できない
- 対策：**ALG（Application Level Gateway）**：ルータ・FWがデータの中まで見てアドレスを書き換え、必要な通信を一時的に許可する
- 記述の型：「アプリケーションのデータ内に記載されたIPアドレスがNAPTで変換されず、プライベートアドレスのまま相手に通知されるから」
- → [[FTP]]、[[VoIP・SIP]]

### ポート番号のないプロトコル（◎）

- **IPsecのESP（Encapsulating Security Payload）**、GRE（Generic Routing Encapsulation）にはポート番号がない → NAPTで複数の端末を区別できない
- 対策：IPsecは**NAT-T（UDP 4500に入れる）**、PPTP（Point-to-Point Tunneling Protocol）はルータのパススルー機能
- **AH**（Authentication Header）はIPヘッダも改ざん検知の対象なので、アドレスを書き換えるとNATと**併用できない**
- → [[IPsec]]

## 4. 午後で問われるテーマと記述の型

### ◎ 公開サーバへのアクセスと変換

- 外部からは**グローバルアドレス**で公開サーバにアクセスし、FW（Firewall）・ルータが**静的NAT**で内部（DMZ（DeMilitarized Zone））のアドレスに変換する
- FWのフィルタリングルールに書くのが**変換前か変換後のアドレスか**を問題文で確認する → [[FW]]

### ○ 内部から公開サーバのグローバルアドレスにアクセスする

- 社内の端末が、同じ社内（DMZ）にある公開サーバに**グローバルアドレス**でアクセスすると、うまく折り返せないことがある
- 対策
  - **ヘアピンNAT**（NATループバック）：ルータで折り返して変換する
  - **スプリットDNS**（Domain Name System）：社内からの問い合わせには**内部のアドレス**を答える → [[DNS]]
- 記述の型：「社内のDNSサーバで公開サーバの内部アドレスを応答させ、NATを経由せずにアクセスさせるため」

### ○ CGNAT（キャリアグレードNAT）

- **CGNAT（Carrier-Grade NAT）**：ISPが多数の利用者をまとめて少数のグローバルアドレスに変換する（IPv4アドレスの不足対策）
  - 利用者側のルータでもNAPTするので、**二重のNAPT**になる
- 問題
  - **外から接続できない**（ポートフォワーディングが使えない）→ サーバの公開、拠点へのVPN（Virtual Private Network）の着信ができない
  - **1利用者が使えるポートの数に制限**がある → 大量のセッションを使うアプリで通信できなくなる
  - 送信元アドレスを他の利用者と共有する → ログでの追跡に、ポート番号と時刻が必要
- IPv6の **MAP-E**、**DS-Lite** も、ISP側（または利用者側）でIPv4アドレスを共有する仕組み → [[IPv6移行技術]]

### ○ ログと追跡

- NAPTの先では、外部から見える送信元は全員同じグローバルアドレス → 不正アクセスの追跡には**NAPTの変換ログ**（時刻、内部アドレス、ポート）が必要

## 5. 覚え方

- **NATは「1人1つの外線番号」、NAPTは「代表番号＋内線番号（ポート）」**
- **NAPTは「中から電話をかけた相手としか話せない」**：外から突然かかってきた電話は誰に回すか分からない
- **「手紙の中に書いた住所（データ内のアドレス）は書き換えない」** → FTP・SIPはALGで中身まで直す
- **「ポートのない荷物（ESP・GRE）は代表番号で振り分けられない」** → UDP 4500で包む
- **プライベートは「10、172.16〜31、192.168」**、100.64はCGNAT用

## 6. 勉強の優先順位

1. NATとNAPTの違い、NAPTの変換の流れを説明できるようにする
2. FTP・SIPがNAPTを越えられない理由とALGを30〜40字で書けるようにする
3. ESPがNAPTを越えられない理由とNAT-T
4. 静的NAT・ポートフォワーディングでのサーバ公開、FWルールとの関係
5. ヘアピンNATとスプリットDNS
6. CGNATの問題点（外から接続できない、ポート数の制限）
7. プライベートアドレスの範囲（午前）

> [!tip] 得点につながる覚え方
> NAPTは「**通信できない理由」の定番**。午後で「この通信がうまくいかない」と問われたら、**データの中にアドレスを書いていないか（FTP、SIP）**、**ポート番号のないプロトコルではないか（ESP、GRE）**、**外から始まる通信ではないか**の3つを疑う。
