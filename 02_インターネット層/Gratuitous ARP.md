# Gratuitous ARP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. Gratuitous ARPの基本（◎）

- **自分自身のIP（Internet Protocol）アドレスを問い合わせる（通知する）ARP**（Address Resolution Protocol）。略してGARP
- 通常のARPとの違い

| 項目 | 通常のARP要求 | Gratuitous ARP |
|---|---|---|
| 送信元IPアドレス | 自分のIP | 自分のIP |
| **目的IPアドレス** | **相手のIP** | **自分のIP**（送信元と同じ） |
| 宛先MAC（Media Access Control）アドレス（Ethernet） | ブロードキャスト | ブロードキャスト |
| 目的 | 相手のMACアドレスを知る | **重複確認**、**自分のMACアドレスを周りに知らせる** |

- ブロードキャストで送るので、**同じセグメントの全機器に届く**（ルータは越えない）
- ARP要求の形で送る実装と、ARP応答の形で送る実装がある（△）
- 応答を待たずに一方的に送ってよいARP、という意味で "Gratuitous（頼まれていない）"

## 2. 3つの目的（◎）

| 目的 | 何が起きるか | 典型的な場面 |
|---|---|---|
| ① **IPアドレスの重複検出** | 応答が返ってきたら、同じIPを使う機器が他にいる | 起動時、IP設定時、DHCP（Dynamic Host Configuration Protocol）でアドレス取得後 |
| ② **周りの機器のARPテーブルを更新** | 受信した機器が「このIPのMACはこれ」と上書きする | **フェイルオーバでIPは同じだがMACが変わる**とき、NIC（Network Interface Card）交換 |
| ③ **L2スイッチのMACアドレステーブルを更新** | フレームの送信元MACを、受信ポートで学習し直す | **同じMACのまま接続ポートが変わる**とき（VRRP（Virtual Router Redundancy Protocol）の切替） |

- 午後では、②と③の**どちらが目的か**を構成から判断させる問題が出る → 下の「VRRPとサーバ冗長化の違い」が核心

## 3. 午後で問われるテーマと記述の型

### ◎ VRRPの切替時のGARP

- VRRPの仮想ルータは **仮想IPアドレス** と **仮想MACアドレス（00-00-5E-00-01-{VRID}）** を持つ
- マスタが故障 → バックアップが新マスタになり、**仮想MACを送信元にしたGARP**を送る
- 端末のARPテーブル：仮想IP → 仮想MAC は**変わらない**ので、更新は不要
- **L2スイッチのMACアドレステーブル**：仮想MACは旧マスタ側のポートで学習されたまま → 新マスタ側のポートに学習し直させる必要がある
- つまり**目的は③**
- 記述の型：「L2SW（Layer 2 Switch）のMACアドレステーブルを更新し、仮想MACアドレス宛てのフレームを新マスタに転送させるため」
- → [[VRRP]]

### ◎ サーバ・FW・負荷分散装置の冗長化（アクティブ／スタンバイ）

- 2台で **同じ仮想IP（サービスIP）** を引き継ぐが、**MACは機器ごとに違う**構成
- 切替後、周りの機器（ルータ、端末、L3SW（Layer 3 Switch））のARPテーブルには旧機器のMACが残る → **旧機器宛てに送り続けて通信できない**
- 新アクティブがGARPを送り、**ARPテーブルを新しいMACに更新させる**
- つまり**目的は②**（同時に③も起きる）
- 記述の型：「切替先の機器のMACアドレスを通知し、周辺機器のARPテーブルを更新させるため」
- 仮想MACを引き継ぐ製品なら、VRRPと同じく③が目的になる → **問題文で「MACも引き継ぐか」を必ず確認**

### ○ GARPに反応しない機器による通信断

- 機器によっては**受信したGARPでARPテーブルを更新しない**（セキュリティ上無視する設定など）
- その機器は**ARPキャッシュのタイムアウトまで旧MACに送り続ける**
- 対策
  - 該当機器でGARPを受け入れる設定にする
  - ARPキャッシュの保持時間を短くする
  - 仮想MACを引き継ぐ方式にする（ARPテーブルの更新自体が不要になる）
- 問われ方：「切替後、一部の機器だけ一定時間通信できなかった原因」
- GARPが失われることもあるので、**複数回送る**実装が多い

### ○ IPアドレスの重複

- 起動時のGARPに応答があれば重複を検知して警告する（OS（Operating System）の「IPアドレスが競合しています」）
- 重複に気づかずGARPを送ると、**正しい機器のARPテーブルの内容を上書き**してしまい、既存の機器が通信できなくなる
- DHCPでも、サーバはアドレスを払い出す前に、クライアントは受け取った後に、使われていないか確認する → [[DHCP]]

### ○ ARPスプーフィング（セキュリティ）

- GARPは**誰でも送れて、認証がない**
- 攻撃者が「デフォルトゲートウェイのIPのMACは自分」というGARPを送る → 端末のARPテーブルが書き換わり、通信が攻撃者を経由する（**中間者攻撃**）
- 対策
  - **ダイナミックARPインスペクション（DAI：Dynamic ARP Inspection）**：L2SWが**DHCPスヌーピングのバインディング情報**（IPとMACとポートの対応）と照合して、不正なARPを破棄する
  - 重要な機器は**静的ARPエントリ**にする
- 記述の型：「DHCPスヌーピングで得たIPアドレスとMACアドレスの対応と一致しないARPを破棄する」

### △ IPv6の場合

- ARPはないので、ICMPv6のNDP（Neighbor Discovery Protocol）で同じことをする
  - 重複検出：**DAD**（Duplicate Address Detection、NS（Neighbor Solicitation）を使う）
  - MACアドレスの変更の通知：**非要請NA（Unsolicited NA）**
- → [[ICMP]]

## 4. 覚え方

- **「自分で自分を呼ぶARP」**：目的IP＝自分のIP
- **3つの目的は「重複チェック・ARP更新・MAC表更新」**
- **IPだけ引き継ぐ → ARPテーブル更新、MACも引き継ぐ → スイッチのMAC表更新**
  - VRRPは仮想MACを持つので「スイッチのMAC表」
  - この区別が午後の記述の分かれ目
- **GARPは「名乗るだけで信じてもらえる」** → だからスプーフィングに使われ、DAIで止める

## 5. 勉強の優先順位

1. VRRPの切替時にGARPを送る目的（L2SWのMACアドレステーブル更新）を30〜40字で書けるようにする
2. 仮想MACを引き継がない冗長化では、目的がARPテーブル更新になることを区別する
3. GARPに反応しない機器があると通信断が続く理由と対策
4. ARPスプーフィングとDAIの仕組み
5. IPv6のDAD／非要請NAは名前と対応だけ押さえればよい

> [!tip] 得点につながる覚え方
> GARPは単独ではほぼ出ず、**冗長化（VRRP、FW（Firewall）・LB（Load Balancer）・サーバのクラスタ）の切替の流れの中で**問われる。構成図を見たら「切替で変わるのはIPかMACか、それとも接続ポートか」を確認し、更新が必要な表（ARPテーブル／MACアドレステーブル）を特定する。
