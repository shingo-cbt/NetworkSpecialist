# ゼロトラスト・SASE まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

SWG（Secure Web Gateway）への移行は、令和4年春 午後Ⅰ 問2「セキュアゲートウェイサービスの導入」、令和7年春 午後Ⅰ 問3「プロキシからセキュアWebゲートウェイサービスへの移行」で出題されている。

## 1. 境界型防御とゼロトラスト（○）

| | 境界型防御（従来） | ゼロトラスト |
|---|---|---|
| 考え方 | **社内は安全、社外は危険**。境界（FW（Firewall）、プロキシ）で守る | **社内も社外も信頼しない**。アクセスのたびに確かめる |
| 守る場所 | 社内ネットワークの入口 | **利用者・端末・アプリケーションごと** |
| 社外からの利用 | VPN（Virtual Private Network）で社内に入ってから使う | どこからでも、同じ確認を経て直接使う |

- 境界型の限界
  - **クラウドサービス**の利用が増え、守るべきものが社外にある
  - **テレワーク**でVPN装置・社内のプロキシ・回線に通信が集中する
  - 一度境界の内側に入られると（VPNの認証情報の盗難、マルウェア感染）、**社内を自由に移動**されてしまう
- ゼロトラストの原則
  - **アクセスのたびに、利用者（多要素認証）と端末の状態（OS（Operating System）の更新、マルウェア対策）を確認**する
  - **必要最小限の権限**だけを与える
  - **すべての通信を記録・監視**する

## 2. 構成要素（◎）

| 要素 | 役割 |
|---|---|
| **IdP（Identity Provider）** | 利用者の認証を一元化する。**SSO（Single Sign-On）**と**多要素認証** → [[SAML]] |
| **SWG** | **Webアクセスを中継・検査するクラウドのプロキシ**。URL（Uniform Resource Locator）フィルタリング、マルウェア検査、TLS（Transport Layer Security）インスペクション |
| **CASB（Cloud Access Security Broker）** | **クラウドサービスの利用を可視化・制御**する。許可していないクラウドサービスの利用（シャドーIT）の発見、データの持ち出しの制限 |
| **ZTNA（Zero Trust Network Access）** | VPNの代わりに、**アプリケーション単位で**社内のシステムへのアクセスを許可する。ネットワーク全体には入れない |
| FWaaS（Firewall as a Service） | クラウドで提供されるFW |
| **EDR（Endpoint Detection and Response）**、MDM（Mobile Device Management） | 端末の監視・管理。端末の状態をアクセスの判断に使う |
| **SD-WAN（Software-Defined WAN）** | 拠点の回線を制御する → [[SD-WAN]] |

- **SASE（Secure Access Service Edge）**：**ネットワーク（SD-WAN）とセキュリティ（SWG、CASB、ZTNA、FWaaS）をまとめてクラウドのサービスとして提供**する考え方
  - セキュリティ機能だけの部分をSSE（Security Service Edge）と呼ぶ（△）

## 3. 午後で問われるテーマと記述の型

### ◎ プロキシからSWGへの移行

- 移行の理由
  - **テレワークの端末も、社内と同じWebアクセスの制御**を受けられる（社内のプロキシを経由させるためにVPNを使わなくてよい）
  - 社内のプロキシ・インターネット回線の**負荷と混雑を解消**できる
- 必要な作業
  - 端末の**PAC（Proxy Auto-Config）ファイル**（またはSWGの専用ソフト）で、Webの通信をSWGに向ける → [[プロキシ]]
  - SWGでTLSインスペクションをするなら、**端末にSWGのルート証明書を配布**する → [[TLS]]
  - **SWGの利用者認証**をIdPと連携する（誰のアクセスかを記録・制御する）
  - クラウドサービス側で、**SWGの送信元IP（Internet Protocol）アドレスからのアクセスだけを許可**する（SWGを経由しないアクセスを防ぐ）
  - 社内のFWで、端末から外部への直接のWebアクセスを拒否する
- 記述の型：「クラウドサービスへのアクセスをSWGの送信元IPアドレスに限定することで、SWGを経由しない利用を防ぐため」

### ○ VPNからZTNAへ

- VPNは**ネットワーク全体**に入れる → 侵入されると横に広がる。VPN装置に通信が集中する
- ZTNAは**許可したアプリケーションだけ**に接続させる。利用者・端末の状態を毎回確かめる

### ○ ローカルブレイクアウトとの組合せ

- 拠点から**クラウドサービスへの通信を、本社を経由せず直接インターネットへ**出す（SD-WAN）→ その代わりにSWGで検査する

## 4. 攻撃者の観点：どこを突くか

| 狙う所 | 攻撃のしかた | 成り立つ条件 |
|---|---|---|
| **境界の内側の信頼** | VPNの認証情報を盗む、社内の端末をマルウェアに感染させる → 内側から**社内を自由に移動**する（横展開） | 境界の内側を無条件に信頼している |
| **ID・パスワード** | フィッシングで盗んだ認証情報でクラウドサービスにログインする | 多要素認証がない、IdPを経由しないログインが残っている |
| **SWGを経由しない経路** | SWGを通らずにクラウドサービスへ直接アクセスする、SWGの設定を外した端末を使う | クラウド側で送信元を制限していない |
| **許可していないクラウドサービス** | 個人のクラウドストレージに業務データを持ち出す（シャドーIT） | クラウドの利用を可視化・制御していない |
| **管理されていない端末** | 私物や、更新されていない端末から接続する | 端末の状態をアクセスの判断に使っていない |

## 5. 防御側に必要な対策

| 対策 | 内容 | 防げる攻撃 |
|---|---|---|
| **IdPによる認証の一元化と多要素認証** | すべてのクラウドサービスをIdPのSSOに統合し、多要素認証を必須にする | 盗んだパスワードでのログイン |
| **アクセスのたびの確認** | 利用者・端末の状態・場所でアクセスを判断する（条件付きアクセス） | 管理されていない端末からの接続 |
| **SWGを経由しない経路の遮断** | クラウド側でSWGの送信元IPアドレスだけを許可、端末のFWで直接の通信を禁止 | SWGの迂回 |
| **CASB** | クラウドの利用状況を可視化し、許可していないサービスやデータの持ち出しを止める | シャドーIT、情報の持ち出し |
| **ZTNA・最小権限** | アプリケーション単位でアクセスを許可する | 侵入後の横展開 |
| **ログの集約と監視** | IdP・SWG・EDRのログを集めて分析する | 不審な振る舞いの早期発見 |

## 6. 覚え方

- **ゼロトラストは「社員証を見せても、部屋に入るたびに確認する」**
- **SWGは「クラウドにあるプロキシ」、CASBは「クラウド利用の監視員」、ZTNAは「アプリごとの通行証（VPNの代わり）」、IdPは「本人確認の窓口」**
- **SASEは「SD-WAN＋セキュリティをクラウドでまとめて」**
- **SWGに移るときは「PACの向き先・ルート証明書・送信元IPの制限」**

## 7. 勉強の優先順位

1. プロキシからSWGへの移行で必要な作業（PAC、ルート証明書、送信元IPアドレスの制限）を説明できるようにする
2. 境界型防御の限界と、ゼロトラストの考え方を30〜40字で書けるようにする
3. SWG、CASB、ZTNA、IdPの役割の違い
4. SASEの意味
5. VPNとZTNAの違い
6. SSE、FWaaSは名前を知っている程度でよい

> [!tip] 得点につながる覚え方
> ゼロトラスト・SWGは**直近の午後で繰り返し出ている新しい定番**。構成図にSWGやIdPがあったら、**端末 → SWG → クラウドサービス**の経路と、**SWGを経由しない経路がふさがれているか**を確認する。
