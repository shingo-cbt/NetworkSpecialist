# IPsec まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. IPsecの基本（◎）

- **IPsec（Security Architecture for Internet Protocol）**：**IP（Internet Protocol）層で暗号化・改ざん検知・認証**を行うプロトコル群
- IP層で動くので、**上位のアプリケーションを問わず**すべての通信を保護できる
- 主な用途：**拠点間VPN（Virtual Private Network）**（インターネットVPN）、リモートアクセスVPN、クラウドとのVPN接続
- 構成するプロトコル

| プロトコル | 役割 | 運び方 | 出題度 |
|---|---|---|---|
| **IKE（Internet Key Exchange）** | 相手の認証と、暗号鍵の交換（SA（Security Association）の確立） | **UDP（User Datagram Protocol） 500** | ◎ |
| **ESP（Encapsulating Security Payload）** | **暗号化＋改ざん検知** | **IPのプロトコル番号50** | ◎ |
| AH（Authentication Header） | 改ざん検知だけ（**暗号化しない**）。IPヘッダも保護するため**NAT（Network Address Translation）と併用できない** | IPのプロトコル番号51 | ○ |

- **SA**：通信の両端で合意した、暗号方式・鍵などの取り決め。**片方向ごと**に作る（送信用と受信用の2つ）
- 午前の定番：「ESPとAHの違い」「IKEのポート番号」

## 2. トンネルモードとトランスポートモード（◎）

| | トンネルモード | トランスポートモード |
|---|---|---|
| 暗号化する範囲 | **元のIPパケット全体**（IPヘッダも） | IPパケットの**データ部分だけ** |
| 新しいIPヘッダ | **付ける**（VPN装置同士のアドレス） | 付けない（元のIPヘッダのまま） |
| 主な用途 | **拠点間VPN**（VPN装置〜VPN装置） | 端末同士の直接通信、GRE（Generic Routing Encapsulation） over IPsec |

```
トンネルモード：[新IPヘッダ][ESPヘッダ][元IPヘッダ][TCP/UDP][データ][ESPトレーラ・認証]
                                   └──────────暗号化────────────┘
```

- 拠点間VPNでは、社内のプライベートアドレスのパケットを丸ごと包み、**VPN装置のグローバルアドレス同士**で運ぶ
- 記述の型：「元のIPヘッダを含むパケット全体を暗号化し、VPN装置のアドレスを持つ新しいIPヘッダを付けて転送するため」
- 表の「GRE over IPsec」の補足：トランスポートモードにしたからマルチキャストが運べるのではない。**GREが先に、VPN装置どうしのユニキャストに包む**ので、IPsecは新しいIPヘッダを付けずに、中身だけ暗号化すれば済む（トンネルモードで包んでもよい）

## 3. IKEの流れ（○）

- **IKEv1**：2段階
  - **フェーズ1**：IKE SAを作る（相手の認証、鍵交換のための安全な通り道）
    - **メインモード**：互いのIDを暗号化して送る。**両端の IPアドレスが固定**のとき
    - **アグレッシブモード**：やり取りが少なく速いが、IDが平文。**片方のIPアドレスが変わる**（動的）拠点で使う
  - **フェーズ2**：IPsec SAを作る（実際のデータを暗号化する鍵）
- **IKEv2**：やり取りが整理され、少ない往復で確立できる。現在の主流（○、令和4年春 午後Ⅰ 問2）
  - **2段階**：① **IKE SA**を確立する（暗号化アルゴリズム、疑似ランダム関数、完全性アルゴリズム、Diffie-Hellmanグループ番号を決める）→ ② IKE SAを介して、認証と**Child SA**（データを運ぶSA。IKEv1のIPsec SAに当たる）を確立する
  - VPNが確立しないときは、**IKE SAとChild SAの状態**を確認して、どちらの段階で失敗しているかを特定する（「何の状態を確認するか」→ 機器ではなくSA）
  - **Diffie-Hellmanグループ番号**：鍵の生成に使うアルゴリズムと**鍵長**を決める番号。グループ1（768ビット）より14（2048ビット）の方が安全
- **ESPでパケットを作る手順**：① 元のパケットに**ESPトレーラ**を付けて**暗号化**する → ② **ESPヘッダ**（SAを識別するSPIなど）と**ESP認証データ**を付ける → ③ トンネルモードなら**新しいIPヘッダ**を付ける（カプセル化）
- **IPsecで使う鍵・仕組みは、役割ごとに別のもの**（○）

| 役割 | 使うもの | 中身 |
|---|---|---|
| ① **相手を確かめる**（認証） | **事前共有鍵** または **証明書**（公開鍵・秘密鍵） | 約束した相手かを確かめる。どちらか一方を選ぶ |
| ② **鍵を作る**（鍵交換） | **Diffie-Hellman** | 盗聴されても分からない形で、両端で同じ鍵を作る |
| ③ **データを暗号化する** | **共通鍵暗号**（AES（Advanced Encryption Standard）など） | ②で作った鍵で、実際のパケットを暗号化する |

- **相手の認証方法の比較**：事前共有鍵（PSK（Pre-Shared Key））と証明書

| | 事前共有鍵 | 証明書（公開鍵・秘密鍵） |
|---|---|---|
| 仕組み | 両端に**前もって同じ値**（合言葉）を設定し、同じ値を知っていることを示し合う。合言葉そのものは流さない | 各装置が**自分だけの秘密鍵**で署名し、相手は**証明書の公開鍵**で検証する |
| 長所 | 設定が簡単 | 合言葉を共有しないので、拠点が多くても管理しやすい。漏えいの影響は1台分 |
| 短所 | 拠点が増えると**ペアごとの管理**が大変。推測しやすい値だと、アグレッシブモードで**オフラインの総当たり**をされる | 証明書を発行・管理する仕組み（CA（Certificate Authority：認証局））が必要 |
| たとえ | **仲間うちで決めた合言葉** | **役所が発行した身分証** |

  - 注意：**事前共有鍵は、データを暗号化する鍵ではない**（暗号化の鍵は②で毎回作る）。「共通鍵」は暗号方式の種類の名前で、前もって設定する合言葉の名前は「事前共有鍵」
  - 無線LAN（Local Area Network）のWPA2-Personalのパスフレーズも事前共有鍵。WPA3のSAE（Simultaneous Authentication of Equals）は、この合言葉をオフラインで総当たりされにくくした方式 → [[WPA]]
  - 問われ方：「拠点が多い場合に、証明書を使う利点」→ ペアごとに鍵を共有・管理する必要がなく、漏えいの影響が1台に限られる。「事前共有鍵をペアごとに変える利点」→ 漏えいしたときの影響範囲を小さくできる
- 問われ方：「アグレッシブモードを使う理由」→ 拠点のIPアドレスが固定されていないため
- **相手のアドレスが動的な拠点**：VPNの相手（拠点のVPN装置）のアドレスがISP（Internet Service Provider）から動的に割り当てられると、宛先を決めた静的経路を書けない → インターネット側は**デフォルトルート**でISPのルータへ送る。記述の型：「ISPが割り当てる営業所のIPsecルータのIPアドレスが動的だから」

## 4. NATトラバーサル（◎）

- **ESPにはポート番号がない** → NAPT（Network Address Port Translation）はポート番号で複数の通信を区別するので、**ESPを変換できない**
- **NAT-T（NAT Traversal）**：ESPを**UDP 4500**に入れて送る → NAPTを越えられる
  - IKEの途中で、経路上にNATがあるかを検知して自動で切り替える
- **FW（Firewall）で許可する通信**：**UDP 500（IKE）、UDP 4500（NAT-T）、ESP（プロトコル番号50）**
- **許可する通信の考え方**（ルール表を埋めるときの手順）
  1. **まず鍵を決める**：IKEで相手を確認し、鍵を交換する → **UDP 500**
  2. **決めた鍵でデータを運ぶ**：ESPで暗号化して運ぶ。ESPはTCPでもUDPでもないので、FWでは**ポート番号ではなくプロトコル番号**（50）で許可する → **ESP（50）**
  3. **途中にNAPTがあるかを確認する**：ESPにはポート番号がないのでNAPTを越えられない → IKEの途中でNAPTを検知すると、ESPを**UDP 4500**に入れる方式（NAT-T）に切り替わる。以降のIKEも4500を使う → **UDP 4500**
  - NAT-Tに切り替わると生のESP（50）は使われなくなるが、NAPTのない経路では50を使うので、ルール表では**3つをセットで許可する**のが定番
  - 手順の型：「最初に何をして（鍵交換）、次に何を運び（データ）、途中に何があるか（NAPT）」の順に通信を分けて書き出す
- 記述の型：「ESPはポート番号を持たないため、NAPTで変換できないから。UDPでカプセル化してNAPTを通過させる」
- → [[NAT・NAPT]]

## 5. 午後で問われるテーマと記述の型

### ◎ MTUとMSS

- ESPのヘッダ・トレーラと新しいIPヘッダの分だけ、運べるパケットが小さくなる（数十バイト）
- 1500バイトのパケットが通らない → **PMTUD**（Path MTU Discovery）が必要、ICMP（Internet Control Message Protocol）を遮断していると失敗する
- 対策：VPN装置で**MSS（Maximum Segment Size）クランプ**
- → [[ICMP]]、[[TCP]]

### ◎ IPsecの上でルーティングプロトコルを動かす

- IPsec（ESP）は**マルチキャストを運べない**ことが多い → OSPF（Open Shortest Path First）のHelloなどが通らない
- よくある誤り（注意）
  - **トンネルモードのカプセル化は原因ではない**：拠点のPC同士の通信（ユニキャスト）は、トンネルモードで普通に届く。原因は、Helloの宛先が**マルチキャスト**（224.0.0.5）であること
  - **トランスポートモードに変えても解決しない**：どちらのモードでも、運べるのはユニキャストだけ
- 対策：**GRE over IPsec**（GREでマルチキャストを含むパケットを包み、それをIPsecで暗号化する）、または**ルートベースVPN**（トンネルインタフェース）の上でOSPF・BGP（Border Gateway Protocol）を動かす
- 2本のVPNで冗長化し、**ルーティングプロトコルで自動的に切り替える**
- 記述の型：「IPsecだけではマルチキャストパケットを転送できないため、GREでカプセル化してからIPsecで暗号化する」
- → [[OSPF]]、[[BGP]]

### ◎ IP-IP over IPsec（令和6年春 午後Ⅰ 問3）

- 構成：本社をハブ、支社をスポークとする**ハブアンドスポーク型**のVPN。各拠点のUTM（Unified Threat Management：統合脅威管理装置）どうしで、**IP-IP**（IP in IPトンネリング）でカプセル化してから、IPsecで暗号化する
- 鍵：UTMのペアごとに**事前共有鍵**を設定する（「共通鍵」は暗号方式の分類で、この鍵の名前ではない）
  - ペアごとに違う値にする効果：1つ漏れても、**影響範囲**がそのペアだけで済む
- 暗号化する範囲（IP-IPのヘッダーを外側に付けた後でIPsecをかける場合）

```
IP-IPでカプセル化：[IPヘッダー（IP-IP）][元のIPパケット]

トランスポートモード：[IPヘッダー][ESPヘッダー][元のIPパケット][ESPトレーラ][ESP認証データ]
                                              └────暗号化────────┘
トンネルモード：[新IPヘッダー][ESPヘッダー][IPヘッダー][元のIPパケット][ESPトレーラ][ESP認証データ]
                                          └─────────暗号化──────────────┘
```

  - トンネルモードは、**IPヘッダー（IP-IPのヘッダー）、元のIPパケット、ESPトレーラ**を暗号化する
  - IP-IPで外側のヘッダーを付けてあるので、トランスポートモードでも元のIPパケットは丸ごと暗号化される。トンネルモードにすると、ヘッダーがもう1つ増えるだけ
  - 設問文に「トランスポートモードでは〜を暗号化する」と書いてあれば、**それより広い範囲**がトンネルモードの答えになる
- **IP Unnumbered**：トンネルインタフェースに**IPアドレスの割当てを行わない**設定。ほかのインタフェースのアドレスを借りる。1対1の接続は相手が1つしかないので、アドレスがなくても転送できる（アドレスの節約、設定の簡素化）
  - 記述の型：「インタフェースにIPアドレスの割当てを行わない設定」
- **フラグメントの防止**：IP-IPとESPでヘッダーが増える → MTUを超えたパケットを、UTMが**分割**（フラグメント）して送ることになり、**転送負荷が増大**する → MSSクランプで、TCPの端末に最初から小さく送らせる → [[MTUとフラグメント]]
  - 「再送」が原因ではない。UTMの負荷の原因は、分割と組立ての処理

### ○ クラウドとのVPN接続

- クラウド側のVPNゲートウェイと、**2本のトンネル**を張って冗長化するのが一般的
- BGPで経路を交換し、障害時はもう一方のトンネルに切り替える（ECMP（Equal Cost Multi-Path）で両方を使うこともある）
- → [[ECMP]]

### ○ 障害の検知

- **DPD（Dead Peer Detection）**：相手のVPN装置が応答しなくなったことを検知し、SAを削除して再接続・切替を行う
- 無通信の時間が長いとNAPTの変換情報が消えるので、**NAT-Tのキープアライブ**を送る

### ○ リモートアクセスVPN：IPsecとTLS-VPNの比較

| | IPsec | TLS-VPN |
|---|---|---|
| 必要な通信 | UDP 500／4500、ESP | **TCP（Transmission Control Protocol） 443** |
| 出先のFW・プロキシ | 止められることがある | **通りやすい** |
| 端末 | 専用ソフトが必要 | ブラウザだけで使える方式もある |

- → [[TLS]]

## 6. 攻撃者の観点：どこを突くか

| 狙う所 | 攻撃のしかた | 成り立つ条件 |
|---|---|---|
| **事前共有鍵** | 推測しやすい鍵、**全拠点で同じ鍵**を使っている所を狙う。アグレッシブモードでは鍵から作ったハッシュ値を盗聴して**オフラインで総当たり**できる | 弱いPSK、アグレッシブモード |
| **VPN装置** | インターネットに公開されたVPN装置の**脆弱性**を突いて乗っ取り、社内に入り込む | 装置のソフトウェアを更新していない |
| **リモートアクセスの利用者** | 盗んだID・パスワード、盗難・紛失した端末で接続する | ID・パスワードだけで認証している |
| **VPNの先の社内** | VPNで入った後、社内を自由に移動する | VPN利用者に社内全体へのアクセスを許している |
| 再送攻撃 | 盗聴したパケットを再送する | （ESPのシーケンス番号で防がれる。△） |

## 7. 防御側に必要な対策

| 対策 | 内容 | 防げる攻撃 |
|---|---|---|
| **認証の強化** | 推測されにくいPSKを**拠点ごとに別々**に設定する、または**証明書**で認証する。アグレッシブモードを避ける | PSKの推測・解析 |
| **VPN装置の管理** | 脆弱性情報を確認し**速やかに更新**する。管理画面をインターネットに公開しない | 装置の乗っ取り |
| **多要素認証・端末の確認** | リモートアクセスでは**多要素認証**や**クライアント証明書**で、許可した利用者・端末だけ接続させる | 盗んだID・パスワードでの接続 |
| **接続後のアクセス制御** | VPN利用者がアクセスできるサーバ・ポートをFWで限定する | 侵入後の横展開 |
| **送信元の制限** | 拠点間VPNでは、相手のVPN装置のアドレスからだけIKEを受け付ける | 第三者からの接続試行 |

## 8. 覚え方

- **IPsecは「IP層の装甲車」**：中身（アプリ）を問わず、全部まとめて守る
- **IKEは「鍵の受け渡し（UDP 500）」、ESPは「暗号化して運ぶ（プロトコル50）」、AHは「封印だけ（51）」**
- **トンネルは「箱ごと別の箱に入れて送る」、トランスポートは「中身だけ鍵をかける」**
- **ESPにはポートがない → NAPTを越えられない → UDP 4500で包む（NAT-T）**
- **FWで開けるのは「500・4500・ESP」**
- **メインは「両方固定」、アグレッシブは「片方が動的」**
- **マルチキャストはIPsecに乗らない → GREで包んでから**

## 9. 勉強の優先順位

1. トンネルモードとトランスポートモードの違いを説明できるようにする
2. NAT-Tが必要な理由と、FWで許可する通信（UDP 500、UDP 4500、ESP）
3. ESPとAHの違い、IKEの役割
4. GRE over IPsecでルーティングプロトコルを動かす理由を30〜40字で書けるようにする
5. MTU（Maximum Transmission Unit）・MSSの問題、DPD、クラウドとの2本のトンネル
6. メインモードとアグレッシブモードの使い分け
7. IKEv2の2段階（IKE SA → Child SA）とESPの手順（暗号化 → ヘッダ付加）

> [!tip] 得点につながる覚え方
> IPsecは**拠点間接続・テレワーク・クラウド接続の問題で必ず出る**。構成図でVPN装置を見つけたら、**FWで開けるポート（500・4500・ESP）**、**NAPTの有無（NAT-Tが必要か）**、**ルーティングをどう流すか（GRE、BGP）**、**MTU**（MSSクランプ）の4点を確認する。
