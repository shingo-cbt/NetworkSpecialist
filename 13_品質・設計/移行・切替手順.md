# 移行・切替手順 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋め・並べ替えとして頻出／○ 午前・午後小問で出る／△ 深追い不要

機器の更改、サービスの移行、保守作業の**手順**を横断で整理する。令和7年春 午後Ⅰ 問1「企業ネットワークのルータ更改」では、OSPF（Open Shortest Path First）とVRRP（Virtual Router Redundancy Protocol）の理解と、**停止を伴わないルータ更改の手法**が問われた（IPA（情報処理推進機構）の出題趣旨より）。設計の考え方は [[ネットワーク設計]] を参照。

## 1. 基本の流れ（○）

| 段階 | やること |
|---|---|
| **① 事前準備** | 現状の調査（構成、設定、通信量）、新しい設定の作成、**検証環境での確認**、手順書と**切り戻し手順**の作成、関係者への連絡、作業時間帯の決定（利用の少ない夜間・休日） |
| **② 前倒しの作業** | 切替の前にやっておけること（DNS（Domain Name System）のTTL（Time To Live）を短くする、端末にルート証明書を配る、新しい機器を並べて設置しておく） |
| **③ 切替** | 冗長構成を使って**片系ずつ**、または**新旧を並行**させて切り替える |
| **④ 確認** | 疎通、経路、サービス、ログ・監視、冗長の切替試験 |
| **⑤ 切り戻しの判断** | 決めた時間までに問題が解決しなければ、**元の構成に戻す** |
| **⑥ 後片付け** | 旧機器の撤去、不要になったFW（Firewall）のルール・経路の削除、DNSのTTLを元に戻す |

## 2. 通信を止めない切替の原則（◎）

1. **先に通信を逃がしてから、作業する**
   - VRRP：作業する機器の**優先度を下げて**、もう一方をマスタにしてから止める
   - OSPF：作業する機器を通る経路の**コストを大きくして**、通信を迂回させてから止める
   - 負荷分散装置：作業するサーバへの**新規の振り分けを止め**、既存のセッションが終わってから止める
2. **片系ずつ作業する**：2台構成なら、1台ずつ順番に更改・確認する
3. **新旧を並行して動かし、少しずつ移す**：一部の拠点・一部の利用者から移行する（段階的移行）
4. **切替のタイミングを経路の優先度で制御する**：新しい経路の優先度を上げる（BGP（Border Gateway Protocol）の属性、OSPFのコスト、フローティングスタティック）
5. **時間のかかる準備は前倒し**：DNSのTTLの短縮、証明書の配布、キャッシュの有効期限

- 記述の型：「停止する機器を経由する経路のコストを大きくし、通信を他方の経路に迂回させてから停止することで、通信断を防ぐため」

## 3. 技術別の定番の手順（◎）

| 場面 | 定番の手順・ポイント | ノート |
|---|---|---|
| **ルータ・L3スイッチの更改（VRRP＋OSPF）** | ①旧マスタの優先度を下げてバックアップに切替 → ②OSPFのコストを上げて経路を迂回 → ③旧機器を停止し、新機器に交換（**VRID（Virtual Router Identifier）・仮想IP（Internet Protocol）・タイマ・OSPFの設定を既存と揃える**）→ ④新機器を経路に戻す → ⑤もう一方も同じ手順 | [[VRRP]]、[[OSPF]] |
| **サーバの移転（IPアドレスの変更）** | ①**数日前にDNSのTTLを短くする**（古いTTLの時間が過ぎるのを待つ）→ ②新サーバを用意 → ③DNSのレコードを新アドレスに変更 → ④旧サーバへのアクセスがなくなったら停止 → ⑤TTLを元に戻す | [[DNS]] |
| **サーバの保守（負荷分散装置の配下）** | 新規の振り分けを止める → 既存のセッションの終了を待つ → 停止・作業 → ヘルスチェックで正常を確認してから戻す | [[負荷分散装置]] |
| **FWの更改** | ルールの移行と確認、**セッション同期**の設定、行きと帰りの経路が新FWを通ることの確認（非対称経路に注意） | [[FW]] |
| **プロキシからSWG（Secure Web Gateway）へ** | ①**端末にSWGのルート証明書を先に配布** → ②一部の利用者から**PAC（Proxy Auto-Config）ファイル**の向き先をSWGに変更 → ③SaaS（Software as a Service）側の送信元IPアドレスの制限にSWGを追加 → ④全員に展開 → ⑤社内のプロキシを撤去 | [[ゼロトラスト・SASE]]、[[プロキシ]] |
| **RIP（Routing Information Protocol）からOSPFへ** | 境界のルータで相互に**再配布**しながら、少しずつOSPFに移す → 移行が終わったらRIPと再配布を削除 | [[再配布]] |
| **IPv4からIPv6へ** | **デュアルスタック**にして並行稼働 → IPv6の経路・FWのルール・監視も用意 → 問題がないことを確認 | [[IPv6移行技術]] |
| **WAN（Wide Area Network）の変更（IP-VPNからインターネットVPN（Virtual Private Network）・SD-WAN（Software-Defined WAN）へ）** | 新回線を並行して用意 → 経路の優先度で新回線へ切替 → 旧回線は一定期間バックアップに残す | [[BGP]]、[[SD-WAN]] |
| **VM（Virtual Machine）の移動（ライブマイグレーション）** | 移動先も同じL2のネットワーク、MTU（Maximum Transmission Unit）の確認、移動後にスイッチのMAC（Media Access Control）アドレステーブルを更新 | [[仮想化]] |

## 4. 確認の観点（○）

- **疎通**：ping、traceroute（経路が想定どおりか）
- **経路**：ルーティングテーブル、OSPFのネイバー、BGPのピアの状態
- **冗長**：VRRPのマスタ・バックアップの状態、**意図的に切替を起こして確認**（切替試験）
- **サービス**：利用者から見て使えるか（Webにアクセスする、メールを送る）
- **ログ・監視**：エラーが出ていないか、監視の対象に新機器を追加したか
- **性能**：通信量、遅延が想定どおりか

## 5. 切り戻し（○）

- **切り戻しの判断基準と期限**を事前に決める（「○時までに確認が終わらなければ戻す」）
- 戻せるように、**旧機器・旧設定を残しておく**（すぐに撤去しない）
- DNSのTTLを短くしておくのは、切り戻すときにも早く戻せるため
- 記述の型：「新構成で問題が発生した場合に、速やかに元の構成に戻せるようにするため」

## 6. 午後で問われるテーマと記述の型

| 問われ方 | 考え方 |
|---|---|
| 手順を**正しい順番に並べる** | 「先に通信を逃がす → 作業 → 確認 → 戻す」の順。準備（証明書、TTL）は最初 |
| 「**なぜこの順番なのか**」 | 逆の順番だと、何が起きるか（通信断、証明書のエラー、古いアドレスへのアクセス）を書く |
| 「作業の**前に確認すべきこと**」 | 現在のマスタ・経路、新機器の設定が既存と揃っているか |
| 「作業中に**通信断が起きない理由**」 | 冗長構成のもう一方に通信が流れているから |
| 「**更改後に起きた障害**の原因」 | 設定の不一致（VRID、タイマ、OSPFのエリア・認証）、FWのルールの移行漏れ、監視の登録漏れ |

- 記述の型（順番の理由）：「先に○○しておかないと、切替後に○○となり通信できなくなるから」

## 7. 覚え方

- **流れは「準備 → 前倒し → 切替 → 確認 → 戻す判断 → 片付け」**
- **通信を止めないコツは「先に逃がしてから止める」**：VRRPは優先度を下げる、OSPFはコストを上げる、LB（Load Balancer）は新規を止める
- **時間のかかる準備は前倒し**：TTLは数日前、証明書は先に配る
- **切り戻しのために、旧機器と旧設定は残す**

## 8. 勉強の優先順位

1. 「先に通信を逃がしてから止める」手順（VRRP、OSPF、LB）を30〜40字で書けるようにする
2. ルータ更改（VRRP＋OSPF）の手順の順番と理由
3. サーバ移転でDNSのTTLを先に短くする理由
4. プロキシからSWGへの移行の順番（証明書を先に配る）
5. 確認の観点と、切り戻しの準備

> [!tip] 得点につながる覚え方
> 移行の問題は、**「この手順を逆にしたら何が起きるか」**を考えると答えが出る。手順を並べ替える設問では、まず「通信を逃がす操作」と「元に戻す操作」の位置を決め、その間に作業と確認を入れる。
