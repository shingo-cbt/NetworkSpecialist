# ネットワーク監視 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

監視に使うプロトコルの詳細は [[SNMP]]、[[Syslog]]、[[NTP]] を参照。このファイルは**何を、どう監視するか（設計）**をまとめる。

## 1. 監視の種類（◎）

| 監視の種類 | 方法 | 分かること | 分からないこと |
|---|---|---|---|
| **死活監視** | **ping（ICMP（Internet Control Message Protocol））**を定期的に送る | 機器・インタフェースが応答するか | サービス（アプリケーション）が動いているか |
| **ポート監視** | TCP（Transmission Control Protocol）で接続できるか確かめる | サービスのプロセスが待ち受けているか | 正しく動いているか |
| **サービス監視** | HTTP（Hypertext Transfer Protocol）で実際にページを要求するなど | **利用者から見て使えるか** | − |
| **リソース監視** | **SNMP（Simple Network Management Protocol）**のポーリングで、CPU（Central Processing Unit）・メモリ・**インタフェースの通信量・エラー数**を取る | 負荷が高い、回線が混んでいる | − |
| **イベント監視** | **SNMPのトラップ**、**Syslog** | リンクダウン、再起動、エラーの発生 | − |
| **フロー監視** | **NetFlow**、**sFlow**、IPFIX（IP Flow Information Export） | **誰が誰と、どのくらい通信しているか**（送信元・宛先・ポート別の量） | パケットの中身 |
| パケットキャプチャ | **ミラーポート**、TAP（Test Access Point）で通信を複製して記録する | パケットの中身まで | 大量の通信では保存が大変 |

- **負荷分散装置のヘルスチェックと同じ考え方**：L3（ping）だけでは、アプリケーションの異常は分からない → [[負荷分散装置]]

### フロー監視：NetFlowとsFlow（○）

| | NetFlow | sFlow |
|---|---|---|
| 方式 | 機器が**フロー（同じ送信元・宛先・ポートの通信のまとまり）ごとに集計**して送る | パケットを**一定の割合で抜き取って（サンプリング）**送る |
| 正確さ | 正確 | 統計的（概算） |
| 機器の負荷 | 大きい | 小さい |

- 用途：通信量が急に増えた原因の特定（どの端末が、どこと）、不審な通信（大量のデータ送信）の発見
- 記述の型：「フローごとに送信元・宛先・通信量を集計することで、帯域を占有している通信を特定できるため」

## 2. 監視の設計（◎）

### ① しきい値とアラート

- 「回線使用率が80%を5分以上超えたら通知」のように、**しきい値と継続時間**を決める
- 一瞬の変化で通知が大量に出ないようにする（誤報・通知の洪水）

### ② 冗長構成の監視

- **VRRP（Virtual Router Redundancy Protocol）の仮想IP（Internet Protocol）アドレスだけを監視すると、片方が故障しても気づかない** → **実機のアドレスもそれぞれ監視**する
- **待機系（バックアップ）は普段使われないので、故障に気づきにくい** → 定期的に状態を確認する
- 記述の型：「仮想IPアドレスはマスタが応答するため、バックアップ機が故障しても検知できないから」
- → [[VRRP]]

### ③ 監視の通信の経路（管理ネットワーク）

- 業務の通信と同じ経路で監視すると、**ネットワークの障害時に監視の通信も届かず**、状況が分からなくなる
- **管理用のVLAN（Virtual LAN）**を分ける、**アウトオブバンド管理**（業務とは別の回線・LTE（Long Term Evolution）回線などで機器のコンソールにつなぐ）
- 記述の型：「業務用のネットワークに障害が発生しても、別経路で機器に接続して状況を確認・復旧できるようにするため」

### ④ 監視がうまくいかない原因

- **FW（Firewall）でpingやSNMPを止めている** → 正常なのに「停止」と判定される → 監視サーバからの通信を許可する → [[FW]]
- **機器がICMPに応答しない設定**、ICMPの応答の優先度が低く、負荷が高いと応答が遅れる
- ポーリングの間隔が長すぎて、短い障害（瞬断）を見逃す
- SNMPの**32ビットのカウンタの一周**で通信量を誤る → [[SNMP]]

### ⑤ 時刻の同期とログの保管

- 全機器をNTP（Network Time Protocol）で同期し、ログをSyslogサーバに集める → 障害・事故の調査ができる
- → [[NTP]]、[[Syslog]]

## 3. 午後で問われるテーマ

### ◎ 障害の検知と切り分け

- 「どの監視で、何が分かるか」を問う：pingは通るのにWebが見られない → サービスの障害、など
- 障害の場所を、**下の層から順に**切り分ける（物理 → L2 → L3 → サービス）→ [[HTTP]]

### ◎ 新しい構成を導入したときの監視項目

- クラウド、SD-WAN（Software-Defined WAN）、冗長構成を導入したときに、**追加すべき監視**（回線ごとの品質、トンネルの状態、待機系の状態）を問う

### ○ 監視サーバの冗長化と監視

- 監視サーバが止まると、障害に気づけない → 冗長化する、外部のサービスで監視サーバ自体を監視する

## 4. 覚え方

- **監視は「生きているか（ping）→ 席にいるか（ポート）→ 仕事ができるか（サービス）」**
- **SNMPのポーリングは「健康診断」、トラップとSyslogは「急病の通報」、フローは「誰と何をしていたかの記録」**
- **NetFlowは「全部集計」、sFlowは「抜き取り調査」**
- **仮想IPだけ見ていると、控えの故障に気づかない**
- **監視の通り道は業務と分ける**（管理VLAN、アウトオブバンド）

## 5. 勉強の優先順位

1. 監視の種類ごとに、分かること・分からないことを説明できるようにする
2. 冗長構成で実機のアドレスも監視する理由を30〜40字で書けるようにする
3. 管理ネットワーク（管理VLAN、アウトオブバンド）を分ける理由
4. NetFlowとsFlowの違い、フロー監視でできること
5. 監視がうまくいかない原因（FW、ICMPの応答、カウンタ）
6. ミラーポート・TAPは名前と用途を知っている程度でよい

> [!tip] 得点につながる覚え方
> 監視の問題は、**「その監視方法で、その障害を検知できるか」**を1つずつ確かめる。特に冗長構成では「普段使われていない側の故障」を見落とさない。
