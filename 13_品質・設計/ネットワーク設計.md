# ネットワーク設計 まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

各ノートの「午後で問われるテーマ」に分かれている設計の考え方を、横断で整理する入口のノート。移行・更改の手順は [[移行・切替手順]] を参照。

## 1. 設計の観点（○）

午後の問題文に書かれた「要件」は、ほぼ次のどれかに当てはまる。要件を読んだら、どの観点の話かに印を付ける。

| 観点 | 問題文での書かれ方の例 | 主な手段 |
|---|---|---|
| **可用性** | 「1台が故障しても業務を継続したい」「停止時間を短く」 | 冗長化、切替の高速化 |
| **性能** | 「Web会議が途切れる」「夜間のバックアップが終わらない」 | 帯域の増強、QoS（Quality of Service）、経路の分散 |
| **セキュリティ** | 「部署間の通信を制限したい」「不正な端末を接続させない」 | セグメント分割、FW（Firewall）、認証 |
| **運用性** | 「設定変更の手間を減らしたい」「障害にすぐ気づきたい」 | 一元管理、監視、自動化 |
| **拡張性** | 「将来、拠点や端末が増える」 | アドレスの余裕、集約しやすい割り当て |
| **コスト** | 「回線費用を抑えたい」 | インターネットVPN（Virtual Private Network）、SD-WAN（Software-Defined WAN） |

- 観点どうしは**トレードオフ**になることが多い（例：ローカルブレイクアウトは性能が上がるが、セキュリティ対策が抜ける）→ 「〜の代わりに何が必要か」まで答える

## 2. 階層構成とセグメント分割（○）

### 階層構成

```
        [インターネット] ─ [FW] ─ DMZ（公開サーバ）
                            │
                    [コアスイッチ（L3）×2]      ← ルーティング、冗長化の中心
                      │            │
              [フロアスイッチ（L2）]  [サーバ用スイッチ]   ← 端末・サーバの収容
```

- **コア**：高速な転送と冗長化（L3スイッチ2台、VRRP（Virtual Router Redundancy Protocol）・OSPF（Open Shortest Path First）、スタック）
- **アクセス（フロア）**：端末の収容、VLAN（Virtual LAN）、802.1X、PoE（Power over Ethernet）
- **管理ネットワーク**：機器の管理・監視の通信を業務と分ける → [[ネットワーク監視]]

### セグメント（ゾーン）の分け方

- **部署・用途ごとにVLANとサブネットを分ける**（業務、サーバ、管理、ゲスト、IP（Internet Protocol）電話）→ [[VLAN]]
- **外部に公開するサーバはDMZ（DeMilitarized Zone）**、社内のサーバは内部に置く → [[FW]]
- 分けたセグメントの間の通信は、L3スイッチやFWで**必要なものだけ許可**する

## 3. アドレス設計（◎）

- 台数から**プレフィックス長**を決める。**ゲートウェイの分**も数える（VRRPなら、仮想IP＋実機2台の**3つ**）
- **将来の増加分**を見込む
- **拠点・用途ごとに連続した範囲**を割り当て、**経路を集約できる**ようにする
- **固定アドレス（サーバ、ネットワーク機器）とDHCP（Dynamic Host Configuration Protocol）で配る範囲を分ける**
- クラウドや合併先と**アドレスが重ならない**ようにする（重なると接続できない、NAT（Network Address Translation）が必要になる）
- → [[IPアドレスとサブネット]]

## 4. 冗長化設計（◎）

### 層ごとの冗長化の手段

| 対象 | 手段 | 切替にかかる時間の目安 | ノート |
|---|---|---|---|
| インターネット・WAN（Wide Area Network）回線 | 2回線（**別の事業者・別の経路**）、BGP（Border Gateway Protocol）、フローティングスタティック | 数秒〜（BFD（Bidirectional Forwarding Detection）で短縮） | [[BGP]]、[[スタティックルーティング]] |
| デフォルトゲートウェイ | **VRRP**、スタック | 約3秒 | [[VRRP]] |
| L3の経路 | **OSPF**、ECMP（Equal Cost Multi-Path） | デッド間隔40秒（BFDで短縮） | [[OSPF]]、[[ECMP]] |
| L2の経路 | **STP（Spanning Tree Protocol）／RSTP（Rapid STP）**、**スタック＋リンクアグリゲーション** | STP 30〜50秒、RSTP数秒、LAG（Link Aggregation Group）ほぼ即時 | [[STP]]、[[リンクアグリゲーション]] |
| サーバ | **負荷分散装置**、クラスタ | ヘルスチェックの間隔 | [[負荷分散装置]] |
| FW | アクティブ／スタンバイ＋**セッション同期** | 数秒 | [[FW]] |
| DNS（Domain Name System）、DHCP | 複数台、スコープの分割 | − | [[DNS]]、[[DHCP]] |

### 冗長化の落とし穴（◎：午後で最も問われる）

1. **単一障害点が残っている**：冗長化していない機器（FW1台、回線1本、電源1系統）が全体の可用性を決めてしまう → [[稼働率]]
2. **共通の原因で両方が止まる**：同じ事業者の2回線、同じ電源・同じラック、同じ配管を通る回線は、**同時に止まる**ことがある
3. **障害を検知できない**：VRRPは上流の回線だけが切れても切り替わらない（→ トラッキング）、スタティック経路はネクストホップの先の障害を検知できない（→ 経路監視）
4. **行きと帰りの経路が揃わない**：ステートフルなFWが2台あると、戻りのパケットが破棄される（→ VRRPのマスタとOSPFのコスト、STPのルートブリッジを揃える）
5. **待機系の故障に気づかない**：普段使われない機器・経路は監視されにくい（→ 実機のアドレスも監視する、定期的な切替試験）
6. **切替で別の問題が起きる**：プリエンプトによる2回目の瞬断、切替後にGARP（Gratuitous ARP）が届かない機器

- 記述の型：「冗長化されていない○○が単一障害点となり、○○の障害時に全体が停止するから」

## 5. 性能設計（○）

- **ボトルネックを探す**：速いLAN（Local Area Network）から遅いWANへの出口、FW・プロキシ・VPN装置の処理能力、本社への集中
- 帯域の見積もり：**ピーク時**の通信量で見積もり、**利用率に余裕（70〜80%以下）**を持たせる（利用率が1に近いと待ち時間が急増する）→ [[伝送時間とスループット]]
- **1つの通信は1本分の帯域まで**（LAG・ECMPで束ねても、1つの大きな転送は速くならない）
- 遅延の大きい回線では、**TCP（Transmission Control Protocol）のウィンドウサイズ ÷ RTT（Round Trip Time）**で速度が頭打ちになる → [[TCP]]
- 混雑する区間ではQoSで重要な通信を優先する → [[QoS]]

## 6. セキュリティ設計と運用性（○）

- **最小権限**：通信は必要なものだけ許可（FWのルール、VLAN間のアクセス制御）
- **接続の認証**：802.1Xで、許可した利用者・端末だけをネットワークにつなぐ → [[IEEE802.1X]]
- **境界だけに頼らない**：クラウド・テレワークの増加 → ゼロトラスト → [[ゼロトラスト・SASE]]
- **運用性**：監視（SNMP（Simple Network Management Protocol）、Syslog）、時刻同期（NTP（Network Time Protocol））、一元管理（SDN（Software-Defined Networking）、SD-WAN）、構成情報の記録

## 7. 午後で問われるテーマと記述の型

| 問われ方 | 考え方 |
|---|---|
| 「この構成の**単一障害点**はどこか」 | 1台・1本しかない機器・回線を探す |
| 「この障害が起きたとき、**通信はどの経路になるか**」 | 経路の判定（ロンゲストマッチ → 信頼度 → メトリック）、VRRP・STPの切替を追う → [[IGPとEGP]] |
| 「冗長化しているのに**切り替わらなかった**理由」 | 4章の落とし穴3（障害を検知できない） |
| 「**通信できなくなった**理由」 | 非対称経路、MTU（Maximum Transmission Unit）、FWのルール、NAPT（Network Address Port Translation） |
| 「要件を満たすために**変更すべき設定**」 | どの機器の、何の設定を、どう変えるか（具体的に） |

- 記述のコツ：**「どの機器の」「何が」「どうなるから」**を具体的に書く。「冗長性が向上する」のような結果だけの書き方は避ける

## 8. 覚え方

- **要件を読んだら「可用性・性能・セキュリティ・運用性・拡張性・コスト」のどれかに印**
- **冗長化の落とし穴は「残った1台、同時に止まる2本、気づけない障害、揃わない行き帰り、見ていない待機系」**
- **アドレスは「余裕を持って、連続して、重ねない」**
- **ボトルネックは「速い所から遅い所への出口」**

## 9. 勉強の優先順位

1. 冗長化の落とし穴（特に単一障害点、障害を検知できない、行きと帰りの経路）を、構成図で見つけられるようにする
2. 層ごとの冗長化の手段と、切替時間の目安
3. アドレス設計の考え方（ゲートウェイの分、集約、重ならない）
4. 性能のボトルネックの見つけ方
5. 設計の観点とトレードオフ

> [!tip] 得点につながる覚え方
> 午後の構成図は、まず**「1つしかないもの」に丸を付け、「2つあるものは、どうやって切り替わるか（何で障害を検知するか）」**を書き込む。設問の多くは、この2点のどちらかを突いてくる。
