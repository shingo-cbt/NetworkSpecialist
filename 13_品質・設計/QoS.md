# QoS まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. QoSの基本（○）

- 通信の**品質（遅延・揺らぎ・損失・帯域）**を、通信の種類に応じて確保する仕組み
- 品質の4要素

| 要素 | 意味 | 影響を受けやすい通信 |
|---|---|---|
| 遅延 | 送信から到着までの時間 | 音声、Web会議 |
| ジッタ（揺らぎ） | 遅延のばらつき | 音声、映像 |
| パケット損失 | 途中で廃棄される | 音声（再送しない）、TCP（Transmission Control Protocol）はスループット低下 |
| 帯域 | 単位時間に送れる量 | 動画、大容量転送 |

- **QoS（Quality of Service）は輻輳（混雑）している出力インタフェースでしか効かない** → 回線に余裕があれば何もしなくても品質は出る
- 2つの考え方
  - **IntServ**（Integrated Services）：通信ごとに**RSVP**（Resource Reservation Protocol）で経路上の帯域を予約する。規模が大きいと各機器の負担が重い（△）
  - **DiffServ**（Differentiated Services）：パケットに**クラスを示す値（DSCP：Differentiated Services Code Point）を付け**、各機器がその値を見て扱いを変える。現在の主流（◎）

## 2. 処理の流れ（◎）

1. **分類**：アドレス、ポート番号、プロトコルなどで通信をクラスに分ける
2. **マーキング**：クラスを示す値（CoS（Class of Service）、DSCP）をヘッダに書き込む
3. **ポリシング／シェーピング**：決めた帯域を超えた分を処理する
4. **キューイング（スケジューリング）**：クラスごとのキューから送り出す順番を決める
5. **輻輳回避**：キューがあふれる前に一部を捨てる（RED（Random Early Detection）／WRED（Weighted RED））

- 分類とマーキングは**ネットワークの入口（端末の近く）**で一度行い、以降の機器はマーキングの値だけ見る
- 端末が勝手に高い優先度を付けることがあるので、信頼できる境界（**トラストバウンダリ**）で値を付け直す（○）

## 3. マーキング（◎）

| 層 | フィールド | ビット数 | 値の範囲 | 場所 |
|---|---|---|---|---|
| L2 | **CoS**（IEEE802.1p） | 3 | 0〜7 | **802.1QのVLAN（Virtual LAN）タグ**内 |
| L3 | IP（Internet Protocol） Precedence | 3 | 0〜7 | ToS（Type of Service）フィールドの上位3ビット（旧方式） |
| L3 | **DSCP** | 6 | 0〜63 | ToSフィールドの上位6ビット（DSフィールド） |

- CoSは**VLANタグがある区間でしか使えない**（タグなしのアクセスポートやルータ越しでは消える）→ ルータを越えるならDSCP
- 主なDSCP値（PHB：Per-Hop Behavior）

| PHB | DSCP値 | 用途 | 出題度 |
|---|---|---|---|
| **EF**（Expedited Forwarding） | **46** | 音声。低遅延・低損失で最優先 | ◎ |
| **AF**xy（Assured Forwarding） | AF11〜AF43 | 帯域を保証したい業務通信。x＝クラス（1〜4）、y＝廃棄優先度（1〜3、大きいほど捨てられやすい） | ○ |
| CS（Class Selector） | 8の倍数（CS1＝8 … CS7＝56） | IP Precedenceとの互換用 | △ |
| BE（Best Effort） | 0 | 一般通信 | ○ |

- 「EF＝46」は穴埋めで出る。AFは**値＝8x＋2y**で計算できる（AF41＝34）

## 4. キューイング（◎）

| 方式 | 仕組み | 欠点 | 出題度 |
|---|---|---|---|
| FIFO（First In, First Out） | 到着順に送る | 優先制御なし | △ |
| **PQ**（Priority Queuing、完全優先） | 高優先キューが空になるまで低優先キューは送らない | **低優先が全く送れなくなる（帯域枯渇）** | ◎ |
| **WRR**（Weighted Round Robin）／WFQ（Weighted Fair Queuing） | 重み（比率）に応じて各キューから順番に送る | 音声に必要な低遅延は保証しにくい | ○ |
| CBWFQ（Class-Based Weighted Fair Queuing） | クラスごとに最低保証帯域を決めて送る | 同上 | ○ |
| **LLQ**（Low Latency Queuing） | **PQ＋CBWFQ**。音声は優先キューで即送るが、**上限帯域を決めて**他を圧迫しない | − | ○ |

- 問われ方：「PQで生じる問題」→ 記述の型：「優先度の高い通信が多いと、優先度の低い通信がいつまでも送信されないから」

## 5. ポリシングとシェーピング（◎）

| | ポリシング | シェーピング |
|---|---|---|
| 超過分の扱い | **廃棄**（またはマーキング値を下げる） | **バッファに溜めて後で送る** |
| 遅延 | 増えない | **増える** |
| 出力の形 | ギザギザのまま | 平滑化される |
| 主な使い所 | 通信事業者の入口、受信側 | **契約帯域より速いインタフェースからの送信側** |

- 仕組みはどちらも **トークンバケット**（トークンが溜まっている分だけ送れる）
- ◎の定番：**LAN（Local Area Network）は1Gbps、WAN（Wide Area Network）の契約は100Mbps** のような構成
  - ルータは1Gbpsで送り出せてしまう → 事業者側の**ポリシングで超過分が廃棄**される
  - 対策：ルータの出力で**契約帯域にシェーピング**する
  - 記述の型：「契約帯域を超えた分が事業者網で廃棄されないよう、送信側で契約帯域以下に平滑化するため」
- 回線自体に輻輳がなくても**ルータの中でキューが溜まらない**と優先制御は効かない → シェーピングと優先制御はセットで設定する

## 6. 輻輳回避（○）

- **テールドロップ**：キューがあふれたら後から来たパケットを全部捨てる
  - 多数のTCPが同時に送信量を下げ、同時に増やす → **TCPグローバル同期**で回線の利用率が波打つ
- **RED**：キューが溜まり始めたら**確率的に早めに捨てる** → TCPごとに減速のタイミングがずれる
- **WRED**：REDを優先度（DSCP、AFの廃棄優先度）ごとに重み付けする
- 記述の型：「複数のTCPコネクションが同時に輻輳制御を行い、回線の利用効率が下がるのを防ぐため」

## 7. 午後で問われるテーマと記述の型

### ◎ IP電話（VoIP）の品質確保

- 音声は**遅延・ジッタ・損失に弱く、再送しても意味がない**（UDP（User Datagram Protocol）／RTP（Real-time Transport Protocol））
- 目安：片方向の遅延 **150ms以内**（ITU-T G.114）
- ジッタは受信側の**ジッタバッファ**で吸収するが、バッファ分だけ遅延が増える
- 必要帯域の計算（G.711、20ms間隔）
  - 音声ペイロード：64kbps × 20ms ＝ 160バイト
  - IP／UDP／RTPヘッダ：20＋8＋12 ＝ 40バイト
  - 1秒に50パケット → (160＋40) × 8 × 50 ＝ **80kbps（IPレベル）**。L2ヘッダを足すとさらに増える
- 設定：音声をEF（46）でマーキング → LLQで優先キュー → WAN側でシェーピング
- 問われ方：「同時通話数から必要帯域を求める」「音声品質が劣化する原因」

### ◎ VPN・トンネルとQoS

- IPsec（Security Architecture for Internet Protocol）やGRE（Generic Routing Encapsulation）でカプセル化すると、**元のIPヘッダが内側に隠れ、外側ヘッダでしか分類できない**
  - 対策：**元のDSCP値を外側ヘッダにコピーする**（ToSリフレクト）、または暗号化前に分類する
- IPsecはESP（Encapsulating Security Payload）で**ポート番号も暗号化される** → 外側ではポート番号での分類ができない
- 記述の型：「カプセル化により、中継ルータが元のパケットのヘッダを参照できなくなるから」
- → [[IPsec]]

### ○ マーキング値の付け直し

- 端末が付けた値は信用しない → アクセススイッチで **値を上書き（リマーキング）** する
- 事業者網や他社のネットワークに出入りするときも、取り決めに合わせて付け直す
- L2スイッチのCoSとルータのDSCPを**相互に変換（マッピング）**する

### ○ 帯域制御で業務通信を守る

- バックアップ、OS（Operating System）アップデート、動画など大量の通信が業務通信を圧迫する
- 対策：その通信を**低優先クラス**にする、**ポリシングで上限をかける**、夜間に実行する
- 問われ方：「業務システムの応答が遅くなる原因と対策」

## 8. 覚え方

- **「QoSは混んだ出口でしか効かない」**：空いている回線、入力側では効果がない
- **ポリシングは「切る」、シェーピングは「貯める」**：遅延が増えるのはシェーピング
- **「1Gで出して100Mで契約、だからシェーピング」**：WAN接続の定番パターン
- **EFは「46（しろ）＝音声は白線の優先レーン」**
- **AFは「8x＋2y」**、xが大きいほど優先、yが大きいほど捨てられやすい
- **PQは「VIPしか通さない入口」**：VIPが多いと一般客が永遠に入れない → LLQでVIPの人数に上限
- **CoSは3ビットでVLANタグの中、DSCPは6ビットでIPヘッダの中**：ルータを越えるのはDSCPだけ

## 9. 勉強の優先順位

1. ポリシングとシェーピングの違い、WAN接続でシェーピングが要る理由を30〜40字で書けるようにする
2. PQの帯域枯渇とLLQで解決する流れを押さえる
3. マーキング（CoS／DSCP、EF＝46）と、どこで付けるか（トラストバウンダリ）
4. 音声の必要帯域の計算を1回自分で解いておく
5. IPsec・GREとQoSの組合せ（外側ヘッダにDSCPをコピー）
6. RED／WREDとTCPグローバル同期は午前レベルで押さえればよい

> [!tip] 得点につながる覚え方
> 午後のQoSは、**「どこが混むか（速いLAN→遅いWANの出口）」を図から見つけ、そこに何を設定するか**で問われる。方式名の暗記より、パケットがどのインタフェースで溜まるかを追いかける。
