# WPA まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. WPAの基本（○）

- 無線LAN（Local Area Network）の**暗号化と認証**の規格（Wi-Fi Allianceが認定。元になる規格はIEEE802.11i）
- 世代

| 世代 | 暗号方式 | ポイント | 出題度 |
|---|---|---|---|
| WEP（Wired Equivalent Privacy） | RC4 | 短時間で鍵が解読される。**使ってはいけない** | ○（誤りの選択肢） |
| WPA（Wi-Fi Protected Access） | **TKIP**（Temporal Key Integrity Protocol、RC4ベース） | WEPからの移行用の暫定規格 | △ |
| **WPA2** | **CCMP（Counter mode with CBC-MAC Protocol、AES：Advanced Encryption Standard）** | 長く標準だった方式 | ◎ |
| **WPA3** | CCMP（AES）／GCMP-256 | **SAE**（Simultaneous Authentication of Equals）、**PMF（Protected Management Frames）必須**、192ビットモード | ◎ |

- 午前の定番：「WPA2で使われる暗号方式」→ AES（CCMP）。「WEPの脆弱性」
- TKIPは11n以降の高速通信に使えない（11nはCCMPが前提）（△）

## 2. パーソナルとエンタープライズ（◎）

| | パーソナル（PSK：Pre-Shared Key） | エンタープライズ |
|---|---|---|
| 認証 | **全員で同じパスフレーズ**（事前共有鍵） | **IEEE802.1X**（RADIUS（Remote Authentication Dial In User Service）で利用者ごとに認証） |
| 鍵の元（PMK：Pairwise Master Key） | パスフレーズとSSID（Service Set Identifier）から作る | EAP（Extensible Authentication Protocol）認証の結果から**利用者ごと・接続ごとに**作る |
| 必要な設備 | AP（Access Point）だけ | RADIUSサーバ、（EAP-TLS（EAP-Transport Layer Security）なら）証明書 |
| 向く場所 | 家庭、小規模 | 企業 |

- **パーソナルの問題点**（午後の定番）
  - パスフレーズが漏れたら、**全端末の設定を変える**必要がある
  - 退職者もパスフレーズを知っている
  - **誰が接続しているか個人を特定できない**
  - 同じパスフレーズを知る人は、他人の通信を復号できる可能性がある
  - 4ウェイハンドシェイクを盗聴されると、**オフラインで辞書攻撃**される（WPA2-Personal）
- 記述の型（エンタープライズにする理由）：「利用者ごとに認証するため、退職者の利用を停止でき、接続した個人を特定できるから」
- → [[IEEE802.1X]]

## 3. 鍵の作り方：4ウェイハンドシェイク（◎）

- **PMK（ペアワイズマスタ鍵）**：鍵の元
  - パーソナル：パスフレーズとSSIDから計算
  - エンタープライズ：802.1X（EAP）の認証成功時にRADIUSサーバとAPが共有する
- **4ウェイハンドシェイク**：PMKを直接は送らずに、APと端末が互いに乱数（ANonce、SNonce）を交換して、次の鍵を作る
  - **PTK**（Pairwise Transient Key、ペアワイズ一時鍵）：その端末とAPのユニキャスト通信用。**接続ごとに変わる**
  - **GTK**（Group Temporal Key、グループ一時鍵）：ブロードキャスト・マルチキャスト用。APが全端末に配る
- 4ウェイハンドシェイクで、**互いが同じPMKを持っていること**（＝正しく認証されたこと）も確認できる
- 記述の型：「PMKをもとに、APと端末の間で通信ごとの暗号鍵（PTK）を生成するため」

## 4. WPA3の新機能（○）

| 機能 | 内容 |
|---|---|
| **SAE**（パーソナル） | パスフレーズを使った新しい鍵交換。**オフラインの辞書攻撃に強い**。パスフレーズが後で漏れても、過去の通信は復号できない（前方秘匿性） |
| **PMF**（管理フレーム保護、802.11w） | **切断（デオーセンティケーション）フレームの偽装**などを防ぐ。WPA3では必須 |
| 192ビットモード（エンタープライズ） | より強い暗号（GCMP-256など）を使う |
| **OWE**（Enhanced Open） | パスワードなしの公衆無線LANでも、通信を端末ごとに暗号化する |

- 問われ方：「WPA3-PersonalでSAEを使う利点」「PMFで防げる攻撃」
- 記述の型（PMF）：「管理フレームを保護し、偽装した切断フレームによる通信妨害を防ぐ」

## 5. 午後で問われるテーマと記述の型

### ◎ 認証方式の選択

- 社員用：**WPA2／WPA3エンタープライズ**（802.1X、EAP-TLSなど）
- ゲスト用：**別SSID・別VLAN**（Virtual LAN）にして社内LANと分離、**APアイソレーション**で端末同士の通信を禁止、パーソナルまたはOWE＋Web認証
- 問われ方：「社員用とゲスト用でSSIDを分ける理由」「パーソナルでは不十分な理由」

### ○ ローミングと再認証

- エンタープライズでAPを移るたびに802.1X認証をやり直すと、数百ms〜数秒かかり、音声通話が途切れる
- 対策：**PMKキャッシュ**（以前接続したAPに戻るとき、PMKを再利用）、**事前認証**、**802.11r（FT：Fast BSS Transition）**
- → [[IEEE802.11]]、[[IEEE802.1X]]

### ○ 古い方式の混在

- WEPやTKIPにしか対応しない古い端末があると、その端末のためにSSIDを分ける、または端末を更新する
- WPA2とWPA3の**移行モード**（両方を受け付ける）がある（△）

### △ その他

- **SSIDステルス、MAC（Media Access Control）アドレスフィルタだけでは不十分**（IEEE802.11.mdを参照）
- KRACK（Key Reinstallation Attack）：WPA2の4ウェイハンドシェイクの脆弱性（パッチで対応）

## 6. 覚え方

- **世代と暗号は「WEP＝RC4（ダメ）、WPA＝TKIP（つなぎ）、WPA2＝AES、WPA3＝SAE」**
- **パーソナルは「家の合鍵を全員に配る」、エンタープライズは「社員証で一人ずつ入館」**
  - 合鍵は、1本なくすと全部の鍵を替える必要がある
- **4ウェイは「PMK（元の鍵）は送らず、乱数を交換して、その場限りの鍵（PTK）を作る」**
- **PTKは個別（Pairwise）、GTKは全体（Group）**
- **PMFは「管理フレームにも封をする」**：偽の切断命令を防ぐ

## 7. 勉強の優先順位

1. パーソナルとエンタープライズの違いと、パーソナルの問題点を30〜40字で書けるようにする
2. 4ウェイハンドシェイクの目的（PMK → PTK・GTK）を説明できるようにする
3. WPA2とWPA3の違い（SAE、PMF）
4. ゲスト用無線LANの分離方法
5. ローミング時の再認証の短縮
6. TKIP、KRACK、192ビットモードは名前を知っている程度でよい

> [!tip] 得点につながる覚え方
> WPAは単独より、**無線LAN導入の問題で**「どの認証方式にするか、その理由」として出る。午後では「エンタープライズ＝802.1X＝RADIUS」とつなげて、IEEE802.1X.mdとセットで復習する。
