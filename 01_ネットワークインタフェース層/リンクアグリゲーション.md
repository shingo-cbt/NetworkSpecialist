# リンクアグリゲーション まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

スタック構成もこのファイルにまとめる（リンクアグリゲーションとセットで出るため）。令和3年春 午後Ⅱでも、STP（Spanning Tree Protocol）・RSTP（Rapid STP）・スタックがテーマになっている。

## 1. リンクアグリゲーションの基本（◎）

- **リンクアグリゲーション（LAG（Link Aggregation Group））**：2台の機器の間の**複数の物理リンクを、1本の論理リンクとして束ねる**技術（IEEE802.3ad、IEEE802.1AX）
- 利点
  - **帯域の拡大**：1Gbps×2本で、合計2Gbps分を使える
  - **冗長化**：1本が切れても残りで通信を続ける。切替が速い（STPのように数十秒待たない）
  - **STPでブロックされない**：論理的に1本なので、ループとみなされず全部のリンクを使える
- 束ねる条件：**速度・全二重／半二重・VLAN（Virtual LAN）の設定（アクセス／トランク、許可VLAN）が全リンクで同じ**であること

### LACP（○）

- **LACP（Link Aggregation Control Protocol）**：両端の機器が情報を交換して、**自動で束ねる**プロトコル
  - アクティブ（自分からLACPを送る）／パッシブ（受けたら応答する）。**両方パッシブだと束ならない**
  - 配線の誤り（別の機器につながっている）や片側の設定漏れを検知できる
- **スタティック**：LACPを使わず手動で束ねる。相手の状態を確認しないので、配線ミスに気づきにくい

## 2. 分散のしかた（◎）

- **フロー単位**：送信元・宛先のMAC（Media Access Control）アドレス、IP（Internet Protocol）アドレス、ポート番号などから**ハッシュ値**を計算し、どのリンクに流すかを決める
  - 同じ通信は同じリンクを通る → 順序が入れ替わらない
- 注意点
  - **1つの通信は1本分の帯域まで**（2本束ねても、1つの大きなファイル転送は速くならない）
  - **偏る**ことがある：例えば**ルータ同士の間でMACアドレスだけでハッシュ**すると、送信元・宛先のMACが常に同じ → **全部が1本に集中**する
  - 対策：**IPアドレスやポート番号もハッシュに使う**設定にする
- 記述の型：「ハッシュの計算に送信元・宛先のMACアドレスだけを用いると、ルータ間の通信では値が変わらず、特定のリンクに負荷が集中するから」
- → [[ECMP]]（L3での同様の分散）

## 3. スタック構成（◎）

- **スタック**：複数台のスイッチを専用ケーブルでつなぎ、**論理的に1台のスイッチとして動かす**
  - 設定・管理は1台分（代表のスイッチがまとめて制御する）
  - **2台にまたがってリンクアグリゲーションを組める** → スイッチが1台故障しても、もう1台のリンクで通信が続く
- **スタック＋リンクアグリゲーション**の構成
  - 上位のスイッチ2台をスタックにし、下位のスイッチから**1本ずつ両方に**つないで束ねる
  - 物理的には冗長だが、**論理的にはループのない1本の線** → **STPでブロックするポートがなく、全リンクを使える**
- 記述の型：「スタック構成のスイッチにまたがってリンクアグリゲーションを組むことで、論理的にループのない構成となり、STPによるポートのブロックが不要になるから」
- **MLAG（Multi-Chassis LAG）**：スタックにせずに、2台にまたがってLAGを組む方式（△）

### スタックの注意点（○）

- **スタック全体が1台扱い** → ソフトウェアの更新時に**全台が同時に再起動**することがある（停止時間が必要）
- スタックケーブルが切れると、2台がそれぞれ代表になる（**スプリットブレイン**）→ 同じ設定の2台がネットワークに現れて障害になる。検知する仕組み（デュアルアクティブ検知）を設定する（△）

## 4. 午後で問われるテーマと記述の型

### ◎ STPを使う構成からの変更

- 従来：L2スイッチを冗長化し、STPで片方をブロック → 帯域の半分が遊ぶ、切替に時間がかかる
- 変更後：**スタック＋リンクアグリゲーション** → 全リンクを使い、リンク・機器の故障でも高速に切り替わる
- → [[STP]]

### ◎ 帯域が期待どおりに増えない原因

- 1つの通信は1本分まで、ハッシュの偏り（2章）
- 問われ方：「2本束ねたのにバックアップの転送が速くならない理由」

### ○ 設定の不一致

- 片側だけLAGの設定、速度・VLANの不一致 → リンクが束ならない、またはループ・通信断
- LACPを使えば、不一致を検知して束ねないので安全

### ○ VRRPとの組合せ

- L3スイッチ2台をスタックにすれば、VRRP（Virtual Router Redundancy Protocol）を使わずに**1台の論理的なゲートウェイ**にできる（スタックで冗長化）
- スタックにしない場合は、VRRPで2台を冗長化する
- → [[VRRP]]

## 5. 覚え方

- **リンクアグリゲーションは「同じ相手との線を束ねて太く・切れにくくする」**
- **LACPは「両端で確認して束ねる」**：両方パッシブでは何も始まらない
- **「束ねても1つの通信は1本分」**、ハッシュがMACだけだとルータ間で偏る
- **スタックは「何台あっても1台のふり」**：2台にまたがって束ねれば、STPが要らない
- **スタックは更新時に全台再起動に注意**

## 6. 勉強の優先順位

1. スタック＋リンクアグリゲーションでSTPが不要になる理由を30〜40字で書けるようにする
2. フロー単位の分散と、偏る理由（MACアドレスだけのハッシュ）
3. 束ねる条件と、LACPの役割
4. スタックの利点と注意点（全台の再起動、スプリットブレイン）
5. MLAGは名前を知っている程度でよい

> [!tip] 得点につながる覚え方
> リンクアグリゲーションは**STP・ECMP（Equal Cost Multi-Path）・VRRPとの比較**で問われる。「L2で同じ相手との線を束ねる（LAG）」「L2で通行止めを置く（STP）」「L3で別の道を同時に使う（ECMP）」「ゲートウェイを二重化する（VRRP）」を区別して覚える。
