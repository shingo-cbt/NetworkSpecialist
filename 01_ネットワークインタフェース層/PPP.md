# PPP まとめ（ネスペ出題観点）

出題度：◎ 午後で記述・穴埋めとして頻出／○ 午前・午後小問で出る／△ 深追い不要

## 1. PPPの基本（○）

- **2点間（ポイントツーポイント）をつなぐデータリンク層のプロトコル**
- もとは電話回線・専用線用。今は **PPPoE**（PPP over Ethernet、Ethernet上でPPP（Point-to-Point Protocol）を使う）として、ISP（Internet Service Provider）へのインターネット接続で使われる
- PPPだけにある主な機能
  - **認証**（PAP（Password Authentication Protocol）／CHAP（Challenge Handshake Authentication Protocol））：ISPが契約者を確認できる
  - **IP（Internet Protocol）アドレスなどの自動割当て**（IPCP：IP Control Protocol）
  - リンクの品質確認、ループの検出
- 2点間なのでMAC（Media Access Control）アドレスのような宛先アドレスは不要

## 2. 接続の流れ（◎）

| 順番  | フェーズ       | 使うプロトコル                                | 内容                                            |
| --- | ---------- | -------------------------------------- | --------------------------------------------- |
| 1   | リンク確立      | **LCP**（Link Control Protocol）                                | 最大受信サイズ（MRU：Maximum Receive Unit）、使う認証方式、マジックナンバーなどを決める            |
| 2   | 認証         | **PAP** または **CHAP**                   | ユーザIDとパスワードで契約者を確認する                          |
| 3   | ネットワーク層の設定 | **NCP**（Network Control Protocol、IPv4は**IPCP**、IPv6は**IPV6CP**（IPv6 Control Protocol）） | IPv4アドレス、DNS（Domain Name System）サーバのアドレスを割り当てる／IPv6はインタフェースIDを決める |
| 4   | データ転送      | −                                      | IPパケットを運ぶ                                     |
| 5   | 切断         | LCP                                    | リンクを終了する                                      |

- **マジックナンバー**：自分の送った値が返ってきたら、回線が折り返されている（ループしている）と判断できる（△）
- IPV6CPはインタフェースIDだけ決める。**プレフィックスはその後にRA（Router Advertisement）やDHCPv6-PD（DHCPv6 Prefix Delegation）で受け取る**（△） → [[ICMP]]
- 穴埋めで「LCP」「IPCP」「NCP」の名前と役割の対応が問われやすい

## 3. 認証方式：PAPとCHAP（◎）

| | PAP | CHAP |
|---|---|---|
| やり取り | **2ウェイ**：ID・パスワードを送る → 結果を返す | **3ウェイ**：チャレンジ → レスポンス → 結果 |
| パスワード | **平文で送る** | **送らない**。チャレンジとパスワードからハッシュ値を作って送る |
| 盗聴されると | パスワードがそのまま漏れる | ハッシュ値しか漏れない。チャレンジが毎回変わるので**使い回し（リプレイ攻撃）できない** |
| 再認証 | 接続時の1回だけ | 接続中も**定期的に再認証**できる |

- CHAPの流れ
  1. 認証する側（ISP）が、毎回違うランダムな値（**チャレンジ**）を送る
  2. 利用者側が、チャレンジとパスワードを合わせて**ハッシュ値**（MD5：Message Digest 5）を計算して返す
  3. ISP側も同じ計算をして、一致すれば認証成功
- ISP側では、PPPの認証情報を**RADIUS（Remote Authentication Dial In User Service）サーバ**に問い合わせて確認することが多い → [[IEEE802.1X]]
- 記述の型（CHAPの利点）：「パスワードそのものを送らず、毎回異なるチャレンジから計算した値で認証するため、盗聴されても悪用されにくいから」

## 4. PPPoE（◎）

- **PPPのフレームをEthernetフレームに入れて送る**仕組み。光回線（FTTH：Fiber To The Home）でISPに接続するときの定番
- Ethernetの上でも、PPPの**認証**（ISPの契約者確認）と**アドレスの割当て**を使いたいから使う

### 接続の流れ

1. **ディスカバリステージ**：接続相手（ISP側の装置）を探し、セッションIDを決める
   - **PADI**（PPPoE Active Discovery Initiation、ブロードキャスト：接続相手はいるか）→ **PADO**（PPPoE Active Discovery Offer、応答）→ **PADR**（PPPoE Active Discovery Request、この相手に接続したい）→ **PADS**（PPPoE Active Discovery Session-confirmation、セッションIDを通知）
   - 切断は **PADT**（PPPoE Active Discovery Terminate）
2. **PPPセッションステージ**：セッションIDを付けて、通常のPPP（LCP → 認証 → IPCP）を行う

- Ethernetのタイプはディスカバリとセッションで別の値（0x8863／0x8864）（△）

### MTUとMSS（◎）

- PPPoEのヘッダ（6バイト）＋PPPのヘッダ（2バイト）＝**8バイト**の分だけ、運べるIPパケットが小さくなる
  - EthernetのMTU（Maximum Transmission Unit） 1500 − 8 ＝ **1492バイト**
  - NTTのフレッツ網では、さらに小さい **1454バイト** が推奨されている（MSS（Maximum Segment Size）は1454 − 40 ＝ 1414）
- 問題：LAN（Local Area Network）側の端末は1500バイトで送ろうとする → ルータで分割が必要になる、DF（Don't Fragment）ビット付きだと破棄されICMP（Internet Control Message Protocol）が返る
  - FW（Firewall）などでICMPを遮断していると**PMTUD（Path MTU Discovery）が働かず、大きいデータだけ通信できない**（PMTUDブラックホール）
- 対策：**ルータでTCP（Transmission Control Protocol）のMSSを小さく書き換える（MSSクランプ）** → 端末が最初から小さいサイズで送るようになる
- 記述の型：「PPPoEのヘッダの分だけMTUが小さくなり、1500バイトのパケットが転送できなくなるから」
- 記述の型（対策）：「ルータでTCPのSYN（Synchronize）パケットのMSS値を、PPPoEのMTUに合わせた値に書き換える」
- → [[ICMP]]（PMTUD）、[[TCP]]（MSS）

## 5. 午後で問われるテーマと記述の型

### ◎ PPPoEからIPoEへの移行（混雑の回避）

- フレッツ網のPPPoE接続は、**ISPとの接続点にある網終端装置**を通る
  - 利用者が多い時間帯（夜間など）に網終端装置が混雑し、**速度が落ちる**
- **IPoE**（IP over Ethernet）：PPPoEを使わず、**IPv6**でそのまま接続する方式。網終端装置を通らないので混雑しにくい
  - ID・パスワードによるPPPの認証がない（回線で契約者を判別する）
  - IPv4の通信は、**IPv4 over IPv6**（MAP-E、DS-Liteなど）でIPv6の中に入れて運ぶ
- **通る道（ルート）そのものが違う**（IPv6というプロトコル自体が速いわけではない）

```
【PPPoE】
家のルータ ── フレッツ網 ── 網終端装置 ── ISP ── インターネット
                            ↑ ここが混む関所
                            （PPPoEのセッションを1本ずつ受け止める装置）

【IPoE】
家のルータ ── フレッツ網 ── ゲートウェイルータ ── IPoE事業者（VNE（Virtual Network Enabler））── インターネット
                            ↑ 大容量の接続口（関所を通らない）
```

| PPPoE（網終端装置） | IPoE（ゲートウェイルータ） |
|---|---|
| PPPoEの**セッションを1本ずつ処理**する装置。同時に扱えるセッション数と通信量に上限がある | セッションを処理せず、**IPのパケットをそのまま転送**する |
| ISPごとに設置され、**増設に時間と費用がかかる** | **大容量の回線**で、少数のIPoE事業者に集約されている |
| 夜間など、利用者が一斉に使う時間帯に**処理が追いつかなくなる** | 利用者が増えても、比較的容量を増やしやすい |

- たとえ：PPPoEは**1台ずつ手続きをする料金所**を通る道で、車が増えると渋滞する。IPoEは**料金所のない道**（回線で誰かわかっているので、止まって手続きをしなくてよい）
- **IPv4もIPoEの道で運べる**：IPv4 over IPv6（MAP-E、DS-Lite）でIPv6の中に入れると、IPv4の通信も網終端装置を通らずに済む（「IPoEにしたらIPv4のサイトも速くなった」のはこのため）。その代わり、IPv4アドレスを共有するので、外からの接続を受けにくくなる
- 覚え方：**「PPPoEは料金所（網終端装置）で渋滞、IPoEは料金所のない道。IPv4もIPv6の車に乗せれば、同じ道を走れる」**
- 問われ方：「夜間に速度が低下する原因」「IPoEに変更する利点」
- 記述の型：「PPPoEでは網終端装置を経由するため、利用者が多い時間帯に輻輳するから」
- → [[IPv6移行技術]]

### ○ ルータの設定項目

- PPPoEで接続するルータに必要な設定：**ISPから払い出されたユーザID・パスワード**、認証方式（PAP／CHAP）、MTU、MSSクランプ
- 固定IPアドレスの契約をしていなければ、**IPCPで毎回違うアドレス**が割り当てられる → サーバの公開にはDDNS（Dynamic DNS）や固定IPの契約が必要
- 問われ方：「ルータに設定すべき項目」「拠点のグローバルIPアドレスが変わる理由」

### △ L2TP（PPPをトンネルで運ぶ）

- PPPのフレームを、IPネットワーク越しに運ぶトンネリングプロトコル（UDP（User Datagram Protocol） 1701）
- 暗号化機能がないので、リモートアクセスVPN（Virtual Private Network）では **L2TP（Layer 2 Tunneling Protocol）／IPsec**（Security Architecture for Internet Protocol） として組み合わせて使う → [[IPsec]]
- ISPの網内で、利用者のPPPセッションをISPまで運ぶのにも使われる

### ○（午前頻出）PPTP：PPPをトンネルで運ぶもう1つの方式

- **PPTP（Point-to-Point Tunneling Protocol）**：PPPのフレームをIPパケットに入れて運ぶ、**リモートアクセスVPN**用のプロトコル
- 午後で問われることはほとんどない。**午前でVPNの方式の比較**として出る
- 制御用に **TCP 1723**、データ用に **GRE（Generic Routing Encapsulation、IPのプロトコル番号47）** を使う
- 暗号化は **MPPE（Microsoft Point-to-Point Encryption）** で行うが弱く、**現在は非推奨**

| | PPPoE | PPTP | L2TP |
|---|---|---|---|
| 目的 | **ISPへの接続** | リモートアクセスVPN | VPN、ISP網内でのPPPの運搬 |
| PPPの運び方 | **Ethernetフレーム**に入れる | **GRE**でIPパケットに入れる | **UDP 1701**でIPパケットに入れる |
| 届く範囲 | 同じEthernetの網の中 | インターネットを越える | インターネットを越える |
| 暗号化 | なし | MPPE（弱い） | **なし** → IPsecと組み合わせる（L2TP／IPsec） |
| 今の位置づけ | 現役（IPoEへ移行中） | **非推奨** | L2TP／IPsecとして利用 |

- 午前の定番：「PPPをカプセル化してトンネルを作るプロトコル」→ PPTP、L2TP。「L2TPだけでは暗号化されない」
- FW・NAPTの観点（出るとすれば）：**TCP 1723とGREの両方**を許可する必要がある。GREにはポート番号がないため、NAPTを越えるにはルータのパススルー機能が必要

## 6. 覚え方

- **流れは「リンク（LCP）→ 本人確認（PAP／CHAP）→ 住所（IPCP）」**：線をつなぎ、誰か確かめ、アドレスをもらう
- **PAPは「合言葉をそのまま言う」、CHAPは「問題を出され、合言葉で解いた答えを返す」**
  - PAPは2回のやり取り、CHAPは3回（チャレンジ、レスポンス、結果）
- **PPPoEのディスカバリは「イ・オ・リ・ス」**：PAD**I**（いますか）→ PAD**O**（います：Offer）→ PAD**R**（お願い：Request）→ PAD**S**（決定：Session）。終わりは PAD**T**（Terminate）
- **「PPPoEは8バイト重い」**：1500 − 8 ＝ 1492。フレッツは1454、MSSはそこから40引いて1414
- **PPPoEは「家からISPまで、Ethernetの中で運ぶ」、PPTP・L2TPは「どこからでも社内まで、インターネット越しにトンネルで運ぶ」**（PPTPは古くて非推奨、L2TPは暗号化がないのでIPsecと組む）
- **PPPoEは「料金所（網終端装置）を通る道」、IPoEは「料金所のない道」**：混む時間に詰まるのは料金所

## 7. 勉強の優先順位

1. PPPoEでMTUが小さくなる理由とMSSクランプを30〜40字で書けるようにする（ICMPのPMTUDとセットで）
2. PAPとCHAPの違い（平文かどうか、チャレンジの役割）を説明できるようにする
3. 接続の流れ（LCP → 認証 → IPCP）を穴埋めで答えられるようにする
4. PPPoEからIPoEへ移行する理由（網終端装置の混雑）
5. PPPoEのディスカバリ（PADI〜PADS）は名前と順番を押さえる程度でよい
6. L2TP、PPTP（午前でVPN方式の比較として出る）、マジックナンバーは名前と特徴を知っている程度でよい

> [!tip] 得点につながる覚え方
> PPPは単独で深く問われるより、**拠点のインターネット接続の構成問題**で「PPPoEだからMTUが小さい」「PPPoEだから夜に遅い」という**原因の説明**として出る。構成図にPPPoEとあったら、MTU／MSSと網終端装置の混雑の2点を確認する。

## 参考：家庭のインターネット接続で見るPPPの全体像

光回線の家庭（NTTのフレッツ光＋ISP）で、ルータの電源を入れてからPCでWebページが見えるまでを追う。

### 登場人物

```
[PC] ─ [家のルータ] ─ [ONU] ═光═ [NTT局舎] ─ フレッツ網 ─ [網終端装置] ─ [ISP] ─ インターネット
                                                                       │
                                                                 [RADIUSサーバ]
```

- **家のルータ**：PPPoEのクライアント。ISPとの契約情報を設定しておく
- **ONU**（Optical Network Unit）：光と電気の信号を変換するだけ
- **フレッツ網**：NTTの網。**いろいろなISPの利用者が同じ網を共用**している
- **網終端装置**：フレッツ網とISPの境目にある装置。PPPoEセッションの相手になる
- **RADIUSサーバ**：ISPの契約者データベース。IDとパスワードが正しいか判定する

### なぜEthernetなのにPPPを使うのか

- フレッツ網は複数のISPの利用者が共用している → 「この通信は**どのISPの、どの契約者**のものか」を見分ける必要がある
- Ethernetには**認証の仕組みも、契約者ごとにアドレスを割り当てる仕組みもない**
- そこで、それを持っているPPPをEthernetの上に乗せる → これがPPPoE

### ストーリー

**0. 契約時**

- ISPから「ユーザID：`taro@isp-a.ne.jp`、パスワード：xxxx」が届く。これをルータに設定する

**1. ルータの電源を入れる：接続相手を探す（PPPoEディスカバリ）**

- ルータ：「PPPoEで接続できる相手はいるか」（**PADI**、ブロードキャスト）
- 網終端装置：「いる」（**PADO**）
- ルータ：「では、あなたと接続する」（**PADR**）
- 網終端装置：「セッションIDは1234」（**PADS**）
- 以降の通信には、すべてこのセッションIDが付く

**2. 回線の条件を決める（LCP）**

- 「1回に受け取れるサイズは1454バイトまで」「認証はCHAPで行う」などを決める

**3. 本人確認（CHAP）**

- ISP側：「このランダムな値（チャレンジ）で計算してみて」
- ルータ：チャレンジとパスワードからハッシュ値を計算して返す
- 網終端装置は、ユーザIDの **`@isp-a.ne.jp` の部分を見てA社の利用者だと判別**し、A社のRADIUSサーバに問い合わせる
- RADIUS：「契約者taroで間違いない」→ 認証成功

**4. 住所をもらう（IPCP）**

- ルータ：「IPアドレスがほしい」
- ISP：「グローバルアドレス `203.0.113.45` を使って。DNSサーバはこれ」
- これでルータのWAN（Wide Area Network）側にグローバルIPアドレスが付く

**5. PCでWebページを見る**

1. PC（`192.168.1.10`）がWebサーバ宛てにパケットを送る
2. ルータが**NAPT**（Network Address Port Translation）で送信元を `203.0.113.45` に書き換える
3. ルータがそれを**PPPのヘッダとPPPoEのヘッダで包み**、Ethernetフレームに入れて送り出す
4. 網終端装置がPPPoEとPPPの包みを外し、中のIPパケットをA社の網へ渡す
5. A社からインターネットへ出ていく

- 包みの8バイト分だけ中身が小さくなるので、ルータは**MSSクランプ**でPCに最初から小さいサイズで送らせる

**6. ある日、夜だけ遅くなる**

- 夜はみんなが一斉に使うので、**網終端装置に通信が集中して混雑**する
- 昼は速いのに夜9時ごろ遅い、というのはこれが原因であることが多い

**7. 解決策：IPoEに切り替える**

- **IPv6 IPoE**：PPPを使わず、IPv6でそのまま接続する方式。網終端装置を通らない
- 認証は「どの回線か」で行う（IDとパスワードは不要）
- アドレスは、PPPのIPCPではなく、**RA／DHCPv6-PD**で受け取る
- IPv4のWebサイトは、**IPv4 over IPv6**（MAP-E、DS-Liteなど）でIPv6の中に入れて運ぶ

### このストーリーと試験の対応

| 場面 | 試験で問われること |
|---|---|
| 1 ディスカバリ | PADI → PADO → PADR → PADS の順番（午前） |
| 2〜4 | LCP → 認証 → IPCP の流れ、PAPとCHAPの違い（午前・午後） |
| 3 RADIUS | ISP側の認証の仕組み |
| 5 カプセル化 | **MTUが小さくなる理由、MSSクランプ、PMTUDブラックホール**（午後の定番） |
| 5 NAPT | プライベートアドレスとグローバルアドレスの変換 |
| 6 夜に遅い | **網終端装置の輻輳**（午後の原因説明） |
| 7 IPoE | 移行の利点、IPv4 over IPv6 |
